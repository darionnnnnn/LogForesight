# F19 規則調整（誤判、門檻）

- 角色／目標：某條規則太吵或太鬆，管理員調整嚴重度、門檻或停用。
- 頻率：每月；上線初期每週。
- 對應測試項目：P11；既有發現：N1、W4。
- 驗證：規則清單與編輯彈窗欄位實測（D2）；儲存、驗證、試算、升級**未實測**。
- 現行步數：規則維護 → 搜尋 → 編輯 → 改欄位 → 先驗證 → 儲存 ≈ 6 步。

## 逐步思考

### F19-1 從問題走到規則
- 需要知道：這個問題是哪條規則判的。
- 畫面有給嗎：風險日處理面板有「規則常誤判」連結到規則維護（不帶規則）；問題查詢列與交辦單頁沒有到規則的連結。規則維護有搜尋。
- 判斷：就地、直達。
- 建議：問題列「更多」與交辦單頁加「調整這條規則」，直接開該規則的編輯（規則 Id 已在問題資料上）。
- 新發現 **F19-1**。

### F19-2 改了會影響多少
- 需要知道：門檻從 3 改 10、或嚴重度從中改低，過去 30 天會少多少主機日、少派幾張單。
- 畫面有給嗎：沒有。趨勢類規則有「試算草稿」；一般規則只有「先驗證」（驗格式與遮蔽）。抑制有影響預覽。
- 情境：防錯——管理員憑感覺調門檻，隔天才知道效果；調太鬆會把真問題藏掉。
- 判斷：防錯、補資訊。
- 建議：一般規則也提供影響試算：以近 30 天既有的問題子列重算「命中主機日：現行 N → 調整後 M」「會派工的問題：N → M」。資料已在 `lf_top_issues`（次數、嚴重度）。
- 新發現 **F19-2**。

### F19-3 改了之後
- 需要知道：何時生效、既有紀錄會不會變。
- 畫面有給嗎：規則頁頂寫「儲存前會自動驗證」；沒有說「只影響之後的分析，既有紀錄與交辦單不變」。
- 判斷：補資訊。
- 建議：儲存後 toast 說明生效範圍，並提供「重新分析近 N 天」的連結（排程作業已有重跑模式）。

### F19-4 編輯彈窗
- 實測：一個彈窗含比對、門檻、分類、嚴重度、重大旗標、處置知識庫（白話、影響、原因、步驟）；PRTG／趨勢欄位依規則類型顯示。
- 判斷：保留。只調嚴重度或門檻時，彈窗偏重。
- 建議：規則清單列上就地調整嚴重度與門檻（兩個最常改的欄位），其餘進彈窗。
