# F14 負載調整、改派、拆單、處理人請假

- 角色／目標：把工作從一個人移到另一個人：單張改派、拆出部分主機、某人請假或離職時整批轉走。
- 頻率：每週；處理人異動時一次很多張。
- 對應測試項目：L8、L12；既有發現：A12、L12、F11-3、F13-1。
- 現行步數：單張改派 4 步（進單→改派→選人→確定）；請假轉走 N 張＝4N 步（D1 的 ui-handler 17 張＝68 步）→ 目標：整批 4 步。

## 現行步驟（處理人請假）

| # | 畫面 | 動作 | 步數 |
|---|---|---|---|
| 1 | 使用者 | 找到人 → 暫停接單（即時生效，之後不再派新單） | 1 |
| 2 | 交辦總覽 | 更多條件 → 勾「只看處理人已停用或失去處理能力」（暫停接單的人不在此篩選內，要改用網址 `handlerId`） | 2 |
| 3 | 交辦單頁 | 逐張：進單 → 改派 → 選人 → 確定 | 4 × N |

## 逐步思考

### F14-1 找出某人名下的單
- 畫面有給嗎：負載看板點人名 → 該人的工作頁（唯讀檢視）；交辦總覽沒有「處理人」下拉（只有群組），要靠網址參數或從使用者頁的 toast 連結進來。
- 判斷：補資訊。
- 建議：交辦總覽篩選加「處理人」。
- 新發現 **F14-1**。

### F14-2 單張改派
- 畫面有給嗎：改派彈窗有候選人、「看不到 N 台（將以交辦授與補上）」、目標已有同問題單時併入。沒有負載（F13-1）。
- 情境：併發——處理人正在回覆時被改派，收到 403、說明遺失（C2）。
- 判斷：保留；補負載。

### F14-3 整批改派
- 畫面有給嗎：沒有（A12）。
- 需要想清楚的情境：
  - 目標處理人已有同問題的單 → 併入（現有規則）。
  - 目標看不到部分主機 → 以交辦授與補上（現有規則）；批次時要彙總「共 N 台以授與補上」。
  - 一部分給甲、一部分給乙（依機房）→ 需要「依主機群組分給不同人」或先篩選再批次。
  - 暫停中（靜音）的單要不要一起轉 → 預設一起。
- 判斷：合併、防錯。
- 建議：交辦總覽與負載看板支援勾選多張 →「改派給…」→ 預覽（每張：併入或新單、授與台數）→ 套用，逐張回報結果。
- 依據：`WorkOrderCoordinator.Reassign` 可逐張呼叫；PLAN 批次 G。

### F14-4 停用帳號
- 畫面有給嗎：停用即存，事後 toast（L12）。
- 判斷：防錯。
- 建議：名下有進行中單時，停用前顯示張數與台數並可一併改派。

### F14-5 請假回來
- 未實測。取消暫停接單即可；轉出去的單不會自動回來，合理。
- 建議：暫停接單可設「到某日自動恢復」，免得忘記解除（處理人長期收不到新單不易察覺）。
- 新發現 **F14-5**。

### F14-6 拆出部分主機
- 畫面有給嗎：勾選成員 → 拆出選取的主機 → 選人。成員表找主機的問題同 F03-1。
- 判斷：保留；沿用 F03-1 的搜尋與貼上清單。
