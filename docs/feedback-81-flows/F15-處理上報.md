# F15 管理員處理上報

- 角色／目標：處理人說處理不了，管理員決定：退回並給指示、代為結案、改派給別人、或從源頭處理（調規則、靜音）。
- 頻率：每週。
- 對應測試項目：L7；既有發現：L7、N1、F04-2。
- 現行步數：找到上報的單（交辦總覽篩「上報中」）1～2 步 → 進單 1 步 → 讀成員附註（上報原因）→ 退回 3 步或代為結案 4 步。

## 逐步思考

### F15-1 找到上報
- 畫面有給嗎：交辦總覽狀態篩選「上報中」；提醒區只列超過 3 天的（L7）；即時上報信。
- 判斷：補資訊（當天可見）。

### F15-2 判斷怎麼處理
- 需要知道：上報原因、哪幾台、這個問題的全貌（其他人手上同問題的單、復發情況）。
- 畫面有給嗎：部分。成員附註欄顯示「上報原因」；沒有「同問題其他單」的連結（問題查詢列上有、交辦單頁沒有）。
- 判斷：補資訊。
- 建議：交辦單頁加「這個問題的其他交辦單」連結（已有 `/work-orders?source=&eventId=` 可用）。
- 新發現 **F15-2**。

### F15-3 執行決定
- 四條路都在交辦單頁右上（改派、退回處理人、取消交辦、代為結案），各自彈窗、原因必填。
- 情境：
  - 只有部分成員上報：退回只作用在上報的成員（實測退回 3 台），合理；代為結案作用在全部進行中成員（實測「代為結案 60 台」），**不能只結上報的那幾台**——要先拆單。
  - 上報原因是「反覆復發」（F04-2）：管理員真正要做的是調規則或靜音，交辦單頁沒有這兩個入口，要回問題查詢找同一個問題。
- 判斷：就地。
- 建議：代為結案可選範圍（全部進行中／只有上報的 N 台／勾選的）；交辦單頁「更多」加入「靜音這個問題」「到規則維護」。
- 新發現 **F15-3**（代為結案不能只結上報的成員；源頭處理入口不在單上）。

## 目標流程

| # | 動作 | 差異 |

| 1 | 儀表板「新上報 N」→ 交辦單頁 | 當天、1 步 |
