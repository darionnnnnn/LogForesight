# F11 管理員早上巡檢

- 角色／目標：管理員早上花幾分鐘確認：昨晚取數與派工有沒有成功、有什麼派不出去、有沒有上報、誰的工作堆太多、系統本身健不健康。
- 頻率：每天。
- 對應測試項目：R2、P02、P07、K1、K2；既有發現：A1、A1b、A3、A4、K1、L7、M1、W0。
- 現行步數：儀表板 → 交辦總覽（提醒區）→ 待派頁籤 → 負載看板頁籤 → 排程作業（確認昨晚）≈ 5 次換頁、每頁自己判讀 → 目標：1 頁看完、每個異常 1 步到處理點。

## 逐步思考

### F11-1 儀表板首屏
- 需要知道：管理員要「做」的事，依序是——系統有沒有壞（取數、AI、PRTG）→ 有沒有人等我（上報、派不出去）→ 工作有沒有卡住（負載、久未回覆）→ 全站風險趨勢。
- 畫面有給嗎：順序相反。首屏是全站風險數字（高風險日、中風險日）與風險類型卡；「待派工問題」是一張卡、數字含不會派的雜訊（A3）；上報、負載、昨晚執行結果都不在儀表板。
- 情境：量大——2,000 台時「高風險日 193」沒有可行動的意義。失敗——AI 不通時今日焦點等 4 秒（A1）、每個管理頁多 2 秒（A1b）。
- 判斷：補資訊、合併。
- 建議：具 Assign 的人，儀表板頂端加一列「需要你處理」：昨晚執行結果（成功／失敗主機 N）、新上報 N、派不出去 N（可派的）、處理人已停用仍有單 N、超過 X 天未回覆的單 N；每項直接連到處理點。交辦總覽提醒區與這一列同一個資料來源（`AdminReminderService`）。
- 新發現 **F11-1**（管理員的行動資訊分散在四個地方）。

### F11-2 提醒區
- 畫面有給嗎：有，三類提醒＋「看是哪些」明細。缺：新上報當天不列（L7）；無人授權的主機群組沒有彙整成一則（A4）。
- 判斷：補資訊。

### F11-3 負載看板
- 需要知道：誰過載、誰閒置、能不能就地調整。
- 畫面有給嗎：只有數字；不能就地改派（A12）；沒有每人「可處理的範圍」提示（為什麼 h-chen 是 0——因為授權範圍裡沒有待派的問題）。
- 情境：量大——D2 的負載是 100／80／8／0／0／0，派工不看負載差距（W0、W5）。
- 判斷：就地、自動。
- 建議：看板列上直接「把 N 張單改派給…」；夜間派工在多位候選人可見同一批主機時加入負載因子（需確認現行選人規則，列入 PLAN 待確認）。
- 新發現 **F11-3**（派工不平衡時管理員沒有就地手段）。

### F11-4 確認昨晚執行
- 畫面有給嗎：頁頂「資料最近更新」與健康橫幅會在異常時出現；正常時不必進排程作業。
- 判斷：保留（異常才需要看）。
