# F05 從主機角度處理多個問題

- 角色／目標：處理人到機房處理某一台主機（或接到某台的電話），想一次看完這台所有被交辦的問題並逐一回報。
- 頻率：每天。
- 對應測試項目：R1、P04、P05；既有發現：H5、H9、H11、O1。
- 現行步數：找到主機 2～3 步＋每個問題 4 步（進風險日→勾選→選狀態→套用）；主機有多天時每天重複 → 目標：找到主機 1 步＋每個問題 2 步，全部在同一頁。

## 現行步驟

| # | 畫面 | 動作 | 步數 |
|---|---|---|---|
| 1 | 我的交辦 → 進階檢視：依主機 | 展開進階檢視，在分頁清單裡找主機（無搜尋） | 1＋翻頁 |
| 2 | 同上 | 點問題連結 → 風險日詳情（最新一天）#handling | 1 |
| 3 | 風險日詳情 | 勾選問題 → 右側面板選狀態 → 填說明 → 套用 | 4 |
| 4 | 回上一頁 | 找同一台的下一個問題，重複 2～3 | 每題 5 |

## 逐步思考

### F05-1 找到主機
- 目的：定位這一台。
- 畫面有給嗎：部分。
  - 「依主機」進階檢視：每列是「主機×問題」，每頁 20、無搜尋（H5）；預設收合在頁尾。
  - 側欄沒有全站主機搜尋；問題查詢的主機篩選要先選視角再搜。
  - **主機詳情頁（`/hosts/{id}`）沒有任何處理資訊**：只有風險時間軸與問題彙總表，沒有「這台有哪些交辦、誰在處理、狀態」，也沒有任何回覆入口（實測 SIM-WIN1017）。
- 情境：直達——別人貼來主機名，處理人沒有一個「輸入主機名就到」的入口。量大——h-wu 100 台＝5 頁。
- 判斷：就地、補資訊。
- 建議：
  1. 頁頂加全站主機快速搜尋（輸入名稱或 IP → 主機詳情）。
  2. 主機詳情頁加「這台的交辦」區塊：每個問題一列（處理人、狀態、單號、上次回覆），本人的問題可就地回覆。
- 新發現 **F05-1**（主機詳情沒有處理資訊與入口）、**F05-2**（沒有主機快速搜尋）。

### F05-2 對這台的每個問題回覆
- 目的：一台一次回完。
- 畫面有給嗎：沒有同頁完成的方式。風險日詳情一次是一天；提示「到我的交辦可以一次回覆同一張單的所有主機」是反方向（以單為主）。
- 情境：權限——只能標指派給自己的問題，面板有說明。併發——別人處理中的問題不可勾選，合理。
- 判斷：就地、合併。
- 建議：主機詳情的「這台的交辦」支援勾選多個問題一次回覆（走各自的交辦單回覆端點，`caseIds` 帶這台）；風險日詳情的勾選套用維持給「沒有交辦單的問題」。
- 依據：`reply` 端點已支援 `caseIds`；前端要把「同主機跨單」組成多次呼叫或用 `reply-many` 擴充。

### F05-3 回到下一台
- 判斷：自動。
- 建議：回覆後留在主機詳情，顯示剩餘未回覆問題數；提供「下一台有待回覆的主機」。

## 目標流程

| # | 動作 | 與現行的差異 |
|---|---|---|
| 1 | 頁頂搜尋主機名 → 主機詳情 | 不必翻進階檢視 |
| 2 | 「這台的交辦」勾選已處理的問題 → 回覆 → 送出 | 不必逐天、逐題跳頁 |

- 依賴：主機詳情新增交辦區塊的 API（以可見範圍與案件授與過濾）；授權守門。
- 暫不建議：把「依主機」進階檢視做成主清單的預設——單（問題）導向仍是大量回覆的主線，主機導向是補充入口。
