# FEEDBACK-30-PLAN — 登入失敗誤判分辨／NetIQ 探索改良／規則涵蓋補強

> 規劃輪：回饋第三十輪。本文件為行為契約層級規劃，不含程式碼與行號級步驟。
> 完工後照 CLAUDE.md 規劃案生命週期歸檔至 docs/archive/。

## 背景與定案摘要（討論結論）

1. **登入失敗誤判**：使用者觀察大量登入失敗多為「動態密碼(OTP)登入後未登出，隔天密碼變更，
   殘留 session／排程／磁碟機對應持續用舊密碼重試」。核對確認現行 4625 偵測只有純計數
   （單日 ≥10 → High），SubStatus／LogonType／來源工作站完全未解析，無任何分辨能力；
   最大誤判源是【破解得手】關聯模式（合法帳號白天必有成功登入 → 帳號交集必然非空 →
   誤報 High＋強制高風險日）。定案：做**自動分辨＋畫面標示**，不新增人工白名單設定
   （觀察實測後若有漏網再評估抑制機制擴充帳號/來源維度）；生效時機採**跨日確認制**——
   首日照常告警、同 (帳號, 來源) 組合跨日重現才標殘留消音（保住橫向移動的首次偵測，
   噪音從每天一發降為每組合一發）。
2. **NetIQ 主機探索**：log 量大時單輪只取前 5 萬筆（無排序、吵主機壟斷）、一輪 50 頁約 85 秒
   吃光 90 秒互動預算、排除子句上限 500 封頂約 500 台。定案：提早停頁＋**網段自動分割**
   （使用者實務輸入為 `192.168` 這類 /16 級前綴 → 自動拆 /24 逐段掃）＋**掃描背景化**；
   時間切片降為單一網段不收斂時的補救。
3. **規則補強**：甲（4771）乙（帳號生命週期/排程/防火牆）丙（硬體/角色型/Linux 運維）全做；
   4768/4769/4776 **不進 seed** 記 BACKLOG——watchlist 只能整 ID 取數（4769 全域超大量），
   且規則模型無成功/失敗（EntryType）維度（4776 成功失敗共用 ID，會把 DC 成功驗證當失敗計數）。
   4688/4663/5140/5145 同前討論刻意不做。
4. **順手 bug 一併修**：Linux `user`/`group` 規則 Contains 過寬；KeyDetails 跳過 `$` 電腦帳號
   造成計數與顯示口徑不一。

## 作業 A：登入失敗誤判分辨

### A1 Windows 4625 結構化解析

**目標**：把分辨所需維度從訊息全文抽出並持久化，不動簽章分組鍵。

**行為契約**
- 從 4625 事件訊息（本機路徑 `Message`／NetIQ `msg` 全文）抽取：LogonType、SubStatus
  （至少涵蓋 0xC000006A 密碼錯誤／0xC0000071 密碼過期／0xC0000234 已鎖定／0xC0000072 已停用／
  0xC0000064 帳號不存在；其餘保留原始碼值）、來源工作站、帳號、來源 IP。中英文事件訊息皆須支援
  （標籤比對沿用既有 `AccountLabels` 的雙語策略）。
- 聚合為**簽章級登入失敗明細**：per (帳號, 來源工作站, LogonType, SubStatus) 計數，
  隨簽章持久化。**持久化方式於開工前查證推翻原暫定**：明細作為 `LogIssueSignature` 的
  `LoginFailureDetails` 屬性，隨 `lf_daily_records.ContentJson` 序列化落地——
  **零 schema 變更、無 SchemaUpgrader、無雙 provider 風險**。理由：`TopIssueRow` 實際上
  只是給 SQL 端聚合用的去正規化投影（不含 `KeyDetails`／`SampleMessages`／趨勢欄），
  完整簽章一向存在 ContentJson；明細只被分析管線與詳情頁消費，不需要 SQL 端聚合。
- **簽章分組鍵不變**（動了會讓既有 4625 歷史斷成「首次出現」，DETECTION-SPEC 已有教訓記載）；
  `KeyDetails` 字串維持既有格式相容。
- **電腦帳號（`$` 結尾）納入明細與 KeyDetails**，標示為電腦帳號——收斂「計數含它、顯示跳過它」
  的口徑不一（順手 bug 2）。
- NetIQ 投影補 `shn`（發起端機器名）／`sip`（發起端 IP）兩欄，對應到來源工作站／來源 IP 的
  優先來源（欄位缺席時退回訊息抽取）。**此兩欄有無值需實機驗證**——列入試點核對清單，
  程式面須容忍恆缺席。
- **4771 的訊息形狀一併支援**（C1 會開始收 4771，抽取層先備好）：帳號、用戶端位址、
  Kerberos 結果碼，並把結果碼映射到等價語意（0x18→密碼錯誤、0x12→帳號鎖定/停用、
  0x6→帳號不存在），與 4625 的 SubStatus 共用同一套明細結構；4771 無 LogonType，留空。
- 明細筆數需有上限（暫定每簽章 50 組，超過時保總量計數並標截斷），避免噴灑情境把欄位撐爆。
- **電腦帳號口徑澄清**：KeyDetails「格式相容」指標籤結構不變，帳號清單的**成員**新增電腦帳號
  （附標示）；`-`（無帳號）維持跳過。
- **無風險日精簡路徑**：明細欄位在精簡儲存路徑必須保留（殘留標記會把原本的高風險日變低風險，
  若精簡路徑丟明細，跨日判定與事後查證就斷了）——驗收含此情境。
- **存量資料**：舊列無明細 → 下游（A3 判定、A6 顯示）一律以「明細缺席」的保守行為處理，
  不回溯重剖歷史。

**驗收**
- 單元測試：中／英文 4625 樣本訊息各欄位抽取正確；SubStatus 未知碼保留原值；`$` 帳號入列並標示。
- 既有 4625 簽章鍵不變：既有聚合測試全綠。
- 雙 provider schema 測試（增欄冪等）。

### A2 Linux 登入失敗解析入庫

**目標**：解除 Linux 在 `KeyDetails`／明細的刻意排除，讓 sshd 失敗的帳號/IP 入庫可分辨。

**行為契約**
- 命中 `builtin-linux-ssh-bruteforce`／`sudo`／`su` 認證失敗規則的簽章，聚合層抽取帳號與來源 IP
  進 A1 的同一份簽章級明細（LogonType/SubStatus 對 Linux 不適用，留空；來源工作站以 IP 承載）。
- 抽取樣式以 sshd `Failed password for [invalid user] X from IP`、pam `authentication failure` 常見
  形狀為準；抽不出時不影響計數。
- **解析單點化**：`LinuxCorrelationAnalyzer` 既有的帳號/IP regex 與本階段的抽取收斂為同一出口
  （關聯層改吃共用函式）——不允許同一份樣式在兩處各寫一份（委派端已知的「同邏輯寫 N 份」
  失敗模式，驗收 grep 逐字相近區塊）。
- 其他 Linux 規則維持不抽（沿用既有「刻意排除」的預設，僅對登入失敗家族開洞）。

**驗收**：單元測試涵蓋 sshd／sudo／su 樣本行；非登入失敗的 Linux 簽章不長出明細。

### A3 殘留憑證判定

**目標**：把「機械性殘留重試」與「攻擊」分開，命中時不升級、畫面誠實標示依據。

**行為契約**
- 新增簽章級判定「疑似殘留憑證重試」，判準（**暫定**，執行端可依測試樣本微調並記錄理由）：
  該日 4625（或 Linux ssh 失敗）明細同時滿足——
  1. 失敗集中：前 2 組 (帳號, 來源) 佔總次數 ≥ 80%；
  2. 型態機械：Windows 側集中組的 LogonType ∈ {3,4,5}（網路/批次/服務）佔比 ≥ 80%；
     Linux 側以「同帳號＋同來源 IP」高集中替代此條；4771（無 LogonType）亦用 Linux 式
     替代判準，結果碼等價於 SubStatus 參與條件 3；
  3. 帳號非未知：集中組的 SubStatus 不是 0xC0000064（帳號不存在）——猜帳號是攻擊特徵；
  4. **跨日確認（定案，非暫定）**：集中組的 (帳號, 來源) 組合在該主機近 7 天內（含當日）
     的登入失敗明細出現 ≥2 天——**首日不滿足、照常以既有攻擊語意告警**，重現日起才標殘留。
     每個新組合都會被人看到一次才消音；「內網主機單帳號重試」的橫向移動因此保有首次偵測。
     **回看資料來源已查證定案**：直接用 `LogAnalysisService` 既有的
     `_historyService.ReadRecent(targetDate, historyDays)`（預設 14 天、已載入供
     TrendAnalyzer／CorrelationAnalyzer 使用）中的歷史簽章明細——**不新增任何 DB 查詢**，
     7 天窗是既有 14 天窗的子集。回看窗內明細缺席（舊資料未回溯）視同未重現。
- **「一組」的定義**：(正規化帳號, 來源工作站或 IP) 二元組；來源缺席時以帳號單獨成組；
  連帳號都抽不出的失敗**不得**標殘留（保守——判不了就維持既有攻擊語意）。
- **信心加分（非必要條件）**：集中組的來源 IP 若屬站內已登錄主機（HostStore 可查）→
  標示「來源為站內主機」提高殘留可信度；查不到不扣分。此條只影響顯示文字，不影響判定
  （避免主機清單不全時判定漂移）。
- 命中時：該簽章當日**不觸發暴力破解升級**（Severity 以 Medium 呈現，暫定；不進 High 統計）、
  不作為關聯層 4625 錨點、畫面與報告標示「疑似殘留憑證重試」與判定依據
  （集中帳號/來源/類型/原因）。
- 不命中（多帳號、外部/多來源、互動或 RDP 型失敗、帳號不存在為主）→ 維持既有攻擊判定不變。
- 判定為純函式、可單元測試；不引入任何新設定鍵。

**驗收**
- 判定測試矩陣：OTP 殘留形狀（單帳號單來源 Type3 高量）→ 命中；密碼噴灑形狀（多帳號同來源）→
  不命中；分散暴力破解（單帳號多來源 Type10）→ 不命中；帳號不存在為主 → 不命中。
- 端到端：殘留形狀的主機日不因 4625 成為高風險日。

### A4 下游消費修正（同型誤判一併處理）

**目標**：讓 A3 的判定貫穿關聯層、趨勢層與 4740。

**行為契約**
- **【破解得手】**（含跨日、RDP 變體）：錨點修正——(a) 已標殘留的 4625 簽章不作錨點；
  (b) 成功登入須晚於該帳號當日首次失敗（時間可得時）。資料缺席時退回既有行為。
  **原條件 (c)「排除失敗與成功同帳號且同來源工作站的自證情境」實作前推翻、不做**：
  典型的真暴力破解正是「攻擊者自同一來源先大量失敗、再成功登入」，同來源是**真陽性的特徵**
  而非誤判特徵；照原案實作會把最經典的得手形狀整類消音。殘留造成的自證情境已由 (a) 涵蓋
  （殘留簽章根本不作錨點），不需要也不應該再加同來源排除。
- **安全稽核事件量突增**：已標殘留簽章的量從突增分子排除；排除後仍突增才告警，告警文字註明
  已排除量。
- **趨勢層**：已標殘留簽章當日不觸發 Rising 升級語意（告警文字可保留但標註殘留），
  不影響其他簽章。
- **4740 帳號鎖定**：被鎖帳號若與當日已標殘留的集中帳號相同 → 該 4740 標示
  「可能由殘留憑證重試觸發」並降為 Medium（暫定）；否則維持 High。
- 各修正點的既有抑制（Correlation/Volume 型）語意不變。

**驗收**：每個消費點各至少一組「殘留→不誤報」與「真攻擊→照常告警」的成對測試；
既有關聯層測試全綠。

### A5 密碼噴灑偵測（新增真攻擊面）

**目標**：利用 A1 的 per 帳號計數補上目前完全沒有的噴灑形態。

**行為契約**
- 判準（暫定）：單日單簽章明細內，同一來源（IP 或工作站）打 ≥10 個相異帳號、每帳號次數 ≤3
  → 產生「密碼噴灑嘗試」訊號，Severity High、`ElevatesDayRisk=true`（暫定）。
- **「一個帳號」的定義**：以抽取層正規化後的帳號字串、不分大小寫計相異數；電腦帳號計入。
  來源缺席（抽不出 IP 也無工作站）的失敗不參與噴灑判定。
- 註冊為關聯模式 ID（可被 Correlation 型抑制），訊號文字含來源與帳號數。
- 與 A3 互斥性：噴灑形狀天然不符殘留判準（多帳號），測試需釘住這一點。

**驗收**：噴灑形狀命中、殘留形狀不命中、正常零星失敗不命中；抑制可靜音。

## 作業 B：NetIQ 主機探索改良

### B1 提早停頁

**目標**：探索只要 distinct IP，不需翻完整份結果——把單輪耗時從約 85 秒壓到常態十幾秒。

**行為契約**
- 殘差輪掃的單輪翻頁中，「連續 K 頁未出現任何新主機」即結束該輪（K 暫定 3），
  該輪視為未觸頂完整（不再進殘差）——**注意**：提早停頁代表後頁可能仍有未見主機，
  故提早停頁的輪**仍應視為觸頂**進入殘差輪（除非該輪總取回數 < 上限且已翻完）。
  此語意執行端不得自行放寬：提早停頁＝「省時間」不＝「已涵蓋」。
- 涵蓋說明（CoverageNote）與警告語意不變。

**驗收**：以假 client 的分頁序列測試——「前 3 頁有新主機、後 47 頁重複」時輪內請求數大幅下降
且仍進殘差輪；「翻完未觸頂」時不誤標。

### B2 網段自動分割輪掃

**目標**：使用者實務輸入為 `192.168`／`192.169` 這類 /16 級前綴——自動拆成 /24 逐段掃，
每段結果集小（最多 254 台）、吵主機壟斷不了整段、殘差排除永不逼近 500 子句上限，
且大幅降低對未實證 `NOT` 大清單的依賴。

**行為契約**
- 輸入前綴比 /24 寬（如 `192.168`）時，自動展開為 /24 子網段序列（`192.168.0` ~ `192.168.255`）
  逐段掃描；輸入已是 /24 級（如 `192.168.1`）則單段、行為近似現狀。已見集合與結果跨段共享。
- **段粒度可選**：精靈提供掃描粒度選項——/24（254 台，預設）／/25（126 台）／/26（62 台），
  單次掃描生效、非持久設定。查詢表達方式依粒度分流：
  - /24 段沿用前綴萬用字元 `repip:{prefix}.{n}.*`；
  - **/25、/26 無法對齊字串前綴**（範圍查詢在點分十進位上是字典序、不可用）——改用
    「逐 IP 明列 OR」子句；每查詢子句數上限 64（probe 實證 OR 50~100 個可用的安全側），
    故 /25 段內部以兩個 /26 查詢執行後合併。此為粒度選項的實作前提，執行端不得改用
    未實證的範圍語法。
  - 更細粒度的段內殘差排除子句天然更少，對 NOT 的依賴進一步下降。
- **展開上限**：`輸入寬度 × 粒度` 的總段數上限暫定 512（/16×/24=256 ✓、/16×/25=512 ✓、
  /16×/26=1024 ✗ 拒絕並提示改用較粗粒度或縮小輸入範圍）；預算估算隨段數線性放大。
- 每段：主掃描（24h 窗、窄化頻道 filter 沿用）＋提早停頁（B1）；段內觸頂才進段內殘差輪
  （NOT 排除只帶**該段**已見 IP，天然 ≤254 子句；未生效偵測沿用）。
- 60 分鐘全頻道補充掃描維持，但同樣按段執行或以整前綴一次補充，執行端依成本取捨並記錄。
- **時間切片為第二層補救**：單一 /24 段殘差輪數用盡仍未收斂時，才對該段把 24h 窗拆片重掃
  （暫定 4 片 × 6h）；一般情況不啟用。
- 涵蓋語意重新表述：CoverageNote 呈現「N 段完整／M 段未收斂（列出網段）」；
  Warning 條件對齊新結構。空段（無任何事件）不計為警告。
- 段數展開上限與切片參數為 internal const（不新增設定鍵）；輸入寬於 /16（如 `10`）時
  拒絕並提示範圍太大（暫定，避免 65536 段展開）。
- **重掃排除復活**：knownIps 依段過濾後套用（每段 ≤254），既有「>500 整組放棄排除」分支
  只剩防禦性保留——重掃已登錄網段回到「趨近免費」。
- **段間並行**：沿用既有 `NetiqOptions.MaxParallelQueriesPerServer`（預設 1）允許多段並行，
  不新增設定鍵；`QueryDelayMs` 有設時計入預算估算。

**驗收**：假 client 測試——(a) /16 前綴展開段數正確、跨段結果聯集正確；(b) 吵主機壟斷某段時
其他段的安靜主機仍全數發現；(c) 段內未觸頂不發殘差查詢；(d) 未收斂段正確列入 CoverageNote；
(e) /24 輸入不展開；(f) /26 粒度時查詢為 ≤64 子句的逐 IP OR、/25 段確實以兩個 /26 查詢執行；
(g) 超過展開上限的組合被拒絕且訊息明確。NOT 未生效偵測行為不變。

### B3 掃描背景化

**目標**：解掉 90 秒互動預算與涵蓋保證的根本矛盾，讓大網段（/16、上千台）掃得完。

  預估 8~10 分鐘；更細粒度段數翻倍，預算需留餘裕——展開上限 512 段即以此預算回推）；

  重新掃描，不做持久化恢復（暫定，掃描可重跑、不值得引入持久化複雜度）。
- 精靈 modal 關閉後重開可續看進度（工作識別由前端暫存）。

**驗收**：假 client 端到端——啟動→輪詢→完成→匯入流程可走通；取消生效；重複啟動被擋；

### C3 Linux 規則過寬修正（順手 bug 1）

**目標**：`builtin-linux-account-change`（`ProgramPattern="user"`）與 `group-mgmt`（`"group"`）
