### 不過度設計：複檢後砍掉或縮小的項目

| 原構想 | 改為 | 理由 |
|---|---|---|
| CSS 五檔（token 獨立一檔） | 四檔，token 併入 `base.css` | token 與元素預設總是一起讀；少一個請求、少一個歸檔判斷 |
| `text(role, …)` 文字工廠 | 不做；直接用角色類別 | 只設 `className` 的工廠沒有封裝任何行為 |
| `lf-text-body` 角色 | 不做；沒有角色的文字就是正文 | 預設值不需要名字 |
| `iconButton`、`detailButton` 兩個新工廠 | 擴充既有 `button()`（已支援純圖示＋`title`），加一個 `opens: 'dialog'` 選項 | 同一件事不要兩個出口（DRY） |
| 資料集做成略過型測試 | 一般測試（每次都跑、寫到暫存目錄） | 略過型會隨 schema 演進悄悄壞掉；略過數也不必改 |
| 量測工具接 CI、像素比對守門 | 不做；工具只當開發與體檢工具，像素比對只用在 A-1 一次 | 截圖隨字型渲染浮動，進 CI 會是常態性誤報 |

**新增抽象的門檻**：同一結構在三個以上頁面出現才抽進 `core/`；不到三處留在頁面內。
`core/elements.js` 本輪只放三個匯出：`disclosure`、`metaLine`、`statusNote`。

## 批次 A：基座

### A-0 多樣化測試資料集與截圖／量測工具

**目標**：一個測試產出涵蓋版面邊界的 SQLite 資料庫；一個指令以它啟動站台、逐頁逐寬度截圖並輸出可機器判定的版面量測。

**資料集契約**（`LogForesight.Tests/UiFixture/`；形狀比照 `ScaleDataSet`：經產品 `StorageBackend`、固定亂數種子）

- 一般測試：每次都產生到暫存目錄並斷言矩陣。設 `LF_UI_FIXTURE=<目錄>` 時另把 DB 留在該目錄供站台使用。
  產生時間**暫定 10 秒內**；超過就縮小資料量（每格一例即可），不改成略過型。
- 能走產品 store／service 寫入的就走；只有量大的歷史列可以直接 INSERT。
- 另產一份「AI 未設定」變體（同資料、設定不同），因為 AI 區塊的有無會改變版面。
- 資料集是測試資料，不得被站台的任何正式路徑引用（不放進 `LogForesight.Web`）。

**多樣性矩陣**（每格至少一例；可增不可減）

**量測工具契約**（`LogForesight.Tests/tools/ui-shots.mjs`；零第三方相依）

- **暫定技術路線**：Edge `--remote-debugging-port`＋Node 22 內建 WebSocket 走 CDP。實作第一步先寫探針確認「能登入、能截整頁、能讀 console」，
  不行就改路線並回寫本節。Edge 路徑可用參數指定。
- 站台從獨立的發佈輸出目錄啟動，不占用 `bin`（預覽站台會鎖 bin）。
- 情境清單是資料檔：`{ 名稱, 角色, 網址, 步驟 }`，步驟只有四種：點選、輸入、等待元素、**斷言**（元素可見／不可見／文字包含）。
  每頁至少一個情境；有展開列、modal、頁籤的頁面各加一個。
- 矩陣：寬度 375／768／1280／1920／2560、字級「中」；另在 375 與 1280 加跑字級「小」「大」（`localStorage` 鍵 `lf.fontScale`）。
- 每格輸出截圖與量測。量測項（每項「0 才通過」）：
  1. 頁面水平捲軸；
  2. 元素超出所屬卡片或表格格子右緣（排除宣告橫向捲動的容器）；
  3. 可點擊元素的點擊區小於 24×24；
  4. console error 與失敗的網路請求；
  5. 頁面停在載入中或錯誤狀態；
  6. 情境中的斷言失敗。
- 另記錄不設門檻的觀察值：DOM 節點數、樣式表總位元組。
- 輸出到 repo 外目錄並產彙總 JSON；任一量測項非零時結束代碼非零。
- 加跑一次子路徑站台（`--Server:PathBase=/LogForesight`）的登入頁與任一內頁：只看量測項 4，確認樣式表在子路徑下載得到。

### A-2 寬度策略與中斷點

**契約**
- 中斷點只用 576／768／992／1200／1600，寫法統一為 `min-width: N` 與 `max-width: N−0.02`。`max-width: 768px` 改 `767.98px`（X4）。
  現有 `1799.98px` 併入 1600。`core/side-rail.js` 的 `RAIL_MEDIA_QUERY` 與 CSS 維持同值。
- token `--lf-content-max`（**暫定 120rem**）：詳情頁（風險日、主機、處理人、使用者、交辦單）與表單型頁（設定、初始設定）的內容區不超過它，靠左。
  清單頁、儀表板、報表、PRTG／NetIQ／排程維護頁滿版。
- token `--lf-measure`（**暫定 40em**，沿用 AI 摘要現值）：成段文字的行寬上限；表格與技術值不套用。
- ≥1600 時詳情頁側軌預設展開；使用者手動收合或展開過的選擇優先（沿用側軌既有的記憶機制，不另加儲存鍵）。

### A-3 文字角色與語意文字色

**契約**
- 五個角色類別（`components.css`），頁面只用角色，不再現場拼 `small text-muted fw-semibold`；沒有角色的文字就是正文：

  | 角色 | 用途 | 取值（暫定，沿用既有 token） |
  |---|---|---|
  | `lf-text-title` | 列或區塊的主標 | base、600、`--lf-text` |
  | `lf-text-meta` | 次要資訊（次數、時段、來源） | sm、400、`--lf-text-muted` |
  | `lf-text-label` | 眉標、欄位標籤 | sm、600、`--lf-text-muted` |
  | `lf-text-data` | 技術值與數字 | mono、tabular-nums |
  | `lf-text-alert` | **風險狀態**文字（逾期、失聯、失敗） | 600、danger 系 |

- 新增 `core/elements.js`：
  - `metaLine(項目陣列)`：一行次要資訊；項目可為字串或 Node；空值略過；窄時整項換行、行首不出現分隔符。
  - `statusNote(類型, 文字)`：操作結果與驗證訊息（成功／失敗／提示），帶圖示與 `role`（失敗為 `alert`、其餘 `status`）。
- `text-danger／text-warning／text-success` 分三類：驗證與操作結果 → `statusNote`；風險狀態 → `lf-text-alert`；其餘（純資訊誤用）→ 一般文字色。
- 角色類別一律用 rem token，不用 Bootstrap `.small`（相對 em，巢狀會連乘縮小）。
- 一個文字節點只帶一個角色；容器不帶角色。

**驗收**
| 項目 | 怎麼驗 |
|---|---|
| `metaLine` | 行為測試：0 個有效項目回傳 null；1 個項目無分隔；含空字串與 null 的陣列只渲染有效項；字串項走 `textContent`（傳入 `<b>` 不產生元素） |
| `statusNote` | 行為測試：失敗類型 `role="alert"`、其餘 `role="status"`；文字走 `textContent` |
| 對比 | `AccessibilityUiTests` 既有的對比計算加入五個角色的前景／背景組合，皆 ≥ 4.5:1 |
| 棘輪 | 新守門：`wwwroot/js/pages` 與 `Views/Pages` 不得出現 `text-danger|text-warning|text-success` 與 `small text-muted`；允許清單＝現況有命中的檔案。突變：在允許清單外的檔加一個 `text-danger`，測試轉紅；把清單內的檔清乾淨卻沒從清單移除，測試也轉紅（清單不得有多餘項） |
| 替身 | `JsModuleImportTests` 綠；`mini-dom` 與用到的 `.behavior.mjs` 替身補上新匯入 |
