# 第 81 輪可用性測試項目

> 用途：上線前盡早發現「步驟多餘、難用、數字對不起來、量大就處理不完」的問題，而不是等使用者不願意用才知道。
> 範圍：全部角色、全部頁面操作、交辦生命週期、資料量與工作量、併發、錯誤與邊界、呈現與一致性。
> 搭配：`docs/FEEDBACK-81-PLAN.md`（發現與修正規劃）。本文件每一項都要有結果欄；結果寫在第 8 節「執行紀錄」。

## 0. 判定標準（什麼算問題）

一項操作符合下列任一條，就記為發現：

| 代號 | 標準 | 說明 |
|---|---|---|
| S1 | **每天都會做的事超過 3 步** | 從「進到該頁」算起到「完成並看到結果」的點擊／輸入次數。處理人回覆、管理員派工屬此類 |
| S2 | **同一動作要對 5 筆以上逐筆重做** | 應有批次；批次也要能跨頁 |
| S3 | **死路** | 看到問題卻無法從該處直接處理，要記住名稱到別頁重找 |
| S4 | **預覽與結果不同** | 預覽說 N，實際寫 M；或建完才告知重要後果 |
| S5 | **畫面與實際不符** | 畫面成功、資料未存；或兩處狀態矛盾 |
| S6 | **同一數字跨頁不一致** | 卡片數字≠下鑽筆數；徽章≠清單；同欄位不同口徑 |
| S7 | **雜訊淹沒重點** | 不能處理或不需處理的項目排在可處理項目前面、或撐大待辦數 |
| S8 | **回應過慢** | 互動請求 > 1 秒、頁面首屏 > 3 秒（在測試資料量下） |
| S9 | **無從得知下一步** | 空狀態、錯誤、權限不足時沒有說明或錯誤說明 |
| S10 | **版面破損** | 溢出、重疊、文字逐字直排、需要水平捲動才看得到關鍵欄 |
| S11 | **量大時處理不完** | 依模擬的每日新進量與合理產能，積壓持續成長且畫面無協助（排序、批次、分流） |

嚴重度：**高**＝資料錯誤、權限錯誤或使用者會放棄使用；**中**＝每天多花明顯時間或容易誤判；**低**＝偶發或外觀。

## 2. 角色劇本（以「一天的工作」走完整流程）

每個劇本記：總步驟數、卡住處、跳頁次數、花在找東西的步驟。

### R1 處理人的一天（D2，h-chen）
1. 登入後第一眼：知道今天有幾張新單、幾台逾期、哪張最急。
2. 依期限處理：打開最急的單 → 判斷問題（看證據、看主機）→ 整單回覆或部分回覆。
3. 處理一張 30 台以上的單，其中 5 台「已處理」、其餘「觀察中」。
4. 一台主機同時有 3 張單（不同問題）：能否在主機視角一次看到並分別回覆。
5. 觀察期到期的成員：在哪裡看到、怎麼接手。
6. 處理不了要上報：上報後在哪裡看到結果。
7. 處理權限異動檢核。
8. 一天結束：確認自己沒有遺漏（未回覆、逾期都是 0 或有理由）。

### R2 管理員的一天（D2，a-admin）
1. 早上看儀表板：哪些要處理、夜間派工派了什麼、派不出去什麼。
2. 處理派不出去：補授權或手動派。
3. 看負載是否失衡；把某位處理人的一部分單轉給別人。
4. 處理上報：退回處理人或代為結案。
5. 處理雜訊：某問題 300 台都有、確定無害 → 統一標記或靜音或調規則；比較三條路的步驟與後果。
6. 新主機上線 20 台：設群組、負責人、確認會被派工。
7. 處理人離職：停用帳號 → 名下所有單轉走。
8. 查「某主機上週為什麼沒有紀錄」。

### R3 主管的一週（D2，m-manager）
1. 看整體風險與處理成效；找出積壓最多的團隊與問題。
2. 下鑽到具體問題與主機，確認處理進度。
3. 匯出或列印報表。
4. 唯讀角色看到的每個提示都不要求他做做不到的事。

### R4 開發維運的異常日（d-dev）
1. 昨晚取數失敗：從排程作業找到原因、受影響主機與日子。
2. 判斷 AI 待補、NetIQ 帳本、PRTG 狀態。
3. 匯出診斷資料。

### R5 主機負責人（ui-owner／o-owner）
1. 知道自己負責的主機今天有什麼問題。
2. 對自己主機的多個問題一次下結論。
3. 自己主機被派給別人處理時，看得到誰在處理、處理到哪。

### R6 受限使用者（ui-viewer／v-viewer）
1. 只看得到授權主機；所有清單、下拉、計數、匯出都不含範圍外主機。
2. 被交辦了看不到的主機時，看到什麼、能不能處理。

### R7 救援帳號（svc-lfadmin）
1. 指派正式管理者的完整步驟。
2. 不會看到業務資料、不會被引導到做不到的頁。

### R8 第一次使用（新站台、新使用者）
1. 首次啟動精靈到第一次取數的步驟。
2. 新處理人第一次登入：空狀態是否說明「為什麼是空的、什麼時候會有」。
3. 說明書能否回答劇本中卡住的問題。
