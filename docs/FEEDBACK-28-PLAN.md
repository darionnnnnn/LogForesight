## 作業 A｜設定頁：資料保留改版＋分析參數生效透明化（P1、P2）

### A1 保留鍵合併與遷移（後端）

**目標**：`DetailRetentionDays` 與 `RiskyEventRetentionDays` 合併為單一鍵 `RawEventRetentionDays`（原始事件內容保留天數）。

**行為契約**
- 新鍵同時驅動原本兩個消費端：`PruneDetails`（日紀錄樣本訊息）與 `riskyEventStore.Prune`（含寫入時窗口）。
- 既有設定遷移：新值＝兩舊值中**較小者**（保守，不讓本來會刪的資料變成不刪）。舊鍵讀取端全部移除；DB 中舊鍵列清理。
- 跨欄位驗證維持：`RawEventRetentionDays ≤ RetentionDays`；服務層與前端 `min/max` 同步。
- 預設值（暫定）：`RawEventRetentionDays = 120`、`RetentionDays` 預設由 120 → **180**、`RunLogRetentionDays` 90 → **120**（使用者要求保留期拉長；`AuditRetentionDays` 730 不動）。執行端不得自行再改預設。
- `RuntimeSettingsResolver` 越界退回預設的第三道防線同步改用新鍵。

**驗收**
- 既有測試改名/改鍵後全綠；新增遷移測試：兩舊值不同 → 取小；只有一舊值 → 沿用；皆無 → 新預設。
- grep 全庫無 `DetailRetentionDays`、`RiskyEventRetentionDays` 殘留（docs 除外，docs 由 A4 收）。

### A2 保留區 UI 改版（前端＋文案）

**目標**：資料保留面板改為每項「標題／常駐說明／天數輸入框」直列式，說明不再藏 popover。

**行為契約**

- 每項常駐說明必須寫明「這個天數刪的是什麼資料」，其中稽核項須明列三種資料（操作稽核、權限異動紀錄、處理歷程）。
- 「首次執行回補天數」移出「永久刪除」警示卡，另立小節（不刪資料的定位要看得出來）。
- 前端 `min="90" max="3650"` 與跨欄位關係提示照舊；刪除警示卡文案保留。

**驗收**：頁面呈現四項直列＋獨立回補小節；popover 移除或僅留補充；瀏覽器實測存檔後值正確寫回。

### A3 分析參數生效時機標示（前端，Claude 可自做或併入 A2 委派）

## 作業 B｜報表頁：比對前期完整化＋根因修高度（P3、P6、P13）

### B1 比對前期三缺口（後端＋前端）——修訂版（2026-08-25，補做前重核對）

> 原契約寫於 A1 之前；重核對後修訂如下。現況：後端已有「前期**終點**早於保留線」的
> `ComparisonOutOfRetention` 旗標＋前端黃色提示＋測試；前端自動切 yoy 的門檻寫死 180；
> 下拉兩個 option 恆為可選。保留天數現由 `SystemSettings.RetentionDays` 提供（A1 後預設 180）。

**行為契約**

1. **部分超出警告**：前期區間與保留線交疊（`previousFrom < 保留線 ≤ previousTo`）時，
   回傳新旗標 `ComparisonPartiallyOutOfRetention`，前端顯示黃色提示
   「比較期間有一部分早於保留期，對比數字會偏低」。既有「全部超出」旗標與文案不動；
   兩旗標互斥（全部超出時只設原旗標）。保留線判定沿用既有寫法
   （`DateTime.Today.AddDays(-RetentionDays)`），不另立第二種算法。
2. **DTO 帶出保留天數**：`ReportSummaryDto` 加 `RetentionDays`（目前設定值），
   由 `ReportService.GetSummary` 填入——前端的門檻與標註都吃這個值，不得寫死。
3. **自動切 yoy 的門檻修正**（根因：180 是寫死的猜測，與保留設定脫鉤）：
   - 規則改為「**只有保留天數足以涵蓋去年同期**（`RetentionDays >= 365 + 區間天數`）時，
     長區間（區間天數 >= 180）才自動切 yoy；否則一律維持 previous」。
     previous 殘缺的情形交給第 1 點的警告呈現，不再自動切到一個必然全空的模式。
   - 前端第一次載入 summary 之前拿不到 RetentionDays——此時**不做自動切換**（維持
     previous），首次查詢回來後存下該值供後續日期變更使用。
   - `updateDefaultCompare` 與 `setRange` 兩處門檻同源（一個函式），不得各寫一份。
4. **下拉標註**：「對比去年同期」option 在「(今天 − RetentionDays) 晚於 (結束日期 − 1 年)」
   時，文字附註「（超出保留期）」，仍可選；日期或設定變更時標註即時更新。

**驗收**

- ReportService 測試補三態：全部超出（僅原旗標）／部分超出（僅新旗標）／未超出（皆 false），
  以及 `RetentionDays` 有帶出。沿用既有測試檔的建構方式；測試總數 > 2571。
- 前端以瀏覽器實測：(a) 部分超出提示出現、(b) 保留 180 預設下選 200 天長區間**不再**自動切 yoy、
  (c) yoy option 標註隨日期變化。
- grep `reports.js` 無寫死的 `180`（改由 RetentionDays 推導；「區間 >= 180 才考慮 yoy」的
  長區間門檻若保留，須以具名常數＋註解說明它是「長區間」語意而非保留語意）。

**執行者**：Claude（改動跨後端＋前端但每處都小，且門檻語意曾被誤解，不委派）。

### B2 高度不齊根因修（CSS）＋撤補丁（P6、P13、P7 的 CSS 半邊）

**目標**：統一 `.btn`／`.form-control`／`.lf-chip` 的字級與高度基準，撤掉兩處「猜像素」補丁。

**行為契約**

- 不得新增任何 inline `style` 高度。

**驗收**：報表頁與問題查詢頁截圖比對：同列輸入框/按鈕/chip 等高；字級縮放（小/中/大）三檔下皆不破。grep 全庫無 `height: 31px`、無 `min-height: 3.5rem`（該兩處）。
