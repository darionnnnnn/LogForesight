## 怎麼讀這份文件

- **核對狀態**：每條改動標 **〔已核〕**（主代理親自讀碼或實跑確認）或 **〔待核〕**（只有 subagent 回報）。〔待核〕的項目，該批次開工第一步由主代理讀碼確認；不成立就移除並在執行紀錄記一行。盤點過程已推翻三條，這一步不能省。
- **驗收**：每個改動項目各有一條驗收，全部是主代理在開發環境能執行並判定的。可用的手段只有這些：
  - macOS 上的 `dotnet build`、`dotnet test`（定向與全量）、`dotnet publish`、`dotnet list package`。
  - Windows 全量測試（Mac Studio 的 Windows 11 VM）。
  - 以 `WebApplicationFactory` 起站台發請求；測試內自建的 HTTPS 伺服器與假的外部服務。
  - UI 量測工具（五個寬度、六項量測）與 Node 前端行為測試。
  - `git grep` 與推送後讀 CI 結果。
- **主代理驗不到的**（真實 IIS、AD、SQL Server、PRTG、Sentinel、正式站台）不寫成驗收，另列在文末「正式站台實測清單」交給使用者；每條都對應一個已通過的模擬驗收。

## 根因（決定批次怎麼切）

約 200 條發現歸納後是五個根因，批次依根因切，不依檔案切：

1. **防線建在文字比對上，不在編譯器或行為上。** 116 個掃原始碼的測試；沒有 `.editorconfig`、沒有啟用安全類分析規則、沒有弱點稽核。每出一次事就加一條紅線與一個字串掃描測試。
2. **「每個呼叫點自己記得做」，沒有「單一出口強制做」。** 截斷、輸入驗證、授權欄位裁剪、收件人資格都是這個形狀。
3. **以通用型別或字串當領域訊號。** 用 `InvalidOperationException`、例外訊息字串、畫面文字前綴來做程式判斷。
4. **專案自己已有唯一出口，旁邊又寫一份。** 對應選取、落庫後流程、服務組裝、狀態常數、快取。
5. **信任邊界全有全無。** 憑證驗證只有全驗與全不驗；回應中的絕對網址原樣使用。

設計原則：每個修正優先選「讓錯誤寫法寫不出來或一測就紅」的做法（型別、單一出口、行為測試），其次才是加檢查。不為了收斂而收斂：只收斂已經出現分歧或已經造成缺陷的重複。

## 重新檢視：維持、替換、不改的理由

### 維持自製，而且現況真的比較好

| 項目 | 理由 |
|---|---|
| `markdown-lite.js` | 只支援不含連結、圖片、原始 HTML 的子集，全程以 DOM API 建構。通用 Markdown 程式庫加淨化器會把連結與 HTML 兩個攻擊面帶進來再擋回去。 |
| `sha256-stream.js`／worker | `crypto.subtle.digest` 不支援分片增量，且在非安全來源不可用（站台支援 http）。 |
| `IpSyntax` | `IPAddress.TryParse` 把 `10.1`、`12345` 解成別台主機位址，是框架的既定行為。 |
| `PrtgRequestBudget` | 內建限流器沒有時鐘注入點，也表達不了「送出才起算」。 |
| `SingleFlight` | BCL 沒有對應型別；現行寫法就是慣用的 `Lazy` 去重。 |
| `LoginThrottle` | 需求是「只計失敗、可列出、可手動解除」，請求限流中介軟體不提供。 |
| CSRF 自訂標頭 | `SameSite=Strict` 加自訂請求標頭是 JSON API 的標準做法。 |
| 安全標頭與 CSP nonce | 框架沒有內建；現行實作短且嚴格。 |
| `PasswordHasher` | 直接用 `Rfc2898DeriveBytes.Pbkdf2` 與 `FixedTimeEquals`。 |
| `AiRequestGate` | 互動優先加動態並行上限，內建限流器無法每次取許可時重讀設定。 |
| AES-GCM 欄位加解密 | 原語用法正確。Data Protection 的設計重心是有期限的保護載荷與自動輪替。 |
| 七份快取的**演算法**（上限、到期、版本戳、統計） | `IMemoryCache` 的大小逐出是背景近似，要在外面包一層才能恢復「同步、嚴格的元素數上限」與統計，程式碼不會變少。問題是抄了七份，不是自己寫。修法是抽成一份（H1），不是換元件。 |
| PRTG 取數的暫停閘與總暫停上限 | 跨工作者共用的領域規則，重試程式庫不涵蓋。只把分頁器裡的單純重試改用 Polly（H8）。 |
| 執行匯出去識別 | 官方的資料遮蔽程式庫不做樣式偵測。 |

### 全輪共同契約

每個階段規格都要逐條抄進規格與驗收：

- **領域訊號不用通用型別與字串。** 新增或改到的判斷一律用專屬例外型別或列舉。
- **先寫會紅的測試。** 每條缺陷修正先寫出在未修正的建置上會紅的測試並確認它紅，再修。
- **邊界兩側各一例。** 有門檻、上限、分隔規則的契約，驗收要有剛好通過與剛好不通過的案例；主代理每階段至少做一個突變，突變用檔案備份還原並更新時間戳。
- **守門先拿反例試。** 新的守門或「搜尋零命中」類驗收，先放一個該命中的寫法確認它會紅。
- **既有資料不能因為規則變嚴而讀不出來。** 變嚴的驗證只擋新的寫入；既有的不合規資料要讀得出來，並在儲存時指出是哪個欄位。
- **不新增沒有消費端的設定。** 本輪新增的設定只有 E1 的兩個憑證指紋。
- **移除時交代依賴方。** 刪掉的類別、匯出、樣式、守門白名單條目列成清單，以 `git grep` 零命中驗收。
- **定向測試篩選詞開工時實跑**，確認命中數大於 0 且含該階段新增的測試。改前端至少含 `UiTests|JsModuleImport|BehaviorTests|ApiTimeout`；新增或搬動端點加跑 `Authorization|ControllerRouteSnapshot|IssueExclusionTests`；改現行文件加跑 `DocNarrativeGuardTests`；改說明書加跑 `HelpContentServiceTests|HelpWritingGuide`。
- **commit 寫成「測試通過才執行」的條件式指令**；每批驗收通過後在 `feature/feedback-79` commit 並 push，確認遠端指向該提交。

### 定案

- 升級只改框架與套件版本，不順便採用新 API。
- 套件版本集中管理並產生鎖定檔；CI 以鎖定模式還原。
- 開發機與 CI 用同一個 SDK 主版。
- 不選的方案：留在 .NET 8 只升修補版。執行階段本身已無安全修補。

### 改動與驗收

| # | 改動 | 驗收 |
|---|---|---|
| P1 | 三個專案目標框架改 `net10.0`；Microsoft 套件（EF Core、Hosting、Mvc.Testing、`System.DirectoryServices` 等）對齊到 10.0 的最新修補版 | macOS 與 Windows 全量測試都維持基線通過數；有差異的測試逐條列進執行紀錄並說明原因 |

| P8 | `CLAUDE.md` 的框架版本與測試基線敘述同步 | `DocNarrativeGuardTests` 通過 |

### 試建置紀錄

主代理在暫存工作樹實跑（2026-11-19，macOS、SDK 10.0.404、SQLite 後端；未在 Windows 與 SQL Server 上跑），分四步，每一步的結果決定了 P1 的做法：

| 步驟 | 做了什麼 | 結果 |
|---|---|---|
| 1 | 只把三個專案的目標框架改成 `net10.0`，套件不動 | 建置零錯誤；全量 1,239 筆失敗。兩個主因：測試伺服器套件（8 版）在新執行階段回應寫入失敗，585 筆；EF Core 8 無法評估 LINQ 查詢參數（新版 C# 把陣列的 `Contains` 綁定到 span 多載），269 筆；其餘多是這兩者的連帶 |
| 2 | EF Core、測試伺服器等套件升到 10.0 | 還原失敗：`System.Diagnostics.EventLog` 9.0.0 與間接相依要求的版本衝突 |
| 3 | `System.DirectoryServices`、`.AccountManagement`、`System.Diagnostics.EventLog` 也升到 10.0 | Core 與 Web 編譯通過；測試專案一個編譯錯誤（`ExecuteUpdate` 在新版 EF Core 換了宣告類別，一處以類別名直接呼叫） |
| 4 | 改掉那一行 | 建置成功（40 個警告）；全量 **10,968 通過／8 失敗／21 略過**（基線 10,976 通過） |

結論：

- **框架與套件必須同一步升級**，不能分兩個提交；中間狀態有上千筆測試是紅的。
- 正式程式碼不需要為了編譯而修改。
- 殘留 8 筆失敗，是 P1 與 P6 的實際工作量：
  - `QueryPlanGuardTests` 1 筆：`lf_daily_records` 出現整表掃描。這是真的效能退化，要改查詢寫法讓它回到走索引，不能改預期。
  - `PrtgBatch4RepeatedLoadTests` 2 筆、`PrtgBatch4CalibrationReadTests`、`PrtgMonitoringSensorTypesProjectionTests`、`CalibrationResidualRetryTests` 各 1 筆：比對產生的 SQL 或讀取次序，新版 EF Core 的翻譯不同。逐筆判斷是預期字串要更新，還是查詢行為真的變了。
  - `PrtgSnapshotHostedServiceTests` 1 筆（有界等待內沒完成採樣）、`AIServiceExtraRequestFieldsTests` 1 筆：原因未查，開工時單獨重跑確認是不是負載下的偶發。
- 建置警告中有一條 `ForwardedHeadersOptions.KnownNetworks` 已過時，在 A4 一併處理。
- 這份資料的限制：只在 macOS 與 SQLite 上跑。Windows 專屬測試與 SQL Server 的翻譯測試（`ToQueryString`）要在 P1 的驗收中另外跑。

- 回應中的網址一律以站台位址解析後檢查同源。

## 批次 F：偵測取得性與擷取

### 現況與核對結果

- 本機來源對 System 與 Application 頻道只收錯誤與警告〔已核〕。「安裝新服務 7045」與「系統日誌清除 104」兩條規則在本機來源取不到〔已核規則存在；事件等級待 F1 的測試確認〕。
- 「稽核日誌清除 1102」在本機靠另一條重複規則的監看清單才收得到〔待核〕。
- NTFS 規則列了 98、130 等事件編號；其中 98 在 Windows 上同時用於「磁碟區健康」與「需要檢查」等不同等級的訊息〔主代理的知識，待 F1 確認〕。
- sudo 認證失敗的片語是單數，下推到 Sentinel 是整詞比對〔待核〕。
- Linux 規則的片語在本地是子字串比對、下推是整詞片語〔待核〕。
- 帳號標籤值超過 128 字視為空值〔已核〕。
- sshd 規則只認 IPv4；成功登入只認兩種認證方式〔已核〕。IPv4 正規式重複三份〔待核〕。
- 文件記載 `dun`、`tuid` 是結構欄位，程式沒有投影〔已核文件〕。
- fail2ban 的 `Ban ` 會命中 `Unban `〔待核〕。

### 定案

- **本機收錄資訊等級事件：用頻道政策的明列清單，不用「由規則的事件編號自動推導」。** 自動推導會把 NTFS 98 這種「同一編號、健康訊息是資訊等級」的事件一起收進來，變成每天的假告警。清單與既有的頻道政策放在同一處，初始只含經 F1 確認的項目。
- 1102 的依賴以守門測試固定。
- 片語下推語意：規則驗證在既有的遮蔽警告機制裡加一類「這個片語在 Sentinel 取數階段取不到」，是警告不是拒絕，既有規則不會因此存不了。
- 超長帳號改成截斷保留。
- IP 擷取收成一份並支援 IPv6；sshd 成功登入放寬為任何認證方式。既有持久化的資料格式不變。
- `dun`／`tuid` 只加進 NetIQ 探測的一個步驟，回報這兩個欄位能否投影與內容形狀。正式取數的投影不動：對外部系統加未驗證的投影欄位，可能讓整個取數失敗。
- 暴力破解錨點擴到 4771／4776、`ResidualCredentialDetector` 的降級條件不在本輪：都是偵測行為變更，沒有實機資料可驗證對錯。

## 批次 K：AI 提示安全

### 現況與核對結果〔皆待核〕

- 深入分析與週體檢的提示沒有資料界線，也沒有「資料不是指令」的聲明。
- 主分析的界線只包住事件與 PRTG 區塊；頻率異常文字與近期歷史摘要在界線外。
- 界線是固定字串，日誌內容可以寫入結束標記。
- AI 輸出整段做簡轉繁，回顯的帳號與主機名可能被改字。

- 外部文字進提示只有一個出口：包進界線、界線帶每次請求的隨機值、剝除內容中的界線字串。
- 簡轉繁只作用於敘述欄位。

## 批次 D：外部字串落庫

### 現況與核對結果〔皆待核〕

- 截斷由每個寫入點手動呼叫，約 50 處；約 20 個有長度上限的外部字串欄位沒走截斷路徑；多處把長度寫成字面值。
- 寫入方式：`SaveChanges` 約 75 處、`ExecuteUpdate` 20 處、`ExecuteSql` 16 處、原生指令約 21 處。
- 遷移器搬入既有資料時沒有截斷。
- 截斷會切斷代理對；安全截斷的實作至少四份。
- 暫時性錯誤以訊息字串判定。
- 對帳測試只比欄名與可否為 null。

### 定案

- 截斷集中在 `LfDbContext.SaveChanges`：對新增與修改的實體，有長度上限的字串屬性依模型定義截斷。屬性清單依實體型別快取，不逐筆反射。

- 繞過 `SaveChanges` 的三到四處各自呼叫同一個截斷方法。
- 截斷方法只有一個，代理對安全。
- 不選的方案：以值轉換器截斷。它在查詢條件上也會生效，改變比對語意。

| # | 改動 | 驗收 |

| D2 | 鍵欄超長時該筆不寫並出聲 | 每個鍵欄寫入超長值：該筆不存在於資料庫且有警告記錄；同一批的其他筆照常寫入 |

| D4 | 單一安全截斷方法；其餘實作刪除 | 截斷點落在代理對中間時結果不含孤立代理字元；其餘實作的方法名 `git grep` 零命中 |
