## 作業總覽

- **目標**：客戶展示時看得出是設計過的產品，不是套了 Bootstrap 的通用後台。品牌藍、Fira 字體、淺色主題、資料密度優先、不加裝飾效果、滑過不位移，這些定案不變。
- **範圍切法**：新視覺方向拆兩輪。本輪做「不新增互動就能完成」的部分，27 頁全部受惠；需要新元件與新操作方式的留給第 72 輪，見文末。
- **實作方式**：內建 Agent subagent（跨檔樣式用 Sonnet 5.5、單純測試段用 Haiku 5.5），同一 checkout 一次只派一個改檔代理；設計契約、驗收、突變、畫面量測與前後對照由主代理親做。整輪不換委派模型。

- **版號**：本輪第一個提交把 `Directory.Build.props` 改為 `1.0.71.0`（批次 A）。
- **提交**：每個批次驗收通過後 commit 並 push 到 `feature/feedback-71`，以「測試通過才提交」的條件式指令執行。

### 為什麼只改外觀層

- 按鈕外觀由 Bootstrap 5.3 的 `--bs-btn-*` 變數決定，`base.css:282-329` 已經在覆寫。直接重定義既有變體的外觀，寫死在 `.cshtml` 的 218 處與走 `button()` 的呼叫端會一起變，不需要改標記，也不需要動「按鈕只用設計系統的五種變體」這條守門。
- 標記的顏色變體集中在 `components.css:452-479`，分段控制都是 `btn-group`，篩選膠囊都是 `lf-chip`，提示框都是 `alert-*`，同樣可以在樣式層一次處理。
- 頁面模組有 204 處 `querySelector`／`closest`，`dashboard.js:498` 還用 `.lf-card--critical` 判斷告警卡。類別改名會讓別頁靜默失效，所以本輪類別名稱一個都不改。
- 樣式表都帶 `asp-append-version`（`_Styles.cshtml`），部署後瀏覽器不會拿到舊樣式配新腳本。
- 代價：`btn-outline-secondary` 這類名稱會與外觀不符（名稱說外框，實際是髮絲邊）。本輪接受，並在 `DESIGN-SYSTEM.md` 寫明「變體名稱是角色，不是外觀」。

### 設計原則的落點（不過度設計為前提）

- **單一對應點**：「哪個變體長什麼樣」只寫在樣式表一處——按鈕在 `base.css`，標記在 `components.css`。頁面與出口函式只說角色，不描述外觀。
- **標記的形式由既有的變體類別決定**，不新增「種類」參數、不改 73 處呼叫端。唯一的例外（「重大」旗標）在它唯一的出口 `elevatesBadge()` 加一個修飾類別。
- **分段控制是一條樣式規則**，不是新元件；`.active` 與 `aria-pressed` 兩種既有寫法都吃同一條規則。
- **改既有 token 的值優先於新增 token**。同一個意思不並存兩個 token。
- **不新增抽象**：不做新的 JS 元件、不做新的設定、不做主題切換機制。
- **守門分兩種**：靜態就能判定的（token 取值、禁用的寫法）寫成 C# 守門測試，CI 會跑；需要渲染才能判定的（對比、行數、列高）寫成常駐量測情境，每批與收尾時執行。

## 批次 B：token 與骨架

### 現況與核對結果

- 面板：白底、1px `--lf-border`（`#e2e8f0`）、`--lf-shadow-xs`；頁底 `--lf-gray-50`。全站所有內容都裝在同一種卡片裡。
- `--lf-shadow-lg` 是單層 `0 14px 40px` 18%。
- 下拉選單沒有陰影：`base.css:455` 設了 `--bs-dropdown-box-shadow`，但 Bootstrap 5.3.8 沒有任何規則引用它，計算值是 `none`。
- 設定提示是 `layout.js:568`、`:670` 產生的 `alert alert-info`，Bootstrap 預設的青色，每一頁頂端都有。
- 提示框 `alert-*` 共 44 處（warning 16、secondary 10、info 8、danger 5、light 3、success 2），另有 `lf-callout-warning` 1 處。
- 頂列標題 `lf-topbar__title`（`layout.css:377`）1.2rem／600，卡片標題 1rem／600。`PageHeaderUiTests` 守門「topbar 是唯一標題」。
- 字級切換是頂列右側的 `btn-group`（`layout.js:349-368`，`#lf-font-scale`），`dashboard-reveal` 行為測試與 `ui-shots.mjs` 會用到。
- 側欄選中項是整塊 `--lf-primary`；登出是全寬 `outline-light` 按鈕。
- 第 70 輪的報表「大螢幕」模式把內容綁在一屏內（`ReportsWallLayoutUiTests`、情境「大螢幕-報表」），對卡片的內距與高度敏感。
- 品牌設定只有名稱、副標、圖示（`settings.js:1105-1122`），沒有可設定的顏色，不影響 token。

### 定案

- **底色階梯**三階：頁底、面板、凹槽（表頭、分段控制的軌道、輸入框尾區）。面板不再用實線邊框，改成一圈由文字色推出的細環加極淡的陰影，並保留透明邊框（共同契約 6）。
- **細線**兩級（一般、較強），由文字色的透明度推出；做法是改 `--lf-border`／`--lf-border-strong` 的值，不另開 token。
- **陰影**只給浮在內容上方的東西；下拉選單的陰影要真的套上。
- **頁面標題留在頂列**並放大。
- **設定提示**改為中性底的一行：品牌藍的進度細條、說明文字、主要動作、安靜的「不再顯示」。它仍然要比一般內容醒目——未完成設定是需要處理的事。
- **側欄**底色加深；選中項改為淡底加左側細條；使用者資訊與登出收在底部一列。**登出保留文字「登出」，不能只剩圖示**。
- **字級切換**功能與位置不變，外觀跟著批次 C 的分段控制。
- **提示框**只改樣式：`info`／`secondary`／`light` 統一成中性底的說明框；`warning`／`danger`／`success` 與 `lf-callout-warning` 保留語意色但改用淡底與細環。四種語意在灰階下仍要分得出（靠既有的圖示或文字，不新增標記）。

不選的方案：把標題移進內容區；把字級切換收成彈出選單；另開一組新的邊線 token。

- 分段切換都用 `btn-group`（16 處）／`btn-group-sm`（13 處），子按鈕變體不同，畫面上有四種長相。按下狀態有 `.active`（38 處）與 `aria-pressed`（13 處）兩種寫法。`layout.css`、`pages.css` 已經在用 `:has()`（共 11 處），可以沿用。
- 篩選膠囊 `lf-chip`（`components.css:811` 起）選中時是實心 `--lf-primary`。
- 焦點環 `--lf-focus-ring` 是 `0 0 0 .2rem rgba(30,64,175,.22)`，實測對白底 1.46:1、對側欄底 1.13:1。
- `.btn` 的 `transition` 沒有列 `color`。

### 定案

- **五種變體是角色，外觀重新定義**（類別名不變）：
  - `primary`、`danger`：實心，不變。
  - `outline-secondary`（一般次要動作）：面板色底、髮絲細環、文字色；滑過出現淡底。
  - `outline-primary`（列內重複動作）：無框、品牌色文字；滑過出現品牌淡底。
  - `outline-danger`（危險動作入口）：無框、危險色文字；滑過出現危險淡底。
  - 表格列內的 `outline-secondary` 小按鈕一律無框，但必須帶圖示（共同契約 5）；沒有圖示的維持髮絲細環。
  - 深色側欄上的 `outline-light` 維持可辨識。
- **分段控制全站一種**：`btn-group` 是一條凹槽，按下的選項是浮起的面板色，並且**字重加粗**（不只靠底色區分）。`.active` 與 `aria-pressed="true"` 兩種寫法都生效。
- 「什麼算切換用途的 `btn-group`」：子按鈕帶有按下狀態的機制（有任一子按鈕具 `aria-pressed` 屬性，或該群組在腳本裡被切換 `.active`）。沒有按下機制的群組（並排的獨立動作）不套用。可複選且目前全部沒選中的群組仍要是凹槽外觀。
- **篩選膠囊**選中改為品牌淡底、品牌色文字、細環，並加粗字重。
- **焦點環**改為實線外框加偏移；淺色內容區與深色側欄各用一個顏色。
- **停用狀態**要看得出是停用：除了變淡，游標與底色也要不同。
- 危險動作的確認鈕（`danger` 實心）外觀不變，確認對話框裡「取消」與「確認」的主次要比現在更清楚，不能更模糊。

不選的方案：新增「ghost」變體並逐一改呼叫端。

## 批次 D：標記形式與顏色訊號

### 現況與核對結果

- 徽章出口在 `format.js`：`statusBadge(text, variant)`（:243）是基礎，`severityBadge`（:268）、`handlingBadge`（:275）、`elevatesBadge`（:101，固定 `'重大', 'danger'`）都呼叫它；`riskBadge`（:259）用 `lf-badge--high／--mid／--low`。樣式變體集中在 `components.css:452-479`。
- `statusBadge` 同時被用來表示狀態（啟用、成功）與歸屬（群組授權），只靠函式名分不出種類。
- 19 個頁面模組直接寫 `lf-badge`（59 處），4 個 `.cshtml` 另有 14 處。
- KPI 數字色由 `components.css:261-263` 的 `lf-stat__value--danger／--warning／--secondary` 決定。儀表板的中風險日、未處理問題、待派工、權限異動待確認都是 `warning` 橘色（`dashboard.js:277`、`:310`、`:326`、`:375`）。
- 告警卡的判定看建卡時的 `variant === 'danger'`（`dashboard.js:411`），不看樣式類別。
- 卡片色條 `lf-card--critical／--warning／--ok`（`components.css:427-437`），呼叫端 `dashboard.js:244`、`:455-456`、`record-detail.js:476-477`；`dashboard.js:498` 以 `.lf-card--critical` 判斷告警類別。
- 風險月曆 `lf-calendar__cell[data-risk]`（`pages.css:449` 起）高、中、低三級都是飽和色。

### 定案

> **實作中修訂（2026-11-12，依全站徽章盤點）**：原定「變體決定種類」不成立——盤點 177 處後，除 `success` 與風險三級外，每個變體都同時被用在兩種以上的資訊（例：`warning` 同時是「失敗」「嚴重度高」「未分組」「新」；`neutral` 同時是「已結案」「嚴重度低」「來源」）。改為「**變體只決定顏色，形狀由是不是層級決定**」，層級的判斷放在層級的出口函式，呼叫端仍然不動。

- **一般標記（所有變體）＝圓點加文字**：無底色、無框，前方一顆變體色的圓點，文字維持文字色。語意色變體（`success`／`warning`／`danger`／`info`／`primary`）是語意色圓點；中性變體（`neutral`／`secondary`／`light`／`dark`）是灰色圓點。圓點以邊框實作（列印不會因「不印背景色」而消失），不新增標記節點。
- **層級（嚴重度、風險等級）＝色點加文字，與一般標記同形但只出現在層級欄**：由層級的出口函式 `severityBadge()`、`severityCountBadge()`、`riskBadge()` 加上層級修飾類別；只有最高一級保留淡底（風險「高」、問題「重大」）。
- **「重大」旗標**：`elevatesBadge()` 加修飾類別，保留淡底。
- **例外：可移除的條件標籤**（內含按鈕的 `lf-badge`，例如問題查詢已選主機、篩選條件標籤、詢問 AI 的焦點問題）維持標籤外觀，改為細框；它們是可操作的元件，不是資訊標記。以 `:has(> button)` 判定，不改標記。
- 新增的類別只有層級修飾類別與「重大」修飾類別兩個，都只出現在 `format.js` 的出口函式與樣式表。
- 舊的 Bootstrap 寫法（`badge bg-*`／`text-bg-*`，JS 約 16 處、PRTG 維護頁約 10 處）不在本輪範圍，記進 BACKLOG。
- 盤點同時發現「同一件事用不同變體」（啟用／停用在規則頁是 `success`／`neutral`、其他頁是 `success`／`secondary`；已抑制在兩頁分別是 `secondary` 與 `dark`）。圓點形式下中性變體同為灰點，視覺已一致，不另外改呼叫端。
- **KPI 數字**：預設文字色；只有 `danger` 上色；`secondary`（零或無事）淡化。`warning` 的數字改為文字色，但卡片標籤旁要有一顆警示色圓點——**沒有副標的卡也看得出它是警示**。告警卡的判定邏輯不變。
- **卡片色條**移除，類別保留。「最嚴重的最醒目」（§8.2 原則 1）改由卡片內的層級標記與數字色表達。
- **風險月曆**：只有高風險用實色；中風險淡底；低風險接近中性；無資料是空框。**中風險另有一個不靠顏色的線索**（例如格內底部的短線，暫定），因為淡琥珀與中性灰在灰階下幾乎一樣。每格保留日期數字，圖例與格子用同一套樣式。

「有底色的標記」的定義：計算後背景不是透明、也不等於所在儲存格背景的行內標記元素。圓點不算。

不選的方案：為 `statusBadge` 新增「種類」參數並改全部呼叫端（要動 73 處以上；以變體決定形式就能涵蓋，例外只有一個）。

## 批次 F：表格密度

### 現況與核對結果

1280 寬實測（UI 資料集）：

- 稽核紀錄：時間折成 3 行，帳號折成 3～4 行，每列約 112px。
- 使用者：帳號逐段折行，顯示名稱最長折成 9 行，每列 85～280px。
- 規則維護：規則代號折 2～3 行，每列約 205px（其中一部分來自直排的列內按鈕）。

- `DESIGN-SYSTEM.md` §8.1 的 `lf-text-data` 已規定「不在字中斷行」；`CLAUDE.md` 明文禁止讓它用 `overflow-wrap: anywhere`。

### 定案

- **識別值不在字中斷行**：帳號、主機名、規則代號、IP、Sentinel 名稱、連線位址。極長的值單行省略並保留完整文字。
- **日期時間一行顯示，內容不變**（完整的年月日與時分）。稽核與權限異動是查核用途，不省略年份。
- **會折行的只有成段文字**。
- 欄寬以內容決定：識別值欄依內容、成段文字欄拿剩餘寬度。
- **不斷行之後表格變寬的後果要管住**：1280 以上不得因此出現局部水平捲動；768～992 寬若需要捲動，既有的「可左右捲動」提示必須出現，且第一欄（主要識別）在不捲動時看得到。375 寬維持既有做法。
- 人名與帳號的顯示字串格式本輪不改，只確保不被逐段拆成三行以上。

不選的方案：省略同年的年份（查核頁面不該有模糊的時間；靠欄寬就能做到一行）；把人名與帳號改成上下兩行（會動到全站名稱顯示規則，留給第 72 輪）。
