# 第 81 輪維運操作流程逐步評估

> 用途：以維運人員的角度，把每個日常與偶發的操作流程逐步走一遍，每一步停下來想「這步要不要存在、能不能更直接、遇到各種狀況會怎樣」，記錄成後續規劃可直接取用的材料。
> 搭配：`docs/FEEDBACK-81-PLAN.md`（發現與修正批次）、`docs/FEEDBACK-81-TEST-PLAN.md`（測試項目與執行紀錄）。
> 逐流程紀錄：`docs/feedback-81-flows/`（每個流程一份）。本檔只放格式、清單、對照與總表。

## 1. 怎麼讀、怎麼用

- **規劃時先看第 5 節「改善機會總表」**：每列一個改善點，已依「頻率 × 可省步數 × 嚴重度」排序，附依據與對應的既有發現。
- **要看某個改善點的來龍去脈**，依「流程-步驟」編號（例 `F02-3`）開對應的流程檔。
- **既有發現只引用編號**（H1、W2…，定義在 PLAN）；本輪新發現的編號是 `F流程-步驟`，不另起一套。

## 2. 每個流程檔的格式

```
# Fnn 流程名稱
- 角色／目標：維運人員想完成的事（一句話）
- 頻率：每天 N 次／每週／偶發；資料條件（D1、D2）
- 對應測試項目：R1、P06、L5…；既有發現：H1、W2…
- 現行步數：N 步（點擊＋輸入，不含捲動）→ 目標步數：M 步

## 現行步驟
| # | 畫面 | 動作 | 步數 |

## 逐步思考
### Fnn-k 動作名稱
- 目的：這步在幫使用者完成什麼
- 需要知道：使用者此刻做決定需要的資訊
- 畫面有給嗎：有／部分／沒有（缺什麼）
- 情境（實測或讀碼，未測的寫「未測」）：
  量大｜量零｜權限邊界｜他人同時改｜失敗中斷｜重新整理或返回｜從連結或通知進來｜手機
- 判斷：保留／省略／合併／預設／自動／就地／補資訊／防錯（可多選）
- 建議：一句話；必要時附畫面示意
- 依據：程式位置或實測數據；對應既有發現

## 目標流程
| # | 動作 | 與現行的差異 |
- 依賴的改動；暫不建議的做法與理由
```

### 判斷用詞

| 用詞 | 意思 |
|---|---|
| 保留 | 必要，且已是最直接的做法 |
| 省略 | 這步可以不存在（系統已知答案，或是前一步的重複） |
| 合併 | 與前後步驟併成一步 |
| 預設 | 給最可能的值，使用者只在例外時改 |
| 自動 | 系統代做，事後告知 |
| 就地 | 不用跳頁或開新視窗就能完成 |
| 補資訊 | 使用者此刻要做決定，畫面缺必要資訊 |
| 防錯 | 容易做錯或後果大，要擋、要預覽或要能復原 |

### 情境清單（每一步都要過一次）

| 代號 | 情境 | 要想的問題 |
|---|---|---|
| 量大 | 數百台、數十張單、數千列 | 還找得到嗎？要逐筆做嗎？會慢嗎？ |
| 量零 | 空清單、沒權限的範圍、剛上線 | 空狀態說明了原因與下一步嗎？ |
| 權限 | 唯讀角色、受限範圍、主機負責人 | 看得到卻做不到？做得到卻不該做？ |
| 併發 | 別人同時改、夜間派工同時跑 | 會蓋掉別人？畫面會過期？ |
| 失敗 | 送出失敗、逾時、外部系統不通 | 輸入會遺失嗎？能重試嗎？ |
| 返回 | 重新整理、上一頁、離開再回來 | 篩選、勾選、草稿還在嗎？ |
| 直達 | 從通知信、徽章、別頁連結進來 | 落點對嗎？脈絡帶到了嗎？ |
| 手機 | 375 寬 | 主要動作做得到嗎？ |

## 6. 跨流程的共同模式

走完 23 個流程後，同一類問題反覆出現。規劃時以這七條為原則，比逐項修更有效：

1. **按鈕叫什麼就做什麼。** 三個「回覆」有兩個不回覆（F02-1）；「立即派工」是全部派（F12-3）；「未回報主機」卡點了沒權限（D4）。看得到的動作就要做得到、做的就是字面上的事。
2. **預設值要是最可能的答案，不是現況。** 回覆預設「處理中」造成靜默誤回覆（F02-2）；期限預設空白讓逾期失效（W1）；觀察期沒有預設（F03-4）；負責人的落點是空頁（F10-1）。
3. **系統已經算出來的，就要顯示在做決定的地方。** 復發只在信裡（W2b）；候選人的可見範圍只在改派、不在交辦（F13-1）；處置參考只在風險日、不在交辦單（F06-1）；派不出去的原因有了、處理點沒有（F12-2）。
4. **以「單」為主的畫面缺少「主機」與「問題」兩個橫切面。** 主機詳情沒有處理資訊（F05-1）；交辦單看不到同問題的其他單與規則（F15-2、F19-1）；六種「不顯示」設定散在四處（F16-4）。
5. **量大時「逐筆」就是不可用。** 換頁清勾選、沒有搜尋、沒有「其餘」（F03）；逐張改派（F14-3）；負責人逐台逐日（O1）；統一標記超過上限要手動分次（F16-3）。每個清單都要問：300 列時怎麼辦。
6. **會靜默失效的設定要有就緒檢查。** 未分組、無授權、無派工池、開關未開、窗口為空、沒有 email——每一種都是「看起來正常、實際不動」，目前要等隔天或永遠不會發現（F23-2）。
7. **重複發生的事，第二次起系統要幫忙。** 復發每天重回（F04）；觀察到期要手動收尾（F08-1）；處理人請假後暫停接單要記得解除（F14-5）；反覆復發沒有人提醒管理員（F04-3）。
