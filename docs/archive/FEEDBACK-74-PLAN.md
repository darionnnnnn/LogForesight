## 核心原則

- 同一頁只用一條主分欄線：元素要嘛對齊這條線，要嘛占滿整列。
- 詳情頁滿版、清單頁滿版，都不加內容最大寬度（`ContentWidthGuardUiTests` 守住只有設定、初始設定限寬）。
- 不放大字（第 72 輪定案）。
- 變體名稱是角色：外觀不對時先改「這個位置用的角色」，不替角色加第二種外觀。
- 不過度設計：同一結構三個以上頁面才抽進 `core/`；本輪新做的東西只有一個使用端時留在頁面模組。

## 共同規則（每一批都適用，抄規格時逐條帶入）

1. **斷言先行**：每一條的斷言先寫好，在未修正的程式上跑出失敗訊息並記進執行紀錄，才開始改；修完轉綠。斷言寫不出失敗的，先修斷言。
2. **邊界兩側**：有門檻或條件的契約，斷言兩側各一例；主代理每批至少親做一個突變（把修正拿掉，確認轉紅）。
3. **改到的頁面跑該頁全部既有情境**；共用元件或共用類別的改動，當批加跑 375 與 2560 兩格，以及 375／1280 的小、大字級。
4. **改 markup 類別名或按鈕文字前**，grep 全前端的 `querySelector`／`closest`、`ui-scenarios.json` 的選擇器、測試專案被斷言的字串。
5. **每個被改外觀的選擇器**，grep 四層樣式裡同一選擇器或同一元素的舊規則（media query、hover、列印）。例外寫成排除（`:not()`），不事後覆寫回預設值。
6. 定向測試篩選：前端段落至少含 `UiTests|JsModuleImport|BehaviorTests|ApiTimeout`；新增或改 `*.behavior.mjs` 加 `NodeRuntimeTests` 並在 C# `InlineData` 登錄，頁面新增匯入的共用函式在替身補一份；改現行文件加 `DocNarrativeGuardTests`；改說明書加 `HelpContentServiceTests|HelpWritingGuide`。
7. 量測站台執行中不跑 `dotnet test`；量測結束清掉命令列含 `--headless` 的 `msedge`。
8. commit 以測試結果為條件；突變還原只用檔案備份並更新時間戳，不用 `git checkout`。

## 批次 A：處理面板缺陷

### 現況與核對結果

- **A-1 勾選沒有跟著篩選修剪**：`record-detail.js` 的勾選集合只在整頁載入時清空。嚴重度鈕與顯示範圍變更都只重繪清單。勾 3 個再把篩選切到只剩 1 個可見，面板仍寫「已勾選 3 個」，送出包含看不到的 2 個。
- **A-2 暫存不分模式**：`handling-panel.js` 的表單暫存日層級與批次共用。污染路徑：本機有草稿時，編輯器自動還原會派送 `input` 事件 → 表單的監聽把「日層級推導出的預選狀態」存進暫存 → 勾選問題進批次模式時取用暫存的狀態，批次被預選。反向同理。同一條路徑還有一個變體：指派後面板重載，推導狀態已變，暫存裡卻是舊的推導狀態。
- **A-3「AI 整理」寫進已卸下的欄位**：`note-editor.js` 的整理按鈕在回應到達時只檢查請求序號。等待期間勾選變動會重建表單，回應寫進舊欄位與本機草稿。

### 定案

- A-1：清單重繪後，不在目前可見清單內的勾選一律取消。修剪掛在「重點問題清單重繪」這一個出口，不在各個觸發點各寫一次。有勾選被取消時，面板顯示一行提示「已取消 N 個不在目前清單的勾選」，下一次勾選變動時清掉。
- A-2：
  - 暫存記錄模式（日層級／批次）。模式不同時，狀態、預計完成日、觀察天數、「不再提醒」不沿用。
  - 狀態只有在使用者親自點過膠囊時才進暫存；沒點過就每次依當下模式取初值（日層級＝推導狀態，批次＝不預選）。這一條同時解掉「自動還原寫入預選」與「重載後預選過期」，不必分辨事件來源。
  - 使用者打的說明文字跨模式保留。從批次回到日層級且說明非空時，表單上方顯示一行「目前沒有勾選問題，儲存會套用到這一天的整體狀態」；批次模式沿用既有的「已勾選 N 個問題…」提示。
  - 本機草稿鍵維持一個、不加模式後綴：草稿只存說明文字，而說明文字本來就跨模式保留，分鍵反而會把同一段文字拆成兩份。（BACKLOG 原寫「鍵加模式後綴」，因定案改為保留文字而不採用。）
- A-3：回應到達時欄位已不在文件上就整個丟棄——不寫欄位、不寫草稿、不顯示訊息。

### 驗收

全部完成並驗證，逐條結果見文末「執行紀錄」。
- 受影響測試：`record-detail-rail.behavior.mjs`、`note-editor.behavior.mjs`、`NoteEditorUiTests`、`RecordDetailRailBehaviorTests`。

## 批次 B：卡片滑過變色只限可點的卡片

### 現況與核對結果

- 樣式有一條全卡滑過規則，所有卡片滑過都換成淡藍底。
- 可點的卡片只有兩處：儀表板風險類型格線內的卡（格線自己有一組只給滑鼠裝置的淺灰底規則，優先權較高，實際顯示的是淺灰）、主機頁的卡片按鈕（目前吃到全卡規則的淡藍底）。KPI 卡是獨立類別，不受影響。
- 另有一條「可點卡滑過加陰影與邊框色」的規則，與 DESIGN-SYSTEM「可點的卡滑過只變底色、陰影只給浮在內容上方的東西」不一致；格線內已被覆寫掉，實際沒有生效的使用端。
- `FrontendConsistencyUiTests` 有一條 regex 鎖住上面那條陰影規則的選擇器寫法。
- 第 73 輪加在「建議處置」的左側指示條保留。

### 定案

- 刪掉全卡滑過規則。
- 可點卡片的滑過只有一種：換底色（沿用格線卡現用的淺灰），只給滑鼠裝置；陰影與邊框色那條一併移除（N-6，順手對齊設計系統，同一處樣式）。
- 鍵盤焦點環不動。

### 驗收

全部完成並驗證，逐條結果見文末「執行紀錄」。

## 批次 C：表格欄寬規則與格線

### 現況與核對結果

- 共用表格元件的欄位定義可帶類別名，沒有欄寬選項；多數表格讓瀏覽器自動分配寬度，多餘寬度均攤到每一欄。
- **C-1 群組與授權**：「角色群組」「部門群組」兩張表各自算欄寬，1920 下「角色」欄左緣差約 80px。
- **C-2 風險日詳情各類別表**（N-2）：2K 下「儲存裝置」表的「趨勢」欄左緣約在 1413px，「硬體」表約在 1275px。
- **C-3 使用者詳情「可見主機」表**：前四欄擠在左邊，「可見來源」在最右，中間空約 1300px。
- **C-4 主機詳情「重點問題」表**（N-1）：2K 下第一欄吃掉幾乎全部寬度，「分類」折成兩行，「出現天數」之後的欄被推到可視範圍外。根因未定位。
- **C-5 規則維護「類別」欄**：1280 下「儲存裝置」折成兩行。

### 定案

表格欄寬規則（寫進 DESIGN-SYSTEM，用共用類別實作，不改共用表格元件的介面）：

- 短值欄（日期、數字、狀態、分類、嚴重度）不在字中斷行、寬度依內容。
- 每張表指定一個「吸收欄」拿走多餘寬度，通常是名稱或說明欄；吸收欄內容過長時照既有的截斷或換行規則。
- 同一張卡片內結構相同的多張表，短值欄給相同的固定寬度，欄位起點才會一致。

各表套用：C-1 兩表共用欄寬（不合併成一張，分區標題與說明要保留）；C-2 類別表同理；C-3 吸收欄是「主機」，其餘靠左緊排；C-4 先用探針定位根因再套規則；C-5 類別欄列為短值欄。

### 驗收

全部完成並驗證，逐條結果見文末「執行紀錄」。

## 批次 E：版面零件

### 現況與核對結果

- **E-1 揭露鈕孤立**：1920 下儀表板「顯示其餘 1 類」獨自靠右占一列。
- **E-2 捲動提示**：「← 可左右捲動」是浮在表格右下角的文字，由共用表格元件依是否可捲動切換類別。
- **E-3 排程作業三張狀態卡**：三卡等高、按鈕貼卡底，2K 下「取數執行」卡的內容與按鈕之間空約 190px。
- **E-4 狀態卡鍵值列**：標籤與值兩端對齊，2K 下短值與標籤相距最多 600px 以上；1920 以下「已對應主機 N 台、未對應 M 台」會折行。
- **E-5 KPI 單組沒填滿**：使用者詳情、處理人詳情四張卡在 2K 只占左側約三成。
- **E-6 主機詳情月曆**：每個月固定 210px，2K 下只占左側五分之一。
- **E-7 卡片外的說明文字與單一控制項**：規則維護頁首只有一個說明圖示獨占一列（截圖確認）；問題負責與靜音頁首說明、權限異動檢核說明、資料匯入的編碼說明卡、NetIQ 維護單按鈕列、主機「全選符合目前篩選的主機」只核對了標記。
- **E-8 儀表板頂部**：期間切換、更新時間、日期範圍在同一個不換行的列（375 由批次 0 補量）。

### 定案

- E-1 揭露鈕移進所屬卡片的標頭列右側；共用的揭露元件一處改，所有使用端跟著動。
- E-2 捲動提示改成表格右緣的淡出陰影，不占版面；文字提示保留給輔助技術（視覺上隱藏）。有固定末欄的表格，陰影畫在固定欄的左側（既有的那條）。列印不顯示。
- E-3 按鈕跟在內容後面；三卡仍等高，空白留在卡片最下方。
- E-4 鍵值列改成標籤固定寬、值緊跟其後靠左，長值自然換行。
- E-5 KPI 只有一組時卡片填滿整列。
- E-6 月份格隨可用寬度放大，上限為現行的 1.5 倍；到上限後右側留白（取捨見文末）。
- E-7 說明文字進頁首副標或所屬卡片；單一控制項併進相鄰工具列或卡片標頭。「單一控制項的卡片」指卡片內只有一個可操作元素且沒有其他內容；說明圖示不算內容。
- E-8 頂部列允許換行，換行後各自成行、靠左。

## 批次 F：問題查詢列內動作與固定末欄

### 現況與核對結果

### 定案

- 列上的動作依固定優先序排：回覆處理狀態 → 交辦 → 統一標記 → 靜音。
