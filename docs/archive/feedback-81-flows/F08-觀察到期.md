# F08 觀察期到期接手

- 角色／目標：之前設為「觀察中」的主機到期了，處理人確認沒再發生就結案，還在發生就繼續處理。
- 頻率：每週。
- 對應測試項目：L6；既有發現：H13、W1。
- 驗證方式：讀規格與程式（WEB-SPEC §9.3 觀察中、`IssueHandlingStatuses.IsObservationExpired`）；VM 無法撥時鐘，畫面行為**未實測**。

## 現行行為（讀碼）

| # | 事實 | 來源 |
|---|---|---|
| 1 | 觀察期內：該問題不進待辦，新日子自動繼承觀察狀態 | WEB-SPEC §9.3 |
| 2 | 到期：讀取時推導為「處理中且逾期」，從既有逾期通道現身；沒有背景作業、沒有通知 | 同上 |
| 3 | 我的交辦的「進行中」台數含觀察期內的主機 | H13 實測 |

## 逐步思考

### F08-1 知道哪些到期了
- 需要知道：哪幾台到期、觀察期間有沒有再發生。
- 畫面有給嗎：部分。到期後算進「逾期台數」，但自動派工的單平常沒有逾期（W1），所以這個數字實際上就是「觀察到期」——使用者不會這樣解讀。沒有「觀察到期」的專屬標示，也沒有「觀察期間再發生 N 次／沒再發生」。
- 判斷：補資訊、自動。
- 建議：
  1. 我的交辦標「觀察到期 N」（F01-3），成員表顯示「觀察期間再發生 N 天」。
  2. **觀察期間完全沒有再發生的主機，到期時提供一鍵「全部結案（沒再發生）」**，或在回覆時預先勾選「到期且未再發生就自動結案」。這是觀察的本意，卻要人手動收尾。
- 新發現 **F08-1**（觀察到期且未再發生可自動或一鍵結案）。

### F08-2 還在發生的
- 判斷：預設。
- 建議：回覆彈窗對「觀察到期且仍在發生」的主機預設建議「處理中＋預計完成日」或「請管理員評估」（同 F04-2）。

## 目標流程
