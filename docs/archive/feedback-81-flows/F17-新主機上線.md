# F17 新主機上線

- 角色／目標：新增一批主機後，確認它們有人看得到、會被分析、出事會派給對的人。
- 頻率：每月。
- 對應測試項目：P12、P14、P17；既有發現：A9、A10、F12-2。
- 驗證：主機頁批次動作實測（D1）；NetIQ 掃描匯入需真實 Sentinel，**未實測**（讀盤點）。
- 現行步數：匯入（精靈）＋設群組（篩未分組→全選→批次設定群組→套用 4 步）＋授權（群組已授權則 0）＋負責人（選填 4 步）。

## 逐步思考

### F17-1 主機怎麼進來
- 來源：NetIQ 掃描匯入精靈（可在步驟二指定各網段的主機群組、OS、分級）、批次貼上、單筆新增、取數時自動登錄。
- 情境：自動登錄的主機沒有群組 → 一般使用者看不到、不會被派工。主機頁頂端「未分組 N」卡有說明，儀表板沒有提示。
- 判斷：自動、補資訊。
- 建議：
  1. 自動登錄的主機依 IP 網段沿用同網段既有主機的群組作為建議（不自動套用），在「未分組」清單一鍵接受。
  2. 「未分組 N 台」進管理員的「需要你處理」（F11-1）。
- 新發現 **F17-1**。

### F17-2 設群組
- 實測：篩「未分組」→ 全選符合條件 → 批次設定群組（加入／取代）→ 套用。4 步，良好。
- 情境：防錯——「取代」模式沒有確認（盤點 A.3）；選錯會把大量主機移出原群組。
- 判斷：防錯。
- 建議：取代模式套用前顯示「N 台將離開原群組 X」。

### F17-3 確認會被派工
- 需要知道：這個主機群組有沒有授權給任何派工池群組。
- 畫面有給嗎：沒有就地提示；要到授權矩陣看，或等夜間派工派不出去才在待派頁看到。
- 判斷：補資訊。
- 建議：主機群組清單加一欄「可見的使用者群組／派工池」，為 0 時標警示；批次設定群組後若目標群組沒有任何派工池可見，當場提示。
- 新發現 **F17-3**（缺口要等到派不出去才發現）。

### F17-4 負責人
- 實測：批次指派負責人（加入／移除／取代）或 CSV。CSV 會自動建立不存在的帳號（M3）。
- 判斷：保留。
