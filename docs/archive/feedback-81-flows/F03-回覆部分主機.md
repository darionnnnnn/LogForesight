# F03 回覆部分主機（有好有觀察）

- 角色／目標：一張單裡，一部分主機修好了、其餘繼續觀察或處理中；各自回報。
- 頻率：每天數次（大單幾乎都不會一次全好）。
- 對應測試項目：R1、L5、V8；既有發現：H4、H5、H6、W3、H13。
- 現行步數：60 台的單、5 台已處理＋55 台觀察中 ≈ 12 步（兩輪勾選，第二輪跨兩頁要分兩次）→ 目標 6 步。

## 現行步驟

| # | 畫面 | 動作 | 步數 |
|---|---|---|---|
| 1 | 我的交辦或交辦單頁 | 展開列／進單 | 1 |
| 2 | 成員表 | 逐台勾選已修好的 5 台（要先在 50 筆／頁裡找到它們） | 5＋翻頁 |
| 3 | 成員表 | 回覆選取的主機 → 改狀態 → 送出 | 3 |
| 4 | 成員表 | 全選本頁剩餘（45 台）→ 回覆 → 觀察中＋觀察至 → 送出 | 4 |
| 5 | 成員表 | 換頁（勾選被清空）→ 全選（10 台）→ 回覆 → 觀察中 → 送出 | 5 |

## 逐步思考

### F03-1 找到要回覆的那幾台
- 目的：從數十到上百台裡挑出這次修好的。
- 需要知道：主機名、所在機房或群組、IP；每台目前狀態與上次回覆。
- 畫面有給嗎：部分。只有主機名、狀態、期限、期間；沒有搜尋、沒有群組／IP 欄、不能排序（H5）。同主機多列（復發）時分不出哪一列是現在的（W3、H6）。
- 情境：量大——115 台＝3 頁；處理人手上通常有一份「今天修了哪幾台」的清單，想**貼上主機名一次勾選**。返回——換頁清空勾選（H4）。
- 判斷：補資訊、就地。
- 建議：成員表加搜尋框（支援一次貼多個主機名，逗號或換行分隔，自動勾選命中的列）；加主機群組欄並可依它篩選；跨頁保留勾選並顯示「已選 N 台」。
- 依據：`work-order-detail.js:783`、`handler-detail.js:68`。新發現 **F03-1**（貼上主機清單勾選）。

### F03-2 對選取的主機下結論
- 同 F02-2、F02-3。

### F03-3 處理「剩下的全部」
- 目的：其餘主機一次設成觀察中。
- 畫面有給嗎：沒有「其餘全部」的概念，只能逐頁全選。
- 情境：量大——每多一頁多 4 步。
- 判斷：合併。
- 建議：回覆彈窗的對象提供三種：選取的 N 台／**未選取的其餘 M 台**／全部進行中；或在第一次送出後提示「其餘 55 台要一起設為…？」。這樣「5 台已處理＋其餘觀察中」是兩次送出、不必再勾選。
- 新發現 **F03-3**。

### F03-4 觀察中要填觀察至
- 目的：設定觀察期。
- 畫面有給嗎：有，日期欄；風險日面板有 3／7／14 日快捷鈕，回覆彈窗只有日期欄。
- 判斷：預設。
- 建議：回覆彈窗也給 3／7／14 日快捷並預設 7 日（規格本來就寫預設 7 天），少一次開日曆。
- 依據：`handling-panel.js:495` 有快捷、`issue-status-reply.js:81` 沒有。新發現 **F03-4**。

## 目標流程

| # | 動作 | 與現行的差異 |
|---|---|---|
| 1 | 列上按「回覆」→ 彈窗 | 同 F02 |
| 2 | 切「只回覆部分主機」→ 貼上主機名或搜尋勾選 | 不必翻頁找 |
| 3 | 點「已處理」→ 送出 | |
| 4 | 提示「其餘 55 台」→ 點「觀察中 7 日」→ 送出 | 不必再勾選、不必分頁 |

- 依賴：成員端點加主機名清單篩選（伺服器端）；回覆端點已支援 `caseIds`，「其餘」由前端帶「排除清單」或後端新增排除參數。
- 暫不建議：把成員表每頁改成 200——治標；找主機仍要用眼睛掃。
