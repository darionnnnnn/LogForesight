# F04 處理復發的問題

- 角色／目標：昨天回過「已處理」的主機今天又出現同一問題；處理人要知道這是復發，並選一個不會每天重來的做法。
- 頻率：每天。D2 模擬中 sshd 暴力嘗試 32 台天天一張新單；NETLOGON 一張單內同一台被回「已處理」8 次。
- 對應測試項目：L3、L4、V2；既有發現：W2、W2b、W3、W5、H13、N1。
- 現行步數：每天 F02 的 5～6 步重做一次，且不知道是復發 → 目標：第一次復發時多 1 步選對做法，之後 0 步。

## 現行步驟

| # | 畫面 | 動作 | 步數 |
|---|---|---|---|
| 1 | 我的交辦 | 看到一張「新」單（其實是昨天那批主機） | 0 |
| 2 | 交辦單頁 | 沒有任何復發提示；照 F02 回「已處理」 | 5～6 |
| 3 | 隔天 | 重複 1～2 | 每天 |

## 逐步思考

### F04-1 認出這是復發
- 目的：知道「我昨天才處理過」。
- 需要知道：哪幾台是復發、上次什麼時候回覆、回了什麼、之後又發生幾次。
- 畫面有給嗎：沒有。系統已算出復發台數（`DispatchDecision.Recurrence`），只寫進通知信（W2b）；單、成員表、我的交辦都沒有。主管報表「結案後再發生」看得到。
- 情境：量大——32 台全是復發時，一句「這 32 台昨天都回過已處理」就夠；部分復發時要逐台標。直達——從信進來的人知道、直接開站的人不知道。
- 判斷：補資訊。
- 建議：單頭顯示「其中 N 台是復發（上次回覆：日期、狀態、說明）」；成員表逐台標復發次數；我的交辦列上標「復發 N」（F01-3）。

### F04-2 選一個不會每天重來的做法
- 目的：停止無效的重複回覆。
- 需要知道：有哪些做法、各自後果。
- 畫面有給嗎：沒有。回覆彈窗的選項與第一次完全相同；處理人自然再選「已處理」。
- 各做法對復發的實際效果（讀規格與程式）：
  | 回覆 | 隔天再發生時 |
  |---|---|
  | 已處理 | 新案件、新單或掛回進行中單（每天重來） |
  | 觀察中（觀察至 D） | 同一案件延續，新日子自動繼承觀察；到期才回到待辦 |
  | 處理中＋預計完成日 | 同一案件延續，不會新開 |
  | 不處理／誤報／已知雜訊 | 這台這個問題永久不再派（W4 的風險） |
  | 上報 | 交給管理員（可調規則、靜音、抑制） |
- 判斷：預設、防錯。
- 建議：
  1. 回覆對象含復發主機時，彈窗頂端提示「這些主機 N 天內回過已處理又再發生」，並把建議選項排前面：**「還在處理（設預計完成日）」「觀察 7 日」「請管理員評估調整規則或靜音」**。
  2. 「請管理員評估」＝上報的一種，附固定原因碼（重複發生），讓管理員端（F15、F16）一眼分出。
  3. 同一台連續復發達 N 次時，系統自動在管理員的提醒區列出「反覆結案又復發的問題」，不等處理人上報。
- 依據：WEB-SPEC §9.4b「沒有重開」、§9.3 觀察中語意；W2、W5。新發現 **F04-2**（復發時的建議選項與原因碼）、**F04-3**（反覆復發自動進管理員提醒）。

### F04-3 單的形狀
- 目的：讓「同一批主機的同一件事」看起來是一件事。
- 畫面有給嗎：沒有。每天一張新單（結案後）或同一張單內同主機多列（未結案時，W3）。
- 判斷：合併（呈現層）。
- 建議：不改「沒有重開」的資料模型；呈現上把同處理人同問題近 N 天的單串成一條（單頭顯示「接續 #62、#64」），成員表同主機合併成一列。
- 暫不建議：結案後自動重開舊案件——牽動報表帳齡、再發生率與逐日列歸屬，風險大；先做呈現與建議。

## 目標流程

| # | 動作 | 與現行的差異 |
|---|---|---|
| 1 | 我的交辦看到「復發 32」標記 | 立刻知道不是新問題 |
| 2 | 回覆 → 彈窗提示復發並建議三個選項 → 選一個 → 送出 | 多 0 步，但選對做法 |
| 3 | 之後不再每天收到同一張單 | 省每天 5～6 步 |

- 依賴：復發資料進成員 DTO；回覆彈窗接收復發資訊；管理員提醒區新增一類。
