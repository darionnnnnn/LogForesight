# F23 第一次啟動

- 角色／目標：新站台從安裝到第一批資料、第一張交辦單，管理員照指示做完。
- 頻率：一次（每個站台）；但做錯的代價是「看起來沒資料、沒人被派工」。
- 對應測試項目：R8、P20；既有發現：A1b、F17-3、F18-2。
- 驗證：救援帳號登入頁與頁頂「初始設定 5/10 完成」實測（D1）；精靈各步驟**未實測**（讀盤點）。

## 現行步驟（讀盤點）

救援帳號登入 → 指派管理員 → 啟動精靈十步（儲存體、AD、管理員、部門群組、NetIQ 主機、授權、PRTG、郵件、AI、排程）→ 第一次取數。

## 逐步思考

### F23-1 知道現在在哪一步
- 畫面有給嗎：有。頁頂進度條「初始設定 5/10 完成——下一步：AD 驗證」、繼續設定、不再顯示；救援帳號首頁有清楚的說明卡。
- 判斷：保留。
- 情境：失敗——每個管理頁都呼叫設定狀態並等 AI 探測（A1b）；AI 還沒設定時不該探測。

### F23-2 步驟之間的相依
- 需要知道：哪些步驟沒做會導致「看起來沒事但其實不會動」。
- 會靜默失效的組合（由本輪發現歸納）：
  | 沒做的事 | 結果 | 目前在哪裡看得到 |
  |---|---|---|
  | 主機沒有群組 | 一般使用者看不到、不會派工 | 主機頁「未分組」卡 |
  | 主機群組沒授權給派工池 | 派不出去 | 隔天的待派頁 |
  | 沒有任何派工池群組 | 全部派不出去 | 待派頁原因碼；設定頁自動派工開關旁有警示（`Settings.cshtml:903`） |
  | 自動派工開關沒開 | 不派工 | 設定 › 郵件通知頁籤最下方（`Settings.cshtml:891`；與郵件無關，位置不直覺） |
  | AI 執行窗口為空 | AI 永不執行 | 排程作業（訊息矛盾，D1） |
  | 排程沒啟用 | 不取數 | 排程作業「排程未啟用」 |
  | 管理員沒有 email | 上報信沒有收件人 | 交辦總覽提醒區 |
  | 處理人沒有 email | 收不到派工通知 | 建單後 toast |
- 判斷：防錯、補資訊。
- 建議：初始設定增加「派工能不能動」的整體檢查：試跑一次派工（待派頁的試跑邏輯已有），列出上表每一項的狀態，全部通過才顯示「派工就緒」。之後常駐在系統健康頁。
- 新發現 **F23-2**（靜默失效組合的就緒檢查）、**F23-3**（自動派工開關放在郵件通知頁籤）。

### F23-3 第一次取數之後
- 需要知道：資料有沒有進來、為什麼儀表板是空的。
- 畫面有給嗎：新處理人的空狀態有說明；儀表板空資料的說明未實測。
- 建議：開工時以空資料庫實測儀表板、問題查詢、報表的空狀態文字。
