# F12 處理派不出去的問題

- 角色／目標：夜間派工有問題派不出去（沒有人看得到那些主機、派工池全暫停、嚴重度未達），管理員要補上缺口或手動派。
- 頻率：每天看、每週實際處理幾次。
- 對應測試項目：A3、A4、A5；既有發現：A3、A4、A5、A9、A10、N1。
- 現行步數（以「機房20 沒有人授權」為例）：待派頁看到原因 → 側欄群組與授權 → 授權矩陣頁籤 → 橫向捲動找群組 → 勾選 → 回交辦總覽 → 待派 → 立即派工 → 確認 ≈ 9 步 → 目標 3 步。

## 逐步思考

### F12-1 看懂為什麼派不出去
- 畫面有給嗎：有原因文字，但逐列重複、雜訊在前（A3、A4）。「嚴重度未達」的列不是「派不出去」而是「本來就不派」，混在同一張表。
- 判斷：補資訊（分組）。
- 建議：待派頁分三段：**可以派（N）**、**派不出去（N，依原因分組）**、**不會派（嚴重度未達／不再打擾，收合）**。

### F12-2 補授權
- 需要知道：這個主機群組該給哪個使用者群組。
- 畫面有給嗎：要離開待派頁到授權矩陣，矩陣本身難用（A9）且連點會遺失（A10）。
- 判斷：就地。
- 建議：「無人看得到的主機群組」旁直接給「授權給…」下拉（列出派工池群組），就地完成並寫稽核；完成後該段自動重算。
- 新發現 **F12-2**。

### F12-3 只派這一個問題
- 畫面有給嗎：沒有（A5）。只有整頁「立即派工」。
- 情境：防錯——管理員只想處理 sshd 這一項，按立即派工會把其他 7 個問題也派出去（含他還沒看過的）。確認框只寫會派工，沒有列出將建立幾張單、給誰。
- 判斷：就地、防錯。
- 建議：每列「派這個問題」（帶建議處理人，可改）；整頁立即派工的確認框列出預計張數與每人台數（待派頁已經算好）。
- 新發現 **F12-3**（立即派工的確認沒有摘要）。

### F12-4 派工池全暫停、沒有派工池
- 未實測（D2 沒有這個狀態）。讀規格：原因碼 `all_paused`、`no_pool`。
- 建議：同 F12-2，原因旁直接給處理點（到使用者頁的暫停接單、到群組的派工池開關）。
