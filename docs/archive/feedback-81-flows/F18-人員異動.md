# F18 新同仁上線、權限調整、離職

- 角色／目標：讓一個人能登入、看得到該看的主機、會（或不會）被派工；離職時收回並轉走工作。
- 頻率：每月。
- 對應測試項目：P13、P14、L12；既有發現：A9、A10、A12、L12、U1。
- 現行步數：新增使用者（新增→帳號→勾群組→儲存 4 步）；若需要新的可見範圍：新增部門群組＋授權矩陣；離職見 F14。

## 逐步思考

### F18-1 新增使用者
- 實測／盤點：單筆或多筆（最多 100，一行一個）；勾所屬群組；帳號已存在時單筆會直接更新並回「已新增」（BACKLOG 已記）。
- 需要知道：加進哪個群組＝得到什麼（角色能力、可見主機、是否進派工池）。
- 畫面有給嗎：部分。群組清單顯示「（User）」「（Admin．系統內建）」；看不到該群組可見幾台主機、是不是派工池。
- 判斷：補資訊。
- 建議：勾選群組時即時顯示結果摘要：「能力：處理、確認權限異動；可見主機 300 台；會被自動派工：是」。使用者詳情頁已經有這些數字，新增時也要有。
- 新發現 **F18-1**。

### F18-2 權限模型的理解成本
- 現況：角色掛在群組、可見範圍掛在「部門群組 × 主機群組」矩陣、派工池是群組旗標、主機負責人另一條路、交辦授與又一條路。五個概念決定「一個人看得到什麼、會不會被派工」。
- 情境：管理員想回答「為什麼小陳看不到這台」「為什麼這張單沒派給小陳」，要查五個地方。
- 判斷：補資訊。
- 建議：使用者詳情頁加「為什麼」查詢：輸入主機名 → 顯示看得到／看不到的原因鏈（哪個群組、哪條授權、是否負責人、是否交辦授與）。派工決策的原因已有資料（待派頁的原因碼）。
- 新發現 **F18-2**。

### F18-3 調整授權
- 實測：授權矩陣即時儲存、連點遺失（A10）、欄寬失控（A9）、沒有確認也沒有上一版（盤點 A.3）。
- 判斷：防錯。
- 建議：矩陣改成「編輯模式→檢視差異→儲存」；或以使用者群組為主的編輯頁（勾主機群組清單）。差異摘要寫出「將新增可見 100 台、移除 0 台」。

### F18-4 測試期與正式期
- 現況：Stub 模式免密碼；正式用 AD。新同仁第一次登入前帳號要先建立（或由負責人 CSV 自動建立）。
- 未實測：AD 帳號不存在於系統時的登入訊息。
- 建議：開工時確認「AD 驗證成功但系統沒有此帳號」的畫面訊息是否告訴使用者找誰。

## 目標流程
步數不變；改善在新增當下看得到結果、調授權有差異預覽、查得到「為什麼」。
