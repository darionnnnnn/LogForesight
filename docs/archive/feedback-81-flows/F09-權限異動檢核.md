# F09 權限異動檢核

- 角色／目標：確認偵測到的權限異動是不是授權操作。
- 頻率：每天（量取決於環境；D1 只有 5 筆，量大行為**未實測**）。
- 對應測試項目：P09；既有發現：BACKLOG「無效網段時列表換成空狀態」。
- 現行步數：單筆 3 步（點列→選授權／可疑→送出）；批次 4 步（全選符合條件→標記為授權→填說明→送出）。

## 逐步思考

### F09-1 找出要確認的
- 畫面有給嗎：有。預設「待確認」頁籤、類別與來源篩選、日期快捷、全選符合條件、依類別／依主機的批次摘要。批次上限 500，有略過清單。
- 判斷：保留。
- 情境：量大（未測）——例行同步彙總類別已獨立，可整類批次。權限——只列可見主機。

### F09-2 判斷是不是授權
- 需要知道：誰改的、改了誰、在哪台、對應的變更單或例行作業。
- 畫面有給嗎：部分。有操作者、目標、類別、高風險標記；無法解析時顯示「（未指定對象）偵測到權限異動，但無法解析細節」——使用者無從判斷，只能點「查看當日權限異動報告全文」。
- 判斷：補資訊。
- 建議：無法解析的列直接附原始事件摘要（或一鍵展開），不要讓人離開清單去翻報告。
- 新發現 **F09-2**。

### F09-3 確認後能不能更正
- 畫面有給嗎：已確認後 UI 不提供改標（盤點；後端是否允許未查）。
- 情境：誤操作——批次標成授權後發現其中一筆可疑，沒有更正入口。
- 判斷：防錯。
- 建議：已確認的列提供「更正」（留歷程）；批次送出前的摘要已經有，維持。
- 新發現 **F09-3**（待開工時查後端）。

## 目標流程
現行流程已接近最短；只補「無法解析的列就地看原文」與「更正」。
