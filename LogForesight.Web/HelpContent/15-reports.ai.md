# 報表（AI 參考指引）

## 頁面基本資訊與存取架構

- **頁面路徑**：`/reports`。
- **存取權限**：所有已登入使用者均可存取（`NAV_SECTIONS` 中 `requires: null`）。但 `isServerAdmin` 帳號因最小授權原則（僅具備系統維護與稽核權限，無業務資料檢視權限）隱藏此頁（`layout.js` 之 `BUSINESS_PAGES`）。
- **後端 API**：`GET /api/reports/summary?from={from}&to={to}&handlingScope={handlingScope}&compare={compare}`，對應服務為 `ReportService.GetSummary`。
- **版面閱讀順序**：由上而下、由左而右＝主管的五個問題——現在要不要擔心（第一排四格）→ 變好還是變壞（前期對比、風險趨勢）→ 風險集中在哪（主機排行、風險類型分布）→ 有沒有人在處理（處理進度、未結案風險日）→ 這些數字可不可信（資料完整度）。整頁在一屏內看完，視窗窄（≤ 991px）時單欄捲動。

## 工具列與篩選條件

工具列（`#report-toolbar`）只有一列：

1. **左側「目前條件」一行文字**：期間名稱（醒目）＋日期與比較基準（次要）。快捷期間寫「昨日／近 7 天／近 30 天／近 90 天」，手動改過日期寫「自訂期間」；日期寫成 `MM/DD–MM/DD`（跨年帶年份）；接「對比前一期」或「對比去年同期」；顯示範圍不是「全部」時再接「 · 僅未結案」等。
2. **期間快捷按鈕（`data-range="1|7|30|90"`）**：結束日期一律為「昨天」，避免當日尚未完成夜間分析導致最後一天必然無資料。點了立即查詢。
3. **「更多條件」（`filterDisclosure`）**：收合面板（`#report-filter-panel`），按鈕標籤後的數字＝已套用的條件數（自訂日期 1、比較模式非預設 1、顯示範圍非「全部」1；0 個時不寫數字）。進頁時已有套用中的條件（例如網址帶 `handlingScope`）預設展開。面板內容：
   - **起始日期（`#report-from`）與結束日期（`#report-to`）**：上限為當天。起訖天數（含頭尾）超過 366 天，前端以 Toast 提示「查詢區間不可超過 366 天，請縮小範圍」並中斷查詢；起日晚於迄日提示「起日不可晚於迄日，請調整日期範圍」。
   - **比較模式（`#report-compare`）**：`previous`（對比前一期）依區間長度向前推等長期間；`yoy`（對比去年同期）起訖各減 1 年。使用者未手動變更過比較模式時，區間 ≥ 180 天且保留天數 ≥ 365＋區間天數才自動選 `yoy`，否則 `previous`；保留天數尚未取得前一律 `previous`。去年同期超出保留期時選項加註「（超出保留期）」，仍可手動選。
   - **顯示範圍 chips（`#report-scope-chips`）**：單選，參數 `handlingScope`。`all` 為預設（網址不留參數）；`unresolved` 下鑽附加 `&statuses=open,in_progress`；`open` 附加 `&statuses=open`；`unassigned` 附加 `&unassigned=true`。點 chip 立即重新請求，載入成功才亮起。
   - **「套用」**：面板內唯一的主要按鈕（`btn-primary`），送出目前表單條件。
4. **「大螢幕」（`#btn-report-fullscreen`）**：視窗寬度 ≥ 992px 時顯示，按下進入大螢幕模式，說明見下方「大螢幕模式（戰情中心）」。
5. **「列印 / 存成 PDF」（`#btn-print-report`）**：執行 `window.print()`。列印時工具列（`.lf-no-print`）隱藏，頁首顯示列印標題 `#print-title`（格式：`LogForesight 風險報表 YYYY-MM-DD ～ YYYY-MM-DD（顯示範圍名稱）`）。

## 第一排四格（`#report-kpi`）

四格同一排，語意色只用在需要注意的狀態（上升、逾期、缺漏、落後），正常狀態是一般文字色。

1. **高風險日**（`kpi.highRiskDays`）：期間內綜合判定為高風險的主機日總數。副標為前期對比。下鑽：`/records?riskLevels=高&from=&to={scopeDrillParams}`。
2. **受影響主機**：值寫成「N / M 台」，N＝`kpi.affectedHosts`（期間內至少一天高或中風險的相異主機數，跨日去重），M＝`totalHosts`（可見且啟用的主機總數）。副標為前期對比。下鑽：`/records?riskLevels=高,中&from=&to={scopeDrillParams}`。
3. **未結案風險日**：值＝`handling.openCount + handling.inProgressCount`（高＋中風險日裡未處理加處理中）。`handling.overdueCount > 0` 時副標以風險狀態文字寫「逾期 N」，沒有逾期不寫逾期字樣。下鑽：`/records?statuses=open,in_progress&riskLevels=高,中&from=&to=`；顯示範圍為「未處理」時 `statuses=open`，「未指派」時另帶 `unassigned=true`。
4. **資料完整度**（`summary.coverage`，與顯示範圍無關，**不可下鑽**）：
   - `noData`（可見啟用主機數為 0，或期間內沒有任何日誌分析紀錄）→ 值「無資料」（次要灰）。
   - `missingHostDays > 0` → 值「缺 N 主機日」（警示色）。缺漏主機日＝應有日誌分析紀錄卻沒有紀錄的主機日（含整晚取數失敗、完全沒有紀錄的）加上既有缺口紀錄數。
   - `lagging`（`dataThrough` 早於 min(期間終點, 昨天)）→ 副標「資料至 MM/DD」（風險狀態文字）；沒有缺漏但落後時值仍是「完整」、卡片轉警示色。
   - 其餘 → 值「完整」，一般文字色。
5. **前期對比徽章（`comparisonBadge`）**：`percent = Math.round((current - previous) / previous * 100)`。語意反轉：告警數上升代表變壞，`delta > 0` 以風險狀態文字（紅）顯示「↑ {percent}%（前期 {previous}）」；`delta < 0` 以次要文字顯示「↓ {percent}%（前期 {previous}）」；持平顯示「與前期持平」。前期為 0 且當期為 0 顯示「與前期相同」；前期為 0 但當期大於 0 顯示紅色「↑ 前期為 0」。
6. **保留期警示**：`comparisonOutOfRetention` 為 true 時於第一排上方顯示「比較期間的資料已超過保留期，對比數字不具參考價值。」；`comparisonPartiallyOutOfRetention` 為 true 時顯示「比較期間有一部分早於保留期，那段的資料已被清除，對比數字會偏低。」（兩者互斥）。

## 圖表區

### 風險趨勢（`#trend-section`）
- **圖表類型**：逐日堆疊長條圖（Chart.js bar，x、y 皆 `stacked`），高風險（紅）在下、中風險（琥珀）在上。若系統設定未勾選顯示中風險日（`!visibleDayRisk.has('中')`），中風險那一組不畫。
- **資料來源**：`currentData.trend`（逐日資料，無資料日由後端補 0）。期間全為 0 顯示「此期間沒有資料」。期間很長時不另做彙總，座標軸 `autoSkip` 省略刻度。
- **下鑽**：點長條導向 `/records?riskLevels={高|中}&from={date}&to={date}`。
- **工具列（表格檢視）**：欄位為「日期」「高風險」「中風險」「錯誤數」。

### 處理進度（`#handling-section`，純 HTML）
- 第一條橫向堆疊條：已處理（`handling.resolvedCount`）、處理中（`inProgressCount`）、未處理（總數減前兩者，正常等於 `openCount`），三段相加＝`handling.totalCount`（期間內高＋中風險日）。條下方列出三個「標籤 數字」。
- 第二條：風險層級（高、中；中風險被顯示設定隱藏時只列高），數字取自趨勢資料的合計。
- 條本身 `role="img"`，`aria-label` 寫出各段數字；寬度以 `--lf-share`、顏色以 `--lf-swatch` 傳入。總數為 0 時顯示「此期間沒有風險日」且不畫條。
- **隱藏規則**：`handlingScope !== 'all'` 時整卡隱藏（母體已抽掉已處理，進度恆為 0% 或 100%），趨勢卡補滿該列。

### 主機排行與問題排行（`#host-section` / `#host-chart`）
- **視角切換器（`#rank-mode-toggle`）**：「主機」（`data-rank-mode="host"`）與「問題」（`issue`）。狀態存 localStorage 鍵 `lf.reports.rankMode`，預設 `host`。
- **主機排行**：水平堆疊長條圖，顯示 Top 10 主機的高風險日數（紅）與中風險日數（琥珀）。標籤有顯示名（`displayName`）時寫成「顯示名（主機名）」，沒有時只寫主機名；座標軸標籤過長時截斷，完整文字在提示與表格。超過 10 台時第 11 台起由後端合併為「其他 N 台」彙總長條（不可下鑽）。點個別主機導向 `/hosts/{hostId}`。有「其他」時顯示「檢視全部」（`#host-view-all`）導向 `/records?view=host&riskLevels=高,中&from=&to=`。表格欄位：「主機」「高風險日」「中風險日」「關聯訊號日」「最新狀況」。
- **問題排行**：水平長條圖，依優先度分數（`priorityScore`）由高至低，長度為事件總次數。受影響主機全部都已有結論的問題不列入，副標題寫「另有 N 個問題已有結論（未列入）」；靜音中的問題同樣不列入。超過 10 個時併成「其他 N 個問題」。點長條導向 `/records?view=issue&source=&eventId=&riskLevels=高,中,低&from=&to=`。副標題（`#host-rank-subtitle`）組合「共 N 個問題」＋（scope≠all）「；不受「顯示範圍」篩選影響」＋（`issueStatsPending`）「；統計整理中，數字可能不完整」＋已有結論或靜音筆數。
- 無資料：主機模式「此期間沒有風險主機」、問題模式「此期間沒有問題事件」。

### 風險類型分布（`#category-section` / `#category-chart`）
- **圖表類型**：水平堆疊長條圖，Y 軸為問題類別（儲存裝置、硬體、安全、服務、備份、設定、資源、其他），堆疊依嚴重度高、中、低。
- **標題列的「N 個問題」**（`#category-issue-total`）：N＝`kpi.totalIssues`（期間內去重的問題總數，含低風險日的問題，且排除靜音中的問題）。點了導向 `/records?riskLevels=高,中,低&from=&to={scopeDrillParams}`。
- **顯示範圍限制**：這張圖是後端 SQL 端跨主機跨日聚合的獨立投影，不受 `handlingScope` 影響；scope≠all 時副標題（`#category-subtitle`）寫「不受「顯示範圍」篩選影響」。
- **下鑽**：點長條的某個嚴重度區段導向 `/records?categories={category}&severity={severity}&riskLevels=高,中,低&from=&to=`。
- **表格欄位**：「類型」「高」「中」「低」「問題數」「期間累計」「主機數」。問題數為去重風險資訊筆數，高、中、低三者之和即為問題數。

## 大螢幕模式（戰情中心）

- **進入**：工具列「大螢幕」（`#btn-report-fullscreen`）在視窗寬度 ≥ 992px 時顯示；按下後網址加 `display=wall`（`replaceState`，保留其他參數）、套用模式並嘗試 `requestFullscreen()`（被拒絕或不支援時只略過，模式照樣生效）。網址直接帶 `?display=wall` 進頁時由伺服器端在 `<html>` 輸出 `lf-wall` 類別（只有報表頁會設 `ViewData["DisplayMode"]`，其他頁帶這個參數無效），側欄、頁首、提醒區在第一次繪製前就不顯示。適合大螢幕電腦開機自動開啟。
- **寬度不足**：< 992px 不提供：按鈕不顯示、樣式不套用、不啟動自動更新；視窗放寬穿越 992px 時即時生效。
- **版面**：隱藏側欄、頁首、提醒區、工具列、圖卡「表格」切換與「檢視全部」；數字與圖表不可點；唯一的互動元素是離開鈕。標頭列（`#wall-header`）有產品名稱、目前條件（與工具列同一個 `periodSummary()`）與「最後更新 HH:mm」，是大螢幕上唯一的說明文字。首次載入失敗的錯誤狀態沒有「重試」鈕，靠自動更新下一輪重試。
- **離開**：Esc；滑鼠移動時右上角出現「離開大螢幕」（3 秒沒動作淡出、鍵盤聚焦時一直可見）；由按鈕進入且已開瀏覽器全螢幕時，使用者用瀏覽器退出全螢幕也一併離開（由網址直接進入的不受影響）。離開時移除網址的 `display`、移除 `<html>` 類別、停止自動更新並以一般模式重繪。
- **字級**：隨視窗高度等比放大（以 1080px 高為基準、下限 1，不受小／中／大字級偏好影響）：1920×1080 時第一排數字約 64px，3840×2160 時約 128px；圖表文字一併放大。
- **自動更新**：上一次載入完成（成功或失敗）後 15 分鐘才排下一次（暫定常數 `WALL_REFRESH_MS`），同一時間只有一個請求。快捷期間每次以目前選的天數重算起訖（跨午夜自然前進一天），自訂日期固定不動。分頁不可見時不發請求，回到可見時若距上次完成已超過 15 分鐘就立刻更新一次。更新時不顯示骨架列、不做進場動畫。
- **更新失敗**：畫面保留舊資料，標頭列以風險狀態文字寫「更新失敗，目前是 HH:mm 的資料」，下一輪照常再試，成功後訊息消失。大螢幕模式下 API 錯誤不跳 toast。首次載入就失敗時顯示一般的全頁錯誤狀態，下一輪照常重試。
- **登入到期**：沿用 JWT 有效時間（`Jwt:ExpireHours`，預設 8 小時，全站生效，站台管理者可調）。到期後 API 回 401，導回登入頁並記住帶 `display=wall` 的原網址，登入後回到大螢幕；沒有長效登入或展示專用帳號。
- **列印**：不受大螢幕模式影響，照一般版面列印。

## 常見問答與邊界狀況（Q&A）

- **Q: 為什麼看不到「處理進度」？**
  - **A**: 檢查「更多條件」裡的顯示範圍是否選了「未結案」「未處理」或「未指派」。範圍不是「全部」時已結案項目被排除，進度失去對比資訊量，整張卡會隱藏；切回「全部」即恢復。
- **Q: 「資料完整度」顯示「缺 N 主機日」代表什麼？**
  - **A**: 期間內有 N 個主機日（一台主機一天）應該有日誌分析資料卻沒有，可能是取數失敗或沒有排到。這時沒有告警不代表沒有問題，要先補資料。
- **Q: 「資料完整度」值是「完整」，為什麼卡片是警示色並寫「資料至 11/08」？**
  - **A**: 沒有缺漏的主機日，但最新資料只到 11/08，比應有的最後一天（期間終點與昨天取早者）更早，代表後面的日子還沒有資料。
- **Q: 為什麼點「風險類型分布」或「問題排行」下鑽後，清單筆數和顯示範圍對不起來？**
  - **A**: 這兩處是跨主機跨日的問題維度獨立聚合，不受日層級「顯示範圍」影響，副標題已標明。
- **Q: 為什麼問題排行的筆數少於問題總數？**
  - **A**: 排行只列 Top 10，其餘併入「其他 N 個問題」。全部受影響主機都已有結論的問題與靜音中的問題不列入，數量標在副標題。
- **Q: 「受影響主機」點進去的清單列數為什麼大於那個數字？**
  - **A**: 數字是去重後的主機台數，而問題查詢頁預設列出逐「主機×日」的明細。要對照主機總數，看問題查詢頁頂部的主機數。
- **Q: 為什麼前期對比出現紅色向上箭頭？**
  - **A**: 告警數量上升代表風險增加，用紅色提醒；下降代表改善，以次要文字呈現。
