# PRTG 維護（AI 檢索版）

PRTG 維護頁（系統管理 > PRTG 維護，權限 Maintain）有「連線」、「擷取參數」、「鏡像狀態」、「環境探測」、「歷史回填」、「使用效果」六個頁籤。資源守門在「系統管理 > 設定 > 資源守門」，因為它也節制 NetIQ 取數。頁首「啟用準備」六項全部確認後顯示「最近一次排程驗收」三項：最近一趟排程取數的 PRTG 結局為 success、AI 待補歸零且上次執行正常、快照最近 24 個完整小時中有目標的小時 ≥75% 品質達標且最近一小時有成功快照；立即執行不計入，沒有排程執行或沒有快照資料不算通過。監看範圍（可選縮圈）是擷取參數頁籤末尾的收合卡、預設收合並記住展開；通知處理狀態在使用效果頁籤末尾。

## 啟用與時程

- 四步：連線測試並儲存 → 同步結構與對應（背景）→ 啟用 PRTG 規則 → 等每日排程。沒有身分、時區、profile、綁定、授權等額外步驟。
- 狀態型 finding（down、warning、flapping、silent）在第一次每日排程後出現；趨勢型最早 28 個有效日後。就緒度卡與主機詳情顯示「資料累積中 X／28 日」。
- PRTG 帳號時區請與服務主機相同。數值以 `datetime_raw`（UTC）為準；缺 raw 時以顯示字串依服務主機地區設定推得，時區不同時執行輸出有警告與計數。

## 設定重點

- 取數策略：保守（預設，15 分鐘快照、夜間不逐顆查歷史值）／激進（5 分鐘快照，夜間對觸發主機查 historicdata）。
- 預設 sensor type 白名單含 Ping、SNMP CPU Load、SNMP Memory、SNMP Disk Free 與網卡、多碟可用空間等，不含 Traffic；既有站台保留原清單。白名單只管數值取數與快照，不影響狀態規則母體。
- 分類補充對照一行一筆 `type=分類[:語意]`；語意代碼 `cpu-percent-used`、`memory-percent-free`、`disk-percent-free`、`ping-ms`。對照外的 type 在數值規則中為「單位未知」。

## 主機對應

- 先比 IP（去 scheme／port／前導零；名稱型 host 經 DNS，佔位值如 `10.2xx.x.x` 不送 DNS）。IP 查無主機或裝置沒 IP 時以名稱退路：裝置名稱括號內字串（含去掉開頭單一字母＋`-` 的變體）與 host 欄非 IP 值，比對主機短名稱。
- IP 命中恰好一台主機時，該 IP 底下所有裝置都 ok 對到這台主機。名稱退路只補 IP 完全沒對到、也沒有人工對應的主機。
- 衝突型別只有兩種：IP 對多主機（multi-host）、hostname 多主機（hostname-multi）。人工對應優先於自動與 IP 排除；IP 排除整個 IP 不對應、不取數、不評規則；同 IP 已有人工指定裝置時其餘略過。
- 名稱不一致提醒：IP 對上，但裝置名稱括號內或 host 欄 DNS 名稱與主機短名稱不同，只提醒、不影響對應。
- 某日的對應取該日或之前 31 天內最近一份；找不到時沿用之後最早一份（執行輸出與逐日說明註明「沿用」）。
- 畫面只呈現主機清單內的主機：未對應主機清單（原因：衝突、沒有 IP、IP 已排除、PRTG 查無）、依主機搜尋裝置後指派；PRTG 端有、主機清單沒有的裝置只在環境探測、資源守門預覽與指派搜尋出現。

## 數值評估與趨勢規則

- 數值可信＝三條件：該日 ok 或人工對應、可用列（ok，或 sampled 且 coverage ≥ 75）、單位可判。另排除範圍外的值與近 7 個有效日每小時完全相同的固定值。每日代表值需至少 12 個可用小時。
- 不足原因列舉：就緒、有效日不足、品質不足、值不合理、固定值、單位未知、對應無效。就緒度卡、規則頁試算、主機詳情顯示同一原因。資料不足不產生 finding、不升風險、不顯示綠燈。
- 四條趨勢規則皆預設停用、門檻暫定：disk_free_trend（可用 % 下降、低水位 20%）、memory_used_trend（已用 % 攀升、預估 7 日內 ≥90%，可用 % 在單一位置轉成已用）、cpu_load_trend（斜率 ≥0.3 pt/日且近 7 日平均 ≥70%）、ping_latency_trend（近 7 日中位數 ≥ 前 28 日 ×1.5 且 ≥50 ms）。35 日窗、至少 28 有效日。
- 趨勢規則只抓慢性惡化；突發由 PRTG 告警經狀態規則處理。
- 啟用條件後端強制：至少一顆就緒且語意相符的 sensor。草稿試算四條共用，唯讀。
- 趨勢 finding 的 Detail：`{裝置}／{sensor}：{規則白話}；近 N 日有效 M 日；目前 {值}{單位}，每日 {斜率}；預估 {日期} 達 {門檻}；資料截至 {日}`，簽章另帶結構化 `PrtgTrendEvidence`。

## finding 的去向

- 進當日主機日的 TopIssues；當日無分析紀錄時建立 PRTG 獨立主機日（log_source=3），日誌分析晚到時原地合併。PRTG 獨立主機日不算已分析，不影響缺日補跑、趨勢歷史、週檢。
- 風險只升不降：availability down（重大）→ 高；嚴重度 High → 中。AI prompt 只收已判定、未抑制的 finding。
- PRTG 不觸發即時告警信；日／週摘要含 PRTG 段。
- 標記誤報：某日標誤報後同主機同簽章 30 日內再出現視同已處理，不進摘要、排行顯示「已標誤報」（每台主機最近一次出現都在窗內才標）；改回其他狀態即解除；finding 仍寫入。使用效果按規則代碼分列「標記誤報／已處理」，分母是已標記的 PRTG 問題，全 0 顯示「尚無標記」。
- 跨來源佐證（儲存、容量、關機三模式）是同主機日弱佐證，不升風險。

## 資源守門

- 受監看清單留空時，夜間取數在建立作業範圍前自動偵測（直接查 PRTG，15 秒逾時）並寫回清單，blob `prtg_resource_guard_autodetect` 記偵測日期；設定頁顯示「自動偵測 yyyy-MM-dd」。人工清單不覆寫；逾時或失敗本趟不守門、取數照常。
- cpu 值 ≥ 門檻、memory／corehealth 值 ≤ 可用門檻算超標；連續超標才暫停，單趟累計暫停有上限，讀值失敗一律放行。

## 環境探測與診斷

- 完整環境探測唯讀，含版本、type 分布、IP 覆蓋、分頁語意、數值單位判定、逐物件查詢驗證（9d-5），成功後接站台對照 [S1]–[S3]。小範圍資料流驗證抓一顆 sensor 昨天的值並讀回。
- 就緒度卡 `GET api/prtg/value-readiness`：取數範圍內已對應的 cpu／memory／disk／availability sensor，28 日窗。
- 歷史回填範圍：保守策略＝該日全部 ok 對應主機（白名單為空時拒絕）；激進策略依夜間數值取數對象。立即執行的「一併補齊」用同一範圍，確認框顯示主機數、sensor 數、查詢次數，查詢 ≥2,000 次時預設不勾。
- 歷史回填先預覽（五分鐘有效）再確認；只補數值與狀態變更，不做主機對應。指定主機補值只補數值。全量回填有完成水位：某日每顆目標 sensor 都取到才記完成，鍵為設定版本、範圍版本與該日目標指紋，7 天未更新不採信；預覽列出可略過天數與剩餘請求，預設只補剩餘日，全部完成時拒絕空跑，「全部重做」（`resume=false`）清水位全跑。夜間取數遇回填執行中最多等 30 分鐘，之後並行。
- 診斷搬運：匯出需 SQL Server snapshot isolation 或 SQLite WAL；匯入走分片持久工作，只作隔離診斷。

## 升級注意

升級前備份資料庫：升級會不可逆刪除已移除機制的 blob，並刪除已停寫的 `lf_prtg_observations` 表。診斷匯出不再含 Observations 區段（格式版本仍為 2），舊包匯入照驗不寫入，舊版站台匯不進新版匯出的包。三條資源壓力規則已移除；套用內建規則更新（seed v11）才有四條趨勢規則。PRTG 不再即時寄信。預設白名單變更不影響既有站台已儲存的清單。
