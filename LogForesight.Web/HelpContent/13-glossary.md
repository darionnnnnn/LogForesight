# 名詞解釋

全站同一個東西只用一個名字。看到不懂的詞，先來這裡查。

## 基本單位

| 名詞 | 意思 |
|---|---|
| 主機日 | 一台主機的一天，是計算次數的單位 |
| 風險日 | 有風險判定的主機日；點進去就是「風險日詳情」 |
| 問題 | 同一種事件：Windows 是「來源＋Event ID＋類型」，Linux 是「程式＋事件名稱」。跨主機都算同一個 |
| 問題簽章 | 用來辨認「是不是同一個問題」的那組識別，比「規則」更細 |
| Event ID | Windows 事件的編號 |

## 風險與嚴重度

| 名詞 | 意思 |
|---|---|
| 日風險等級 | 一台主機一天整體的風險：高、中、低。畫面篩選標籤叫「風險層級」 |
| 問題嚴重度 | 單一問題本身有多嚴重。「依問題」角度的篩選標籤叫「問題嚴重度」 |
| 重大 | 規則勾了「命中即列為高風險日（重大）」，命中當天直接判為高風險 |
| 統計模式 | 沒用 AI 的分析結果，畫面寫「統計模式（AI 未分析）」。規則判斷不受影響 |
| AI 深入分析 | 只針對沒命中任何規則（「其他」類別）的問題，請 AI 進一步解讀 |

一個高風險日裡，同時有高、低嚴重度的問題是常態。日風險等級綜合規則、次數變化、可疑組合與 AI 判讀決定，不等於單一問題的嚴重度。

## 比較與排序

| 名詞 | 意思 |
|---|---|
| 基準 | 過去 30 天裡，這個問題有出現的那些天，每天影響幾台主機的中位數 |
| vs 基準 | 這次影響台數 ÷ 基準。畫面顯示「基準 N 台/日」、「→ M 台」與倍數徽章 |
| 擴散 | 2 倍以上，紅色。影響範圍異常變大 |
| 正常 | 1～2 倍，灰色。一般波動 |
| 收斂 | 低於 1 倍，綠色。情況正在好轉 |
| 新問題，無基準 | 過去 30 天出現不到 3 天，還無法比較 |
| 機房首見 | 這個問題第一次在整個機房出現的日子 |
| 本期首見 | 在這次查詢期間內第一次出現的日子 |
| 優先度分數 | 儀表板與報表排序用；綜合嚴重度、影響範圍、擴散、新舊、未處理比例與主機分級 |
| 主機分級 | 核心、一般、測試三級（預設一般）；只影響優先度分數，不影響偵測 |

新主機剛加入時，系統會寫「趨勢基準建立中」。大約累積兩週資料後，比較才穩定。

## 處理與交辦

| 名詞 | 意思 |
|---|---|
| 處理狀態 | 畫面分三種：未處理、處理中、已處理 |
| 結案原因 | 已處理、不處理、誤報、已知雜訊 |
| 無法處理 | 處理中的一種：要處理但自己做不到，必須寫原因，會通知 admin 群組 |
| 交辦單 | 一個問題 × 一批主機 × 一位處理人 |
| 成員 | 交辦單上的一台主機 |
| 續掛 | 進行中的交辦單自動加入同範圍新出現同問題的主機；指定主機的單不續掛 |
| 派工池 | 使用者群組的設定；池裡的人才會被自動派工選中 |
| 暫停接單 | 使用者的設定（例如休假）；不會再被派新單 |
| 待派 | 有問題卻沒人處理，列在「交辦總覽」的「待派」頁籤 |

「不處理」是評估後決定不處理；「無法處理」是還要處理，但需要別人接手。

## 負責人

| 名詞 | 意思 |
|---|---|
| 主機負責人 | 綁在一台主機上的負責人 |
| 問題負責人 | 綁在一個問題上，跨所有主機；在「問題負責與靜音」頁設定 |

同一天命中問題負責人的問題時，通知改寄給問題負責人，不寄給主機負責人。
問題負責人可以檢視並處理保留期內出現過該問題的主機，不必加入群組。

## 讓告警安靜

| 名詞 | 意思 |
|---|---|
| 靜音 | 整個機房暫時不看某個問題，到期自動恢復 |
| 告警抑制 | 某些主機、群組或全站不再因某訊號告警；事件仍照常記錄 |
| 停用規則 | 整條規則不再用來分類；事件仍會被次數比較與組合檢查看到 |
| 機房結論 | 替整個機房的某個問題一次下結論，可勾選之後自動套用 |

四種工具怎麼選，見「讓告警安靜的工具」。

## PRTG

| 名詞 | 意思 |
|---|---|
| PRTG | 另一套監看網路與主機數值的軟體，本系統可讀取它的資料 |
| sensor | PRTG 裡的一個監看項目，例如某顆磁碟的可用空間 |
| 主機對應 | 把 PRTG 的裝置對到本系統的主機，依 IP 或主機名稱比對 |

PRTG 的設定與名詞見「PRTG 維護」。
