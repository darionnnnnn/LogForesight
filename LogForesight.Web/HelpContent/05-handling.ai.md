# 處理狀態與交辦單（AI 參考指引）

畫面上稱為交辦；舊稱案件。使用者說「案件」時，指的就是交辦單或交辦單上的成員。

## 頁面與權限

- **頁面**：
  - 風險日詳情 `/records/{hostId}/{date}`：逐日與逐問題標記處理狀態。
  - 處理人工作頁 `/handlers/{userId}`：側欄「我的交辦」導向自己的這一頁；主區塊是交辦單清單（手機寬度只留問題與「回覆」鈕，成員數、逾期、未回覆、期限收在問題底下一行），頁尾「進階檢視」展開後另有「依主機」與「被指派的風險日」。
  - 交辦總覽 `/work-orders`：四個頁籤「進行中」「負載看板」「待派」「靜音中」；網址可帶 `source`、`eventId`、`handlerId`、`groupId`，`#load`／`#gaps`／`#muted` 直接開頁籤。
  - 交辦單詳情 `/work-orders/{id}`：頁首卡（單號與問題、狀態、來源徽章，管理動作在卡片右側；處理人、成員、期限、最近回覆一行；範圍、建立、最近新增收在「詳細資訊」）、成員表、時間軸。
  - 使用者詳細 `/admin/users/{id}`：頁首卡右側有「開啟工作頁」；被指派歷程多一欄「所屬交辦單」。
- **能力**：
  - 標記處理狀態、回覆交辦單：`Handle`（回覆只限自己是處理人的單，admin 也一樣）。
  - 交辦、追加、改派、拆出、取消交辦：`Assign`（實務上只有 admin）。
  - 代為結案、統一標記：`Assign` 且 `Handle`。
  - 交辦總覽與清單：`Assign` 或 `ViewAll`（主管角色看得到、改不了）。
  - 立即派工（待派頁籤的 `POST auto-dispatch`）：`Assign`。
  - 自動派工開關、問題靜音：`Maintain`。
  - 看交辦單：處理人本人、`Assign`、`ViewAll` 三者之一；其他人回 403。成員依檢視者可見範圍過濾，看不到的台數會說明。
- **主要 API**（前綴 `/api/work-orders`）：`POST preview` 與 `POST`（交辦預覽與建單）、`POST {id}/append|reassign|split|cancel|admin-close`、`POST {id}/reply`、`POST reply-many`、`GET`（清單）、`GET handler-groups`、`GET {id}`／`{id}/members`／`{id}/timeline`、`GET load-board`、`GET gaps`、`POST auto-dispatch`。處理人頁用 `GET /api/handlers/{userId}/work-orders`、`/work-orders/summary`、`/api/handlers/me/badge`（側欄徽章）、`/workload`（被指派的風險日）。

## 處理狀態模型

```
未處理（open）
處理中（in_progress）
  ├─ 觀察中（observing，問題層級，到期視同逾期）
  └─ 無法處理（escalated，上報，寄信給 admin，不是結案）
已處理（結案四態）
  ├─ 已處理 resolved
  ├─ 不處理 wont_fix
  ├─ 誤報 false_positive
  └─ 已知雜訊 known_noise
```

- 「無法處理」與「不處理」的差別：前者是「要處理但我做不到」，單會轉「上報中」等管理者代為結案或改派；後者是評估後正式結案。

## 交辦單

- **定義**：一個問題（來源＋事件 ID）× 一批主機 × 一位處理人。每台主機是一個成員，背後是那台主機那個問題的案件。
- **不變式**：
  - 進行中的案件一定屬於某張交辦單。
  - 同一處理人同一問題同時最多一張進行中單；再交辦同一問題給同一人＝追加成員、範圍取聯集。
- **推導狀態**（不另存狀態）：進行中（任一成員未結案）、已結案（全部結案；原因 all_closed／moved／cancelled／admin_closed／empty_dispatch）、上報中（任一成員 escalated）、暫停（問題目前靜音中）、未回覆（處理人從未回覆）。沒有重開：結案後同問題再出現是新案件、新單；畫面以讀取時推導標示**復發**（見下「復發、台數與觀察到期」）。
- **來源**：manual（人工交辦）、owner_rule（問題負責人）、auto_dispatch（自動派工）、day_assign（詳情頁日層級指派）、backfill（升級時把舊案件整理成單）。
- **範圍與續掛**：範圍是全站、主機群組或指定主機。續掛開啟時，夜間分析發現範圍內新出現此問題、還沒有人處理的主機，自動加進這張單。指定主機的單不續掛；夜間自動建的單一律是指定主機、不續掛。

## 復發、台數與觀察到期

- **復發**（`IssueRecurrence`，唯一判定，與派工延續性偏好共用 30 天常數）：同主機同問題的上一件案件以「已處理」結案，且結案日距本件建立不超過 30 天（日曆日，第 30 天算、第 31 天不算）。不處理類結案、已取消、沒有上一件都不算。成員帶復發旗標、復發次數與上一件的回覆（日期、狀態、說明）；不存欄位、不重開舊案件。
- **交辦單詳情的成員表**：有狀態篩選與「主機名」搜尋（完全相符、不分大小寫，按 Enter、回第一頁）；勾選（共用的 `createPageSelection`）換頁與搜尋都保留，卡片寫「已選 N 台」，改狀態篩選才清除；整單結案後進行中篩選只會是空的，載入時自動切到「全部」且只切一次（使用者自己選回「進行中」就尊重）。我的交辦的展開成員表同樣有主機名搜尋與「已選 N 台」。
- **台數口徑**：單頭、清單與 KPI 的「台」是不重複主機數，「件」是成員數；畫面寫「進行中 N 台；歷來 M 台、K 件」（歷來同進行中時寫「歷來同」）。停用主機上的成員不計入。成員表一件案件一列；篩選為「全部」時依主機、再依日期由新到舊排，同主機的舊案件標「第 N 次」。
- **觀察到期**：觀察中且觀察至早於今天。成員表寫「觀察期間再發生 N 天」（觀察開始日不含、到今天，該主機該問題有出現紀錄的日數）、「沒有再發生」或「無資料」（觀察期間沒有任何分析紀錄，不等於沒有再發生）。單頭的「把到期且沒有再發生的 N 台結案」只含確定沒有再發生的成員，先確認再以「已處理」、說明「觀察期滿未再發生」送出，不自動結案；只有能回覆的人（處理人本人）在進行中的單看得到。
- **預設期限**：夜間新建的單與案件依嚴重度帶期限（高 3 天、中 7 天、低不帶；`DefaultDueDays` 常數，不是設定）；續掛進既有單的成員沿用單的期限，單沒有期限才依嚴重度帶；既有案件不回填。人工交辦預覽的「預計完成日（選填）」以同一組常數預填、可清除，使用者改過就不再覆蓋。
- **處理優先序與標記**：我的交辦與交辦總覽有嚴重度欄與「新 N」「復發 N」「退回 N」「觀察到期 N」標記；排序另有「處理優先序」（被退回、逾期、嚴重度、期限）、「期限最近」「嚴重度」；清單端點的 `flag`（returned／newToday／recurrence／observationExpired／dueSoon）與其他篩選取交集；`status=todo` 是「待我處理」。

## 交辦流程（依問題視角）

1. 篩選列選好期間、主機或主機群組，在問題列按「交辦」。
2. 後端依篩選解析主機（前端不送主機清單、不設台數上限），預覽與建單共用同一個計畫函式，所以預覽數字就是會落盤的結果。
3. 預覽內容：影響台數、預估主機日、已知雜訊排除台數（手動交辦只排除已知雜訊，抑制與嚴重度不擋）、別人處理中的衝突主機（可勾改派）、會併入的既有單、分攤結果、可逐台取消勾選的主機表格（欄位：選取、主機、狀態；狀態寫「未處理」「處理中（目前：某人）」「已結案：…」「先前判定不處理」）。已結案與先前判定不處理的主機預設不勾、略過，預覽與結果各帶略過台數（「已結案略過 N 台」「先前判定不處理略過 N 台」）；逐台勾選才放進 `reopenHostIds`：已結案的重新開啟、不再打擾的等於恢復。表頭全選只作用在當頁一般主機。預覽另寫「N 台不在對方的檢視範圍」（對方仍可經交辦看到被交辦的問題）、建議期限（依嚴重度：高 3 天、中 7 天）。處理人名單每人標「進行中 N 台」，沒有 email 的標「沒有 email」。協調器另有保底：成員涵蓋日沒有任何可寫入的逐日列時不建案件。
4. 分攤：單一使用者，或使用者群組（一人一張單；平均輪流或依現有負載，兩者都是確定性的）。
5. 範圍由篩選推導：選了主機→指定主機；選了主機群組→那些群組；都沒選→全站。範圍不是指定主機時可勾「續掛新主機」（預設勾）；手動取消勾選過主機時不提供續掛，因為被排除的主機之後再出現會被續掛加回。
6. 逐日寫入量不超過 5000 列就當場完成；超過時案件先建好，逐日列由背景作業分批補上，畫面顯示「逐日同步中 N 台」。

## 回覆流程（處理人）

- 我的交辦頁與交辦單頁：「回覆」一律開回覆表單，對象預設全部進行中主機（`caseIds` 為空）；表單內「只回覆部分主機」可搜尋、貼上多個主機名自動勾選（找不到的列出）、跨頁勾選；也可勾選多張單一次回覆。結論不預選，未選時送出鈕停用（「請選擇這次的結論」）；選處理中時送出鈕寫「更新說明（不結案）」。貼上多個主機名後自動勾選。只回覆部分主機並選結案類結論時，結論下方多一段「其餘 N 台一起設為…（選填）」，選了就在同一次送出兩部分；沒選時，勾選的送出後單上若還有進行中主機，表單問「其餘 N 台要一起設為…」。回覆含復發主機時表單頂端提示並排出三個建議：「還在處理（設預計完成日）」「觀察 7 日」「請管理員評估調整規則或靜音」（後者選「無法處理」並預填「重複發生，請評估調整規則或靜音」）。回覆被拒（改派 403、已結案或成員已非進行中 400）時訊息常駐、說明留在草稿並可複製，並自動重新載入單頭、成員表、清單與 KPI。回覆「處理中」不填日期時，目前就是處理中的成員保留原期限。
- 問題查詢依問題視角的「回覆處理狀態」：回覆自己名下這個問題的全部單。
- 處理人選不處理類（不處理（評估後決定）、誤報、已知雜訊）時，表單多一行提醒：「這台主機的這個問題之後不會再派給任何人；需要恢復請找管理者。」處理人沒有「是否停派」可選，一律停派；一次回覆多台主機或多張單時說明改寫「這些主機的這個問題…」；風險日詳情的處理面板選到不處理類時也顯示同一行說明（一次勾多個問題時寫「這台主機的這些問題…」）；管理者從待派頁的「不再自動派工」區恢復。
- 回覆值域與必填規則同詳情頁：不處理要說明、無法處理要原因。觀察中在處理面板（風險日詳情）填「觀察天數」（1～90 天，預設 7，後端換算成日期），在我的交辦的回覆表單填「預計完成日／觀察至」（日期欄，不可早於今天、最遠 90 天）；兩處都存成同一個到期日。日層級（沒勾問題）的表單沒有觀察中。
- 另一條路徑：點列展開成員表，勾選後按「回覆選取的主機」；只剩一台進行中時對象是那一台，0 台時不開表單並提示「這張單已沒有進行中的主機」。
- 成員被標為無法處理（escalated）後，單的狀態為上報中；有 `Assign` 者在交辦單詳情可按「退回處理人」並寫退回說明，這些成員改回處理中；處理人在下一封交辦摘要收到退回通知（未啟用交辦通知時畫面提示自行告知）。
- 多單回覆含別人的單時整筆拒絕、零寫入。
- 風險日詳情逐筆標記由處理人本人做時也更新「最近回覆時間」，未回覆提醒消失（管理者代標不算）。
- 風險日詳情的處理面板（右欄側軌展開後可見）分四區：狀態摘要（`derivedStatusLabel`、最後更新、逾期字樣、常駐一行雙軌語意說明）→ 人員（主機負責人、處理人與指派）→ 表單（勾選問題時頂端顯示「已勾選 N 個問題」；狀態 chips 以 CSS grid 自動排欄、顯示短標籤、`title` 為完整名稱，點選只切換選取不重建節點；條件欄位；說明欄）→ 動作區（「儲存」／「套用到 N 個問題」）。
- 說明欄編輯器（`attachNoteEditor`，處理面板與交辦回覆彈窗共用）：textarea 下緣緊貼一條灰色尾區，左側字數、「常用語」、「沿用此問題上次的說明」（只勾一個問題時），右側「AI 整理」；草稿提示與 AI 整理結果訊息都在尾區內；錯誤訊息槽（`errorEl`）固定在尾區之後。

## 管理動作（交辦單詳情）

- **改派**：整張單換人；目標已有同問題的進行中單就併入，原單以 moved 結案。
- **拆出主機**：勾選成員交給另一人（同樣適用併入規則）。
- **取消交辦**：派錯時用。成員案件關閉；由這張單寫出去、且不是結案類的日子改回明確「未處理」並留歷程；處理人自己標過的日子不動。原因必填。
- **代為結案**：以管理者名義把整張單結案。對話框「結案狀態」不預選（預設「請選擇結案狀態」，沒選或沒填原因時送出鈕停用），選項是已處理、不處理、誤報、已知雜訊；「結案原因（必填）」；送出鈕寫「代為結案 N 台」（N＝單上進行中台數）。
  - 選不處理、誤報、已知雜訊（不處理類）時才出現勾選框「這台主機的這個問題之後不再自動派工」（單上進行中多於一台時寫「這 N 台主機」），預設不勾；改選別的狀態會清掉勾選。選「已處理」沒有勾選框，後端也忽略。
  - 勾選框文字：單一問題的單照上面寫；單上不只一種問題（沒有單一來源）時改寫「這 N 台主機上的問題之後不再自動派工」（單台寫「這台主機上的問題…」），不指稱「這個問題」。
  - 對話框下方的後果說明：依「交辦單通知」切換——開啟時「處理人會在下一封交辦摘要收到結案通知。」，未開啟時「目前未啟用交辦單通知，請自行告知處理人。」（與退回、取消同句型）；不處理類再依勾選顯示「已勾選：這台主機的這個問題之後不會再自動派工。」或「未勾選：這個問題之後再出現時會重新派工。不想再收到，請勾選上方選項，或改用靜音。」
  - **不勾選時問題再出現會重新派工**，這是管理者最容易漏掉的地方；勾選等同處理人回覆不處理類（見下節「不再自動派工」）。靜音選代為結案時，附註的通知句同樣依「交辦單通知」切換。
  - 靜音時選「代為結案為『不處理』」走同一個結案流程但不停派：靜音期間不派工，靜音結束後問題再出現會重新派工（結案通知信也這樣寫）。
  - 能力：`Assign` 且 `Handle`，詳情頁卡片右側才有「代為結案」鈕。

## 夜間掛接的優先序

每個主機日分析寫入後，逐問題依序判斷：

```
⓪ 紀錄日落在靜音區間 → 不派新工（②③ 照常）
① 當天已有標記或處理 → 略過
② 已有進行中案件 → 掛入
③ 「問題負責與靜音」有自動套用的機房結論 → 套用結論
   派工閘門不過 → 略過並計數（已抑制／已知雜訊／嚴重度不在未處理計算等級／不再打擾）
④ 續掛：同問題有範圍涵蓋此主機、開啟續掛的進行中單 → 掛入（多張時交給負載最輕的處理人）
⑤ 問題負責人 → 掛進負責人的單或建一張（多位時負載最輕；停用、無處理能力、暫停接單者不選）
⑥ 自動派工（系統設定開啟時）→ 派工池成員中看得到此主機、負載最輕者
   無候選 → 計入待派
```

- 自動派工選人：本趟已為此問題選中且看得到這台的人優先；其次是最近 30 天內這台這個問題上次修好（resolved）的人；再來才是負載最輕（進行中成員數→單數→帳號）。
- 不再打擾（畫面稱「不再自動派工」）：同主機同問題最近一件案件以不處理、誤報或已知雜訊結案，且沒有被明確標為「不停派」時，之後不自動派工；以「已處理」結案的不算（修好又壞是新事件）。不處理類的擋派工不會因資料保留期而失效（案件結案標記不隨主機日資料過期清除）。處理人回覆、風險日詳情標記一律停派；管理者代為結案只有勾選時停派；靜音造成的結案不停派。升級前就以不處理類結案的舊案件沒有這個標記，視同停派，會出現在「不再自動派工」區，管理者可逐筆或整個問題恢復。
- 續掛停止：夜間續掛對進行中單做資格檢查（單一判定，續掛、問題負責人、自動派工共用）。處理人已停用或失去處理能力、暫停接單、看不到這台新主機（續掛與自動派工才檢查可見）時，續掛被擋，單上記下原因，顯示為「續掛已停止：處理人已停用或失去處理能力／處理人暫停接單／處理人看不到新主機」（只對具 `Assign` 或 `ViewAll` 的檢視者顯示，處理人本人看不到）——出現在交辦單詳情頁首（info 提示）與交辦總覽「進行中」清單的徽章。成功續掛，或原因已恢復，標記清除。
- 夜間留痕寫在交辦單時間軸（建立、本趟新增台數），執行紀錄有一行摘要「自動派工：建 N 單／掛入 M 台／無候選人 K 台／靜音略過 X／閘門略過 J（抑制、已知雜訊、嚴重度、不再打擾各幾筆）」；自動派工開著但派工池沒有可接單的成員時另有一則警告。

## 待派與立即派工

- 待派頁籤以與夜間相同的決策試跑：期間（預設昨天往前 7 天）內出現、沒有進行中案件、未靜音、且最近出現日還沒被處理人結案的主機（已結案的整筆不列在待派頁、不計入儀表板待派卡、立即派工也不建案；之後有未結案的新出現日就回到待派），套閘門、可見範圍、選人，依問題列出待派台數、建議處理人、派不出去的原因（沒有派工池群組、沒有池成員看得到這些主機、候選人都暫停接單、自動派工未開）。
- 「立即派工」走同一個試跑再落盤，畫面數字就是會發生的事。候選出現點超過 20000 筆時要求縮小期間。

### 「不再自動派工」區

- 位置：交辦總覽「待派」頁籤下方（網址 `#gaps`）。說明文字：「處理人或管理者判定不處理、誤報、已知雜訊的問題，之後不再自動派工。恢復後下一次夜間派工會重新判斷。」
- 內容依問題分組（每頁 50 組，標題右側「共 N 個問題、M 台」），每組標問題與台數，表格欄是「主機」「先前結案狀態」「結案的人」「日期」。沒有項目時寫「沒有不再自動派工的問題」。
- 恢復：列尾「恢復」（確認視窗「恢復自動派工」）只處理那一台；組標題的「整個問題恢復」（確認視窗「恢復整個問題的自動派工」）處理該問題全部主機。恢復只把最新一件案件的停派標記改成「不停派」，不建單、不改狀態與歷程；下一次夜間派工重新判斷。
- 能力：看清單 `Assign` 或 `ViewAll`（主管、開發人員唯讀）；恢復與兩顆按鈕只給 `Assign`，救援帳號 serverAdmin 沒有。
- 待派清單裡，被這個閘門擋下的台數顯示為可點的「不再打擾 N 台」，點了會捲到下方的「不再自動派工」恢復清單。

## 跨日問題案件

- 案件唯一鍵是（主機, 問題簽章），同時最多一件進行中。
- 建案時回溯該主機歷史裡同一問題所有未結案的日子一併掛入；之後每天新的一天自動掛入。
- 在案件涵蓋的任一天標記狀態會同步到其他天；標成結案類時案件結案。
- 使用者自己明確標成結案的日子，案件同步不覆蓋。

## 交辦單上的主機數標記

- 停用主機上的進行中成員不計入處理人的台數（徽章、處理人摘要、負載看板、總覽列、候選人負載同一口徑）：詳情成員表在主機名旁標「主機已停用」，頁首多一項「主機已停用 N 台（不計入處理人的台數）」，總覽「成員」欄副行寫「主機已停用 N」；已結案成員不標。
- 詳情頁首「處理人目前看不到 N 台」：這張單上不在處理人一般可見範圍（群組授權、主機負責人、問題負責人）內的主機數，讀取時計算，不含交辦授與；有值才出現，且只對具 `Assign` 或 `ViewAll` 的檢視者顯示（處理人本人看交辦單時不出現）。處理人仍能處理被交辦的那個問題。
- 使用者頁停用帳號或勾「暫停接單」後，若他名下有進行中交辦單，toast 寫「帳號 名下還有 N 張進行中的交辦單，（停用／暫停接單）後這些單仍在他名下」，附連結「到交辦總覽改派或結案」（帶 `handlerId` 與進行中篩選）；操作者沒有 `Assign` 也沒有 `ViewAll`（例如 serverAdmin 救援帳號）時不附連結，改寫「請通知系統管理員改派或結案」；0 張不提示。單不會自動轉走。

## 交辦授與

- 被交辦的主機即使不在授權範圍內，也取得針對那個問題的檢視權：看不到同一天其他問題與整日 AI 敘事，頁面標示「您以交辦單處理人身分檢視」。
- 以「現在或曾經是處理人」為準，結案後仍看得到。
- 不進一般可見清單：主機清單、儀表板、報表的統計不包含這些主機，動線是我的交辦與直連。

## 通知

- 系統設定「交辦單通知」開啟時：建單寄給處理人；改派時新處理人收建單信、舊處理人收「已移交」；取消交辦寄給處理人；夜間續掛與自動派工每趟每人一封彙總。
- 處理人新收到三種通知：「代為結案」（結案狀態、原因，並寫問題再出現時：勾選不再自動派工＝「不會重新派工」、靜音造成的結案＝靜音期間不會且迄日後會、其餘＝「會重新派工」）、「靜音暫停」（設定靜音時進行中單暫停，寫迄日與原因）、「靜音恢復」（提前解除靜音）。靜音若同時代為結案，只發結案通知，不另發暫停。一位處理人同一時段的多種通知併成一封，信件段落依序是【新交辦】【新增成員】【移交】【取消】【退回】【代為結案】【靜音暫停】【靜音恢復】，主旨摘要有才列。
- 改派或拆出主機時，接手的人若已有同問題的進行中單，主機併進那張單，對方收到【新增成員】（時間軸動作「追加主機」）而不是新交辦。
- 管理者提醒（`AdminReminderService.Compute` 是唯一彙整；交辦總覽與夜間入列共用）：①上報（無法處理）成員超過 N 天仍未處理，自轉進上報的時間起算（舊資料退回最後更新日）；②最近一趟夜間派工派不出去的問題；③上報時沒有任何收件人的單；④反覆結案又復發的成員（同主機同問題復發次數達 3 次，與上報類同樣每 N 天至多提醒一次；靜音中的問題與停用主機不列）；交辦總覽提醒區另有第五類「今天新上報」，只在畫面顯示、不寄信。N＝設定「管理者提醒間隔（天）」，預設 3、範圍 0～30，0＝不寄信（總覽仍以 3 天判定逾期）；同一成員每 N 天至多提醒一次。收件人是 admin 群組啟用中、有 email 的成員，隨交辦摘要寄出（段落【管理者提醒】，只有提醒時主旨為「管理者提醒」），需要「啟用郵件通知」與「交辦單通知」同時開啟。上報時找不到收件人的當下會留稽核。
- 交辦總覽頁籤列上方的提醒區（`GET api/work-orders/admin-reminders`，`Assign` 或 `ViewAll`）：警告「有項目需要管理者處理」，每類一行——「今天新上報：N 筆」（看上報中的單；只在這裡顯示、不寄信）、「上報超過 N 天沒人處理：N 筆」（看上報中的單）、「最近一次夜間派工派不出去的問題：N 筆」（看待派）、「上報信沒有任何收件人的單：N 筆」（看單號）、「反覆結案又復發：N 筆」（連到進行中的單，明細有單號、問題、主機、復發次數）；各類都是 0 時整區不顯示，不受郵件開關與間隔影響，郵件關閉時這是唯一管道。每類有預設收合的「看是哪些」明細（上報：單號連結、問題、主機、上報天數；派不出去：問題、原因、台數，並標彙整時間；每類最多 50 筆，超過時註明總數）；提醒間隔設為 0 時另顯示「提醒信已關閉（設定為 0），此處仍會顯示。」
- 只有退回段附「只看被退回的單」連結（`?flag=returned`）；新交辦、新增成員兩段不帶篩選（信常在隔天早上才寄，「今天新增」會是空的），信尾的連結指向「我的交辦」。
- 信件連結：系統設定「站台網址」有填才附「連結：…」；交辦類信件連到該處理人的「我的交辦」、管理者提醒連到「交辦總覽」、上報信連到該交辦單與「問題查詢」。沒填就不附任何連結。
- 彙總信裡，若自動派工把某台主機派回給最近 30 天內修好它的人（復發），該單那一行會寫「其中 N 台是復發」。
- 信件列前 20 台主機名，超過寫「…等 N 台」；收件人是操作者本人時不寄。

## 待派三段、單題派工與批次改派
- 待派頁籤分三段：「可以派」（有建議處理人，預設展開）、「派不出去」（無人選，依原因 no_pool／all_paused／no_visibility 分組，每組說明一次）、「不會派」（嚴重度未達、不再打擾、抑制、已知雜訊、靜音；預設收合）。同一問題在不同主機上可落在不同段，各段各算一次。儀表板「待派工問題」卡與提醒區的「可派未派」只計前兩段。
- 「沒有人看得到」的主機群組去重，每個群組一列；有維護權限者可在群組旁「授權給…」（選派工池群組，增減式授權，完成後該段重算），沒有時只有連結。
- 「立即派工」（整頁）與每列「派這個問題」（單題）都先預覽（將建立 N 張、併入 M 張、共 K 台、每人幾台、派不出去的原因）再確認；預覽與實際派工用同一個試跑。沒有任何新成員被派出時訊息為「沒有需要派的項目（可能剛由其他人派出）」。
- 批次改派：進行中頁籤勾選多張（上限 100，超過按鈕停用）→「改派給…」→選新處理人→「預覽」→「確定改派 N 張」。預覽每張分類：原單換處理人（目標沒有同問題進行中單）、併入 #單號（目標已有同問題單，原單以移交結案）、略過（已是該處理人、已結案、找不到）；另寫會移動台數、要補上授與的台數，以及目標暫停接單、沒有 email、沒有處理能力的提醒（仍可改派）。套用逐張進行，一張失敗不影響其他張，結果表列出失敗與略過原因。需要 Assign。
- 進行中頁籤有「處理人」篩選；負載看板點人名會帶入篩選，「改派他名下的單…」會篩出該人並勾好（名下的單超過一頁時要先調高每頁筆數或勾本頁）。停用帳號或勾「暫停接單」前，名下有進行中單會先顯示張數與台數，可選「一併改派」或「先不處理」。
- 管理員待辦：提醒區與儀表板「需要你處理」列同一份資料，除五類提醒外，具 Assign 者另有最近一趟取數失敗、可派未派、處理人已停用或暫停仍有單（單位是人）、未分組主機；Manager、Dev 看不到這四項；可派未派不進摘要信。

## 不再打擾 30 天解除與先前判定不處理
- 處理人回覆「不處理、誤報、已知雜訊」後，該主機該問題不再派工。若該問題目前規則的嚴重度是高或帶重大旗標，結案滿 30 天（第 30 天仍擋、第 31 天不擋）後解除一次：問題仍在發生就照常派工，新單的成員標「先前判定不處理（日期、判定人），已滿 30 天仍在發生」，單歷程有一筆系統事件「dismissal_released」。處理人再次回不處理就重新計 30 天。
- 永久的情況：中、低嚴重度；管理者代為結案時勾選「之後不再自動派工」；規則不存在或無法唯一對到規則；上線前（生效日 2026-11-25 之前）就結案的案件，清單標「上線前判定」，要管理者逐筆或整個問題「恢復」。
- 不再自動派工清單預設收合、展開才載入；標題旁的數字是輕量計數；每列「恢復派工」欄寫「N 天後恢復派工」、「永久」或「上線前判定」。
- 回覆彈窗選不處理類、代為結案的說明與結案通知信，對會解除的問題寫「30 天內不再派工，之後仍在發生會重新派工」，永久的維持「之後不會再派給任何人」。多張單一起回覆時，要全部都會解除才用新說法。
- 這是上線當天要提醒的行為：以前永久不派的高嚴重度問題，滿 30 天後可能出現新單。

## 交辦單頁的處置參考、捷徑與代為結案範圍
- 單頭可展開「處置參考」（規則的影響、可能原因、處置步驟）與「訊息樣本」（成員中最近一次出現的樣本，最多 3 則）；未命中規則的問題沒有處置參考，樣本照常。
- 捷徑：「這個問題的其他交辦單」（Assign 或 ViewAll）、「靜音這個問題」、「不再顯示這個問題…」、「調整這條規則」（後三者需要 Maintain，「調整這條規則」另需問題命中規則）。
- 代為結案的「結案範圍」：全部進行中／只有上報中的（有上報成員時預設）／勾選的成員。範圍內結案後單上還有進行中成員，單繼續進行。
- 成員表同一台主機有多列時標登錄類型；沒有權限檢視的人看不到成員與歷程區塊。
- 回覆「無法處理」後，訊息寫「已通知 N 位管理員」；沒有可通知的管理員時寫已列入交辦總覽提醒。

## 常見問答

- **為什麼問題明明修好了，隔天又出現未處理？** 若先前只標「處理中」，案件仍進行中；若已結案但隔天同一台又出現同一事件，系統視為復發、建新的未處理紀錄。以「已處理」結案的主機會優先派回給上次修好的人。
- **自動派工為什麼沒派給某人？** 確認他所在群組是派工池、沒有暫停接單、看得到該主機、具處理能力；問題本身不在靜音、抑制、已知雜訊、嚴重度門檻、不再打擾之列。派不出去的原因會列在待派頁籤。
- **統一標記會動到別人處理中的主機嗎？** 不會。統一標記只套用在沒有進行中案件的主機，已有案件的主機在預覽列為略過。
- **處理人看不到那台主機怎麼辦？** 交辦授與讓他看得到被交辦的那個問題；在我的交辦頁點成員或「去處理」進入。
- **交辦單為什麼顯示暫停？** 該問題目前靜音中。暫停的單不在處理人清單與徽章裡，靜音結束後自動恢復，總覽可用「只看自靜音恢復」找到。「只看處理人已停用或失去處理能力」篩出處理人已停用或不再具處理能力的單（與續掛停止原因「處理人已停用或失去處理能力」同義）。
