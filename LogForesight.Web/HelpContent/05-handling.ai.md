# 處理狀態、交辦單與案件（AI 參考指引）

## 頁面與權限

- **頁面**：
  - 風險日詳情 `/records/{hostId}/{date}`：逐日與逐問題標記處理狀態。
  - 處理人工作頁 `/handlers/{userId}`：側欄「我的交辦」導向自己的這一頁；三個頁籤「交辦單」「依主機」「被指派的風險日」。
  - 交辦總覽 `/work-orders`：四個頁籤「進行中」「負載看板」「待派」「靜音中」；網址可帶 `source`、`eventId`、`handlerId`、`groupId`，`#load`／`#gaps`／`#muted` 直接開頁籤。
  - 交辦單詳情 `/work-orders/{id}`：標頭、成員表、時間軸、管理動作。
  - 使用者詳細 `/admin/users/{id}`：被指派歷程多一欄「所屬交辦單」。
- **能力**：
  - 標記處理狀態、回覆交辦單：`Handle`（回覆只限自己是處理人的單，admin 也一樣）。
  - 交辦、追加、改派、拆出、取消交辦：`Assign`（實務上只有 admin）。
  - 代為結案、統一標記：`Assign` 且 `Handle`。
  - 交辦總覽與清單：`Assign` 或 `ViewAll`（主管角色看得到、改不了）。
  - 立即派工、自動派工開關、問題靜音：`Maintain`。
  - 看交辦單：處理人本人、`Assign`、`ViewAll` 三者之一；其他人回 403。成員依檢視者可見範圍過濾，看不到的台數會說明。
- **主要 API**（前綴 `/api/work-orders`）：`POST preview` 與 `POST`（交辦預覽與建單）、`POST {id}/append|reassign|split|cancel|admin-close`、`POST {id}/reply`、`POST reply-many`、`GET`（清單）、`GET handler-groups`、`GET {id}`／`{id}/members`／`{id}/timeline`、`GET load-board`、`GET gaps`、`POST auto-dispatch`。處理人頁用 `GET /api/handlers/{userId}/work-orders`、`/work-orders/summary`、`/api/handlers/me/badge`（側欄徽章）、`/workload`（被指派的風險日）。

## 處理狀態模型

```
未處理（open）
處理中（in_progress）
  ├─ 觀察中（observing，問題層級，到期視同逾期）
  └─ 無法處理（escalated，上報，寄信給 admin，不是結案）
已處理（結案四態）
  ├─ 已解決 resolved
  ├─ 不予處理 wont_fix
  ├─ 誤報 false_positive
  └─ 已知雜訊 known_noise
```

- 「無法處理」與「不予處理」的差別：前者是「要處理但我做不到」，單會轉「上報中」等管理者代為結案或改派；後者是評估後正式結案。

## 交辦單

- **定義**：一個問題（來源＋事件 ID）× 一批主機 × 一位處理人。每台主機是一個成員，背後是那台主機那個問題的案件。
- **不變式**：
  - 進行中的案件一定屬於某張交辦單。
  - 同一處理人同一問題同時最多一張進行中單；再交辦同一問題給同一人＝追加成員、範圍取聯集。
- **推導狀態**（不另存狀態）：進行中（任一成員未結案）、已結案（全部結案；原因 all_closed／moved／cancelled／admin_closed）、上報中（任一成員 escalated）、暫停（問題目前靜音中）、未回覆（處理人從未回覆）。沒有重開：結案後同問題再出現是新案件、新單。
- **來源**：manual（人工交辦）、owner_rule（問題負責人）、auto_dispatch（自動派工）、day_assign（詳情頁日層級指派）、backfill（升級時把舊案件整理成單）。
- **範圍與續掛**：範圍是全站、主機群組或指定主機。續掛開啟時，夜間分析發現範圍內新出現此問題、還沒有人處理的主機，自動加進這張單。指定主機的單不續掛；夜間自動建的單一律是指定主機、不續掛。

## 交辦流程（依問題視角）

1. 篩選列選好期間、主機或主機群組，在問題列按「交辦」。
2. 後端依篩選解析主機（前端不送主機清單、不設台數上限），預覽與建單共用同一個計畫函式，所以預覽數字就是會落盤的結果。
3. 預覽內容：影響台數、預估主機日、已知雜訊排除台數（手動交辦只排除已知雜訊，抑制與嚴重度不擋）、別人處理中的衝突主機（可勾改派）、會併入的既有單、分攤結果、可逐台取消勾選的主機清單。
4. 分攤：單一使用者，或使用者群組（一人一張單；平均輪流或依現有負載，兩者都是確定性的）。
5. 範圍由篩選推導：選了主機→指定主機；選了主機群組→那些群組；都沒選→全站。範圍不是指定主機時可勾「續掛新主機」（預設勾）；手動取消勾選過主機時不提供續掛，因為被排除的主機之後再出現會被續掛加回。
6. 逐日寫入量不超過 5000 列就當場完成；超過時案件先建好，逐日列由背景作業分批補上，畫面顯示「逐日同步中 N 台」。

## 回覆流程（處理人）

- 我的交辦頁：勾選單內部分成員回覆（未勾＝全部進行中成員），或勾選多張單一次回覆。
- 問題查詢依問題視角的「回覆處理狀態」：回覆自己名下這個問題的全部單。
- 回覆值域與必填規則同詳情頁：不予處理要說明、無法處理要原因、觀察中要天數。
- 多單回覆含別人的單時整筆拒絕、零寫入。
- 風險日詳情逐筆標記由處理人本人做時也更新「最近回覆時間」，未回覆提醒消失（管理者代標不算）。

## 管理動作（交辦單詳情）

- **改派**：整張單換人；目標已有同問題的進行中單就併入，原單以 moved 結案。
- **拆出主機**：勾選成員交給另一人（同樣適用併入規則）。
- **取消交辦**：派錯時用。成員案件關閉；由這張單寫出去、且不是結案類的日子改回明確「未處理」並留歷程；處理人自己標過的日子不動。原因必填。
- **代為結案**：以管理者名義把整張單結案，選結案四態之一、原因必填。

## 夜間掛接的優先序

每個主機日分析寫入後，逐問題依序判斷：

```
⓪ 紀錄日落在靜音區間 → 不派新工（②③ 照常）
① 當天已有標記或處理 → 略過
② 已有進行中案件 → 掛入
③ 問題檔案設了自動套用的機房結論 → 套用結論
   派工閘門不過 → 略過並計數（已抑制／已知雜訊／嚴重度不在未處理計算等級／不再打擾）
④ 續掛：同問題有範圍涵蓋此主機、開啟續掛的進行中單 → 掛入（多張時交給負載最輕的處理人）
⑤ 問題負責人 → 掛進負責人的單或建一張（多位時負載最輕；停用、無處理能力、暫停接單者不選）
⑥ 自動派工（系統設定開啟時）→ 派工池成員中看得到此主機、負載最輕者
   無候選 → 計入待派
```

- 自動派工選人：本趟已為此問題選中且看得到這台的人優先；其次是最近 30 天內這台這個問題上次修好（resolved）的人；再來才是負載最輕（進行中成員數→單數→帳號）。
- 不再打擾：同主機同問題最近一件案件以不予處理、誤報或已知雜訊結案時，之後不自動派工；以「已解決」結案的不算（修好又壞是新事件）。
- 夜間留痕寫在交辦單時間軸（建立、本趟新增台數），執行紀錄有一行摘要「自動派工：建 N 單／續掛 M 台／待派 K 組／閘門略過 J」。

## 待派與立即派工

- 待派頁籤以與夜間相同的決策試跑：期間（預設昨天往前 7 天）內出現、沒有進行中案件、未靜音的主機，套閘門、可見範圍、選人，依問題列出待派台數、建議處理人、派不出去的原因（沒有派工池群組、沒有池成員看得到這些主機、候選人都暫停接單、自動派工未開）。
- 「立即派工」走同一個試跑再落盤，畫面數字就是會發生的事。候選出現點超過 20000 筆時要求縮小期間。

## 跨日問題案件

- 案件唯一鍵是（主機, 問題簽章），同時最多一件進行中。
- 建案時回溯該主機歷史裡同一問題所有未結案的日子一併掛入；之後每天新的一天自動掛入。
- 在案件涵蓋的任一天標記狀態會同步到其他天；標成結案類時案件結案。
- 使用者自己明確標成結案的日子，案件同步不覆蓋。

## 案件授與

- 被交辦的主機即使不在授權範圍內，也取得針對那個問題的檢視權：看不到同一天其他問題與整日 AI 敘事，頁面標示「您以案件處理人身分檢視」。
- 以「現在或曾經是處理人」為準，結案後仍看得到。
- 不進一般可見清單：主機清單、儀表板、報表的統計不包含這些主機，動線是我的交辦與直連。

## 通知

- 系統設定「交辦單通知」開啟時：建單寄給處理人；改派時新處理人收建單信、舊處理人收「已移交」；取消交辦寄給處理人；夜間續掛與自動派工每趟每人一封彙總。
- 信件列前 20 台主機名，超過寫「…等 N 台」；收件人是操作者本人時不寄。

## 常見問答

- **為什麼問題明明修好了，隔天又出現未處理？** 若先前只標「處理中」，案件仍進行中；若已結案但隔天同一台又出現同一事件，系統視為復發、建新的未處理紀錄。以「已解決」結案的主機會優先派回給上次修好的人。
- **自動派工為什麼沒派給某人？** 確認他所在群組是派工池、沒有暫停接單、看得到該主機、具處理能力；問題本身不在靜音、抑制、已知雜訊、嚴重度門檻、不再打擾之列。派不出去的原因會列在待派頁籤。
- **統一標記會動到別人處理中的主機嗎？** 不會。統一標記只套用在沒有進行中案件的主機，已有案件的主機在預覽列為略過。
- **處理人看不到那台主機怎麼辦？** 案件授與讓他看得到被交辦的那個問題；在我的交辦頁點成員或「去處理」進入。
- **交辦單為什麼顯示暫停？** 該問題目前靜音中。暫停的單不在處理人清單與徽章裡，靜音結束後自動恢復，總覽可用「只看自靜音恢復」找到。
