# 主機與群組

## 主機清單（「系統管理 > 主機」頁）

要分析哪些主機由這裡的主機清單決定——admin 可新增、停用、批次貼上多筆主機。清單上看得到：

- 每台主機的**作業系統**標記（`[Windows]`／`[Linux]`）——OS 決定套用哪個平台的規則面，標錯等於整台的偵測面配錯。
- **分級**（核心／一般／測試）：純人工分類，不影響規則面或批次行為，只用於儀表板「重點問題」與報表排行的優先度分數計算——受影響主機裡有核心主機的問題會被排得比較前面。可單台編輯，也可勾選多台後「批次設定分級」。
- **負責人**：指定後，該使用者即使沒有加入任何群組，也能看到並處理這台主機（見「授權與角色」一節）。
- 實際會被查詢的主機清單與排除原因（例如尚未確定所屬 Sentinel、IP 與其他主機衝突）——沒查到不等於沒事，畫面上必須看得出來。IP 衝突時只查最早建立的那一台，行為才可預測。

## 主機群組與使用者群組（「系統管理 > 群組與授權」頁）

三個分頁：

1. **使用者群組**：對應組織的部門／團隊，決定一群人共用哪些授權。
2. **主機群組**：把主機分類（例如依機房、依用途），是授權矩陣與告警抑制範圍的作用對象。
3. **授權矩陣**：勾選「哪個使用者群組可以看見哪個主機群組」。**只列出一般使用者群組**——admin／manager／dev 角色本來就能看見全部主機，不需要也不受此矩陣影響。

主機群組除了授權，也是「告警抑制」的抑制範圍選項之一（同類主機批次抑制，見「告警抑制」一節），以及規則維護頁抑制目標的主機下拉篩選依據。

## NetIQ 主動探索匯入

多主機環境（透過 NetIQ Sentinel 取數）可用「系統管理 > NetIQ 維護」頁的「匯入」分頁批次登錄主機：選一台已設好探索帳密的 Sentinel、輸入要掃描的網段（前綴如 `192.168.0` 或 CIDR）→ 掃描 → 依網段勾選 → 指派群組與作業系統 → 送出即立即新增／更新／復活已停用主機。掃描只涵蓋掃描窗口內有事件回報的主機，涵蓋範圍與是否截斷會誠實顯示在結果上方；安靜的主機請改用主機頁手動登錄。

掃描結果會記入「資料匯入」頁的匯入紀錄，與負責人 CSV 匯入共用同一份稽核軌跡，詳見「匯入」一節。當晚的規則檢查與趨勢分析仍要等下次批次執行才有結果——即時的只是「主機被收進清單」這件事本身。
