# 主機與群組（AI 參考指引）

## 頁面基本資訊與存取架構

- **頁面路徑**：
  - 主機管理頁面：`/admin/hosts`。
  - 群組與授權管理頁面：`/admin/groups`（包含「使用者群組」、「主機群組」、「授權矩陣」三個分頁）。
  - 單一主機詳情／時間軸：`/hosts/{id}`。
- **存取權限**：`/admin/hosts` 與 `/admin/groups` 需要 `Capability.Maintain`（`admin` 與 `serverAdmin` 角色具備）。
- **後端端點**：
  - 主機清單分頁查詢：`GET /api/admin/hosts`（支援 `query`, `status`, `sentinel`, `groupIds`, `os`, `sort`, `dir`, `page`, `pageSize` 伺服器端分頁與過濾）。
  - 全選符合條件主機 ID：`GET /api/admin/hosts/ids`。
  - 主機儲存／單台編輯：`POST /api/admin/hosts`。
  - 批次變更主機群組：`PUT /api/admin/hosts/groups/batch`。
  - 批次設定主機分級：`PUT /api/admin/hosts/tier/batch`。
  - 設定主機負責人：`PUT /api/admin/hosts/{hostId:long}/owners`。
  - 主機合併／解除合併：`POST /api/admin/hosts/merge`、`POST /api/admin/hosts/{hostId:long}/unmerge`。
  - 主機群組 CRUD：`GET/POST/DELETE /api/admin/host-groups*`。
  - 授權矩陣查詢與更新：`GET /api/admin/access`、`PUT /api/admin/access/{userGroupId:long}`。
  - NetIQ 網段掃描與匯入：`POST /api/admin/netiq/scan`、`POST /api/admin/netiq/import`。

## 主機清單與核心屬性模型（`WebHost`）

主機清單是系統決定「要對哪些資產執行日誌分析」的事實來源：

### 1. 作業系統標記（`Os`）
- **列舉值**：`windows`（預設）或 `linux`（經 `WebHost.NormalizeOs` 正規化為全小寫）。
- **核心影響**：`Os` 決定該主機在夜間分析時套用 **Windows 規則面** 還是 **Linux 規則面**。
- **匯入不變原則**：NetIQ 掃描匯入與 CSV 匯入時設定的作業系統，**僅套用於本次新建立的主機**；既有主機（含已復活的孤兒主機）之 `Os` 絕不被匯入作業自動覆寫，以防止既有主機的偵測面被意外篡改。

### 2. 主機分級（`Tier`）
- **列舉值**：`core`（核心）、`standard`（一般，預設值）、`test`（測試）。
- **核心影響**：純人工資產分級，**不改變底層規則判定或批次分析行為**，僅用於：
  1. 儀表板重點問題與報表排行的優先度分數（`PriorityScore`）計算：受影響主機包含核心主機時給予 `tierW = 1.2` 加權；一般主機為 `1.0`；僅測試主機為 `0.7`。
  2. 清單與詳情頁的資產徽章顯示。
- **維護方式**：支援單台主機編輯，以及工具列勾選多台後進行「批次設定分級」（`SetTierBatch`）。

### 3. 主機負責人（`OwnerUserIds`）
- 指定一至多位使用者作為該主機的負責人。
- **授權賦予**：被指定為負責人的使用者，即使未加入任何授權群組，登入後自動取得該主機的檢視權，並自動獲得 `Capability.Handle` 與 `Capability.ConfirmPermission` 能力。

### 4. 所屬 Sentinel 與 IP 衝突排除機制
- 記錄該主機所屬的 NetIQ Sentinel 伺服器識別碼。
- **IP 衝突防護**：若在同一個 Sentinel 下偵測到多台主機使用相同的 IP 位址，為確保分析結果具備可預測性，系統**固定鎖定最早建立的那一台主機進行日誌取數**，其餘衝突主機自動標記為排除狀態並在介面上明確提示排除原因。

## 主機合併與解除合併（Host Merge & Tombstone）

- **適用情境**：主機因重灌、更名或網卡更換導致 Sentinel 辨識為新主機，但維運人員希望延續舊主機的歷史分析紀錄與案件。
- **合併機制（Merge）**：
  - 將舊主機（Source）合併入新主機（Target）。
  - 舊主機標記 `merged_into` 墓碑指標並設為停用（`Active = false`）。
  - 查詢新主機時，系統自動將舊主機的歷史主機日與關聯案件一併呈現。
- **解除合併（Unmerge）**：支援誤操作時一鍵解除合併，還原兩台主機的獨立狀態。

## 群組管理與授權矩陣（Group & Authorization Matrix）

頁面包含三個分頁：

### 1. 使用者群組（User Groups）
- 對應企業內部組織（如資訊部、資安維運組、資料庫組）。
- 每個群組指定一個系統角色（`User`、`Dev`、`Manager`、`Admin`）。
- **內建群組防護**：系統內建的 `admin` 與 `manager` 群組受保護，禁止刪除且禁止變更其角色。

### 2. 主機群組（Host Groups）
- 對應主機的分類維度（如依機房位置、依業務系統、依網段）。
- 具備兩大核心功能：
  1. 授權矩陣的受詞目標（決定哪些人可以看見這批主機）。
  2. 告警抑制的範圍對象（對同類主機一鍵批次抑制，免除逐台設定負擔）。

### 3. 授權矩陣（Access Matrix）
- 二維勾選矩陣：列為「一般使用者群組（Role: User）」，欄為「主機群組」。
- 勾選即代表該使用者群組的所有成員可檢視該主機群組內的所有主機。
- **矩陣排除原則**：矩陣中**僅列出 User 角色的使用者群組**。`admin`、`manager` 與 `dev` 角色依系統架構本來就具備 `ViewAll` 能力，可檢視全站所有主機，因此不需要亦不受授權矩陣的勾選約束。

## NetIQ 主動探索匯入流程（Active Discovery Import）

針對透過 NetIQ Sentinel 集中收集的大規模主機環境，提供即時的網段掃描與登錄功能：
1. **探索前置**：於「NetIQ 維護」確認 Sentinel 已建立且具備探索帳密。
2. **網段掃描**：選擇 Sentinel 伺服器，輸入欲探測的網段前綴（例如 `192.168.1` 或 CIDR 格式 `10.0.0.0/24`），發起 `POST /api/admin/netiq/scan`。
3. **有效窗口覆蓋**：掃描僅會辨識出在探測時間窗口內實際有事件回報至 Sentinel 的活躍主機；完全無事件發生的靜態主機需於主機頁手動登錄。
4. **批次指派與套用**：勾選掃描出的主機，指派其所屬主機群組、作業系統（Windows / Linux）與資產分級後送出。
5. **即時落盤（`NetiqImportApplier`）**：後端直接完成新增主機、更新既有主機或復活已停用之孤兒主機，無排隊延遲。
6. **稽核軌跡**：掃描匯入結果自動記錄於「資料匯入」頁面的歷史日誌中。

## 常見問答與邊界狀況（Q&A）

- **Q: 為什麼在主機清單勾選了「批次設定群組」，選擇「取代模式」後某些主機變成了「未分組」？**
  - **A**: 「批次設定群組」提供兩種模式：「加入模式（聯集）」與「取代模式（覆蓋）」。若選擇「取代模式」且在彈窗中沒有勾選任何主機群組，送出後該批主機原本所屬的群組會被全數清空，成為未分組主機。
- **Q: 兩台主機合併後，舊主機在資料庫中會被實體刪除嗎？**
  - **A**: 不會。系統嚴格禁止實體刪除歷史資料。舊主機會被標記 `merged_into = {新主機ID}` 墓碑指標並設為停用狀態，其過去的歷史分析紀錄與案件均完整保留，且隨時可以透過「解除合併」還原。
- **Q: 掃描網段匯入新主機後，為什麼在問題查詢頁查不到這台主機昨天的資料？**
  - **A**: 網段掃描匯入的即時性在於「將主機登錄進主機主檔」。針對該主機的規則比對、頻率趨勢分析與風險判定，必須等待下一次排程作業或手動點擊「立即執行」完成日誌取數與分析後，才會產出對應的歷史紀錄。
