# 系統總覽與登入

LogForesight 分析 Windows Server 的 Event Log 與 Linux 主機的 syslog（經 NetIQ Sentinel 取數），目的是**提早發現硬體故障前兆與入侵跡象**，在問題擴大前示警。

偵測與風險判定完全由確定性的規則／趨勢／慢速趨勢／關聯四層負責；本機 AI 模型只負責把這些結論翻譯成白話，讓不熟 Event Log 的人也能一眼看懂狀況該怎麼處理。**AI 不可用時系統照常運作**——規則命中、趨勢異常、關聯訊號都是程式確定性判定的結果，不依賴 AI。

## 登入

- 正式環境使用 AD 帳密登入（「系統管理 > 設定 > AD 驗證」頁設定 AD 伺服器）。
- 有一組本地救援帳號（`serverAdmin`），AD 停擺或設定填錯把一般使用者擋在門外時，仍可用救援帳號登入處理。救援帳號只有維護與稽核能力，看不到業務資料（總覽儀表板、問題查詢、報表）——這是刻意的最小授權，不是壞掉。
- 帳號或密碼錯誤時，畫面上會顯示明確的錯誤訊息並停留在登入頁；不會因為驗證失敗而整頁跳轉蓋掉錯誤訊息。

## 角色與能力

系統依角色（`user`／`dev`／`manager`／`admin`）決定你能用哪些功能，詳見「授權與角色」一節。**是任一啟用中主機的負責人、或任一問題的負責人**時，即使沒有加入任何群組，登入後也能看見並處理自己負責的主機（問題負責人看得到保留期內出現過該問題的主機；兩者都看不到全站資料）。

## 系統架構（背景知識）

每次分析執行大致走過以下步驟：

1. 讀取 Event Log／syslog，聚合統計
2. 規則標記已知危險訊號
3. 趨勢比對（首次出現、頻率上升自動升級嚴重度）
4. 慢速趨勢（近 7 天總量 vs 前 7 天總量比較）
5. 跨 log 關聯分析（攻擊鏈、故障鏈）
6. 風險等級確定性判定（前面幾層都是程式決定，不靠 AI）
7. 有訊號才呼叫 AI 做白話翻譯
8. 寫入歷史資料庫，於儀表板、問題查詢、排程作業頁示警

分析執行由「系統管理 > 排程作業」頁的排程或手動「立即執行」觸發，兩者行為完全一致，第一次執行就可用（自動回補歷史基準）。詳見「排程作業」一節。
