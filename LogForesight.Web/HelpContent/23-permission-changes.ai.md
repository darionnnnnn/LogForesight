# 權限異動檢核（AI 參考指引）

## 頁面基本資訊

- **頁面路徑**：`/permission-changes`；側欄「監控作業 > 權限異動檢核」。
- **存取權限**：查詢與確認需要 `Capability.ConfirmPermission`（User 與 Admin 角色具備；主機負責人與問題負責人也會隱含取得）。說明書本章對所有登入者顯示。
- **後端端點**：
  - 權限異動清單分頁查詢：`GET /api/permission-changes`，對應 `PermissionChangesController.Query` 與 `PermissionChangeService.Query`。
  - 異動類別字典：`GET /api/permission-changes/categories`，回傳 8 大類別 Key 與中文標籤。
  - 全選待確認項目 ID 清單：`GET /api/permission-changes/ids`。
  - 單筆確認／標記可疑：`PUT /api/permission-changes/{changeId}/confirm`。
  - 批次確認／標記可疑：`POST /api/permission-changes/confirm/batch`。
- **批次操作按鈕**：「標記為授權操作」、「標記為可疑」、「清除選取」；確認視窗按鈕「確認為授權操作」／「標記可疑」。

## 權限異動檢核（Permission Changes Monitoring）

「權限異動檢核」專門用以審核特權帳號提權、群組成員變更、檔案目錄 ACL 調整與稽核政策變動，確保所有特權操作均有跡可循。

### 1. 兩個偵測來源（Source）
- **`本機監控`（`local`）**：
  - 由 `PermissionMonitorService` 直接對執行 LogForesight 服務之主機的本機 Administrators 群組與監控資料夾（`WatchedFolders`）ACL 快照進行比對。
  - **時間戳特性**：記錄的時間為**系統比對快照時的偵測時間**，而非實際變更發生的時間。
- **`NetIQ 事件`（`netiq`）**：
  - 由機房 Windows 主機當日之 Security 事件日誌推導（包含 Event ID 4728/4732/4756 成員加入、4729/4733/4757 成員移出、4670 ACL 變更、4907 稽核變更、4717/4718 權限指派、4719 稽核原則變更等）。
  - **時間戳特性**：記錄的時間為**事件發生的原始時間**。

### 2. 八大異動類別（`PermissionCategory`）

| 類別 Key | 中文標籤 | 涵蓋事件與特徵 |
|---|---|---|
| **`group_member`** | 群組成員異動 | 特權群組或本機群組之成員新增／成員移除。若加入特權群組（如 Administrators），自動標記**紅色「高風險」**徽章。 |
| **`folder_acl`** | 資料夾權限異動 | 檔案或資料夾之存取控制清單（ACL）規則新增、移除或變更（4670 且物件為檔案/目錄）。 |
| **`object_acl`** | 物件權限變更 | 非檔案/目錄類之系統物件權限變更（4670 且物件為 Token、登錄機碼 Registry 等）。 |
| **`owner_change`** | 擁有者變更 | 檔案、資料夾或系統物件之擁有者被更換。 |
| **`folder_access`** | 資料夾存取狀態 | 監控資料夾出現無法存取或恢復可存取之狀態變更。 |
| **`audit_policy`** | 稽核政策變更 | 系統稽核原則被修改或關閉（4717/4718/4719/4907）。 |
| **`summary`** | 例行同步彙總 | 例行同步合併列（見下文）。該列的 change_type 是「例行同步（彙總）」；舊資料列可能還存著已不再產生的舊值「權限異動（彙總）」，兩者都歸入本類別。 |
| **`other`** | 其他 | 無法歸類於上述類別時之通用退路。 |

### 3. 例行同步合併機制（Routine Sync Pair Collapse）
- **背景**：企業 AD 自動化腳本（如每日定時先清空再重建群組成員的同步作業）會在短時間內產生數萬筆對稱的加入與移出事件，導致審核清單被淹沒。
- **合併規則**：
  - 在同一主機日內，針對相同 (帳號, 群組) 之「成員新增」與「成員移除」配對。
  - 當成對數量達到 **50 對** 時，系統將該批對稱異動自動合併為單一筆「**例行同步（彙總）**」（類別為 `summary`），並標註涵蓋時段與對數。
- **特權群組不合併原則（絕對安全防線）**：
  - 若異動涉及特權群組（如 Administrators、Domain Admins 等），**即使成對出現也一律逐筆列出，絕不合併**，防止攻擊者藉由偽造同步掩蓋提權軌跡。

### 4. 展開明細的「原始訊息」區塊
- 每一列可點擊展開，展開內容的**最下方**會顯示該筆異動的原始事件訊息（等寬字、保留換行、超過高度可捲動）。
- **三種情形**：
  1. 升級後新寫入的逐則列 → 顯示**未截斷的完整原文**（`raw_text` 欄位），標題為「原始訊息」。
  2. 升級前寫入的舊資料 → `raw_text` 為空，退而顯示 500 字截斷版的告警文字，
     標題會明白標註「僅存前 500 字，此為本次升級前寫入的資料」。**舊資料不會被回填全文**，
     要拿到完整原文只能重新取數。
  3. 例行同步彙總列 → 它代表多則異動合併後的結果，沒有單一原文可對應，
     標題會說明這點，區塊內顯示的是合併說明。
- **安全處理**：原始訊息是來自事件日誌的外部輸入，一律以純文字呈現，
  不解析任何 HTML 標籤、也不做 Markdown 渲染——這裡要的是一字不改照實顯示。
- **保留期**：原始訊息隨權限異動紀錄一同清理，受「稽核與追責紀錄保留天數」控制，沒有獨立的設定項。

### 5. 異動說明文字生成規則（Summary Text）
- 句型結構固定為：**「操作者 → 動作 → 對象」**（例如 `admin_ad 將 user01 加入群組 Administrators`）。
- **被動句型**：若事件無操作者紀錄（如本機監控快照），自動改用被動句（如 `user01 被加入群組 Administrators`）。
- **帳號短名化**：AD 之完整辨別名稱（DN）過長，句子中一律顯示短名（如 `user01`），滑鼠懸停 Tooltip 或點擊展開列可檢視完整 DN。

## 審核操作與批次核准（Batch Approval）

### 1. 四種審核狀態頁籤
- `待確認`（未審核）、`已確認授權`（合規變更）、`標記可疑`（資安疑慮）、`全部`。

### 2. 批次核准作業流程
1. **縮小範圍**：利用關鍵字、網段（支援 CIDR 如 `192.168.1.0/24` 或萬用字元 `192.168.1.*`）、類別、來源或時間進行篩選。
2. **項目選取**：
   - 勾選當頁項目（表頭支援全選）。
   - 點擊「全選符合目前篩選的權限異動」：呼叫 `GET /api/permission-changes/ids` 一次選取所有符合當前篩選條件之待確認項目（具備上限防護，超過上限提示分批處理）。
   - **跨頁保留選取**：切換分頁時，已勾選的項目會完整保留。
3. **預覽確認**：彈出確認視窗，按「類別」與「主機」分組展示選取清單。
4. **標記可疑強制原因**：若選擇「標記可疑」，**系統強制要求必須填寫調查原因與說明**。
5. **部分成功容錯**：送出後若部分項目已被其他管理員處理，系統會將其略過並在回傳中列出原因，其餘項目正常確認完成。
6. **專屬稽核日誌**：批次操作會寫入動作代碼為 `perm_confirm_batch` 之專屬稽核紀錄。

## 兩大關鍵注意事項

1. **確認狀態不可逆**：一旦將異動標記為「已確認授權」或「標記可疑」後，**系統刻意不提供改回「待確認」之功能**。待辦清單必須忠實反映未審核之事實；若事後發現誤判，應再次變更為另一種審核結論或於稽核日誌中加註。
2. **時間戳語意差異**：「本機監控」來源之時間為**快照偵測時間**；「NetIQ 事件」來源之時間為**事件真實發生時間**。

## 常見問答與邊界狀況（Q&A）

- **Q: 為什麼在權限異動檢核清單中，找不到一般使用者的檔案讀取或登入紀錄？**
  - **A**: 權限異動檢核專注於「權限與組態變更」（特權群組異動、ACL 變更、稽核政策修改），不記錄日常的資料讀取或正常登入事件，以確保資安審核人員能專注於特權異動風險。
- **Q: 為什麼某些列展開後，異動前後的值顯示為「（訊息未提供）」？**
  - **A**: 某些 Windows 事件（如 4719 稽核原則變更）在特定作業系統版本或日誌層級下，事件文字中並未包含變更前後的詳細數值。系統在此情況下會誠實申報「（訊息未提供）」，而非留白或填寫猜測的假資料。
- **Q: 網段篩選支援哪些格式？**
  - **A**: 支援三種標準格式：(1) 標準 CIDR 格式（如 `192.168.1.0/24`）、(2) 萬用字元格式（如 `192.168.1.*`）、(3) 單一精確 IP 位址（如 `192.168.1.50`）。輸入無效格式時，錯誤提示會直接顯示於輸入框下方。
