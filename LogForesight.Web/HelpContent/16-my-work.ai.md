# 我的交辦：三分鐘上手（AI 檢索版）

本章用於回答處理人如何查看、回覆與連續處理交辦單。回答時應先確認使用者問的是整張交辦單或其中幾台主機，並提醒使用者送出前核對選取範圍。

## 從哪裡開始
只有處理能力、沒有任何管理或全站檢視能力（沒有 Maintain、Assign、ViewAll，且不是 serverAdmin）的帳號，登入後會進入「我的交辦」；有 DevMonitor、沒有 Handle 也沒有 Assign 的帳號（開發維運）進「排程作業」；其餘帳號登入後進儀表板。
若由通知連結登入，系統會先返回原本要開啟的頁面。
側欄「我的交辦」只對具 `Handle`（處理能力：User 角色、Admin，以及隱含 User 角色的主機／問題負責人）的人顯示；serverAdmin 救援帳號也不顯示。
Manager、Dev 沒有處理能力，沒有這個導覽項目；自己開 `/handlers/{自己的編號}` 時，頁面顯示「你的角色沒有處理能力」，說明「交辦單只會派給有處理能力的人，所以這裡不會有內容。需要處理交辦時，請管理者調整你的群組角色。」這不是「沒有被指派的工作」。
使用者說側欄找不到「我的交辦」時，先確認他的角色有沒有處理能力。
頁面上方有兩排 KPI（`GET api/handlers/{userId}/work-orders/summary`）。
第一排「今天需要你處理」：今天新增（台，成員建立日是今天）、復發（台）、被退回（件）、觀察到期（台）、3 天內到期（件，處理中成員期限在今天到今天＋3 天、已逾期的不算）。大於 0 的卡可點：就地套用標記篩選、狀態切到「進行中」，清單上方顯示「只看：…」橫幅與「清除」鈕，網址帶 `?status=active&flag=…`；0 的卡淡化且不可點。
第二排「目前存量」：進行中單、待我處理、觀察期內、上報中、逾期台數、未回覆單。「待我處理」（進行中、非上報中、非觀察期內；觀察到期算在這裡）＋「觀察期內」＋「上報中」＝進行中台數。
狀態篩選預設「待我處理」，排序預設「處理優先序」（依序比：有被退回的、有逾期的含觀察到期、嚴重度高到低、期限近到遠且無期限最後，其餘依建立時間；期限以日曆日計）；另有「期限最近」「嚴重度」「最新建立」「成員最多」「最久未回覆」。網址的 `status`、`sort`、`flag` 優先於預設。
頁面頂端的「清單有更新」＋「重新載入」：側欄徽章的既有輪詢發現自己進行中的台數或單數與載入時不同才出現，不是新輪詢。
清單欄位：單號、問題（其下標記「新 N」「退回 N」「觀察到期 N」，0 不顯示）、嚴重度（含「重大」，推導不到「—」）、主機（「進行中 N 台；歷來 M 台、K 件」，台＝不重複主機、件＝成員〔主機×問題〕；復發的標「復發 N」）、逾期、未回覆、期限、回覆。
夜間新派的單依嚴重度帶預設期限（高 3 天、中 7 天、低不帶；程式常數）；上線前建的單與成員沒有期限、不回填；回覆「處理中」而不填日期時，目前就是處理中的成員保留原有期限。
先處理被退回、逾期的工作，再依實際影響安排順序。

## 看懂一張交辦單
一張交辦單可包含同一問題的多台主機。
「主機」欄顯示進行中台數與總台數，不代表每台都已修好。
點單號可看完整說明與歷程。
列上的「回覆」一律開回覆表單：對象預設「全部進行中主機（N 台）」（送出時 `caseIds` 為空）；只剩一台時對象是那一台；0 台不開表單並提示「這張單已沒有進行中的主機」。
表單內「只回覆部分主機」切到就地面板：可搜尋主機名，或貼上多個主機名（換行、逗號、空白分隔），貼上後自動勾選、不必按鈕；找不到的名稱列在面板內，勾選跨頁保留並顯示「已選 N 台」。
另一條路徑：點列展開成員表（有主機名搜尋、狀態篩選），勾選後按「回覆選取的主機」。主機名搜尋是完全相符、不分大小寫，輸入完整主機名後按 Enter、回到第一頁；勾選以「已選 N 台」顯示，換頁與搜尋都保留，只有改狀態篩選才清除。進階檢視的「依主機」也有同樣的「主機名」搜尋（完全相符、按 Enter）。
不要把只處理好三台的說明套用到整張九十六台的單。

如果交辦單連到風險日問題詳情，點問題列展開，在「來源觀測」核對已儲存的來源佐證；未儲存的主機、資源或時間會標為「未知」，不要從分組時段推測。若你僅透過交辦單獲准查看該主機，授與範圍只有被交辦的問題，不含主機整體的 PRTG 資訊（主機詳情的「PRTG 監控對應」卡），也不含任何管理權限。

## 更新處理結果
選擇要回覆的主機或交辦單，按回覆。
「這次的結論」是一排單選按鈕，**不預選**；沒選時送出鈕停用並提示「請選擇這次的結論」。選「處理中」時送出鈕寫「更新說明（不結案）」。再貼上或輸入處理說明。
「觀察中」需填「預計完成日／觀察至」（日期欄；有「3 日」「7 日」「14 日」快捷，預設 7 日）；「不處理」與「無法處理」需填理由。
只回覆部分主機並選結案類結論（已處理、不處理、誤報、已知雜訊）時，結論下方多一段「其餘 N 台一起設為…（選填）」：選了結論（觀察中帶日期快捷）再按一次「送出」，系統依序送出勾選的與其餘的（其餘等於對全部進行中主機，`caseIds` 為空，說明沿用同一份），兩次都成功才關閉並出一則合併訊息；其餘那次失敗時表單不關，改問「其餘 N 台要一起設為…」並保留已選的結論與日期。其餘選到不處理類（不處理、誤報、已知雜訊）時，其餘那一段多一行與主結論同款的後果提醒（其餘 2 台以上用複數說法，滿 30 天會解除的問題改寫成 30 天內不再派工），取消選擇或其餘區收起時一起隱藏。沒選其餘結論時，勾選的送出後若單上還有進行中主機，表單留著並問「其餘 N 台要一起設為…」；第一次回的是處理中或觀察中時不出現。
部分主機面板載入失敗（第一頁、換頁、篩選或貼上清單）時，面板內常駐一行「主機清單載入失敗，請再試一次。」，下一次成功載入就清掉。送出被拒（400、403）時，面板清單重新載入目前這一頁，勾選以伺服器現況為準（已不在進行中的主機取消勾選，含不在目前頁的勾選），已選台數與「其餘 N 台」跟著更新。
成功提示寫出結論：「已回覆 N 台為已處理」「N 台改為觀察中，至 12-01」「已更新 N 台的說明（仍為處理中）」。
回覆被拒（單剛改派 403、單已結案或成員已不在進行中 400）時，訊息常駐到使用者關閉，說明留在草稿；403 時訊息寫「這張單剛改派給 X，你的說明仍保留在草稿」並可複製說明；同時自動重新載入單頭、成員表、清單與 KPI。
鍵盤：結論按鈕群組以方向鍵切換，說明欄 Ctrl／⌘＋Enter 送出，Esc 關閉並保留草稿。
選不處理類（不處理（評估後決定）、誤報、已知雜訊）時，表單多一行提醒：「這台主機的這個問題之後不會再派給任何人；需要恢復請找管理者。」處理人回覆不處理類一律停派，沒有選項；管理者從交辦總覽「待派」頁籤下方的「不再自動派工」區恢復。
說明請寫實際做過的動作、查到的原因及仍待確認的事項。
同一批主機都做了相同處理時，可一次套用相同說明。
不同問題或不同處置方式應分開回覆，避免誤導接手者。
送出前再次確認選取的範圍與狀態。

## 復發與觀察到期
復發（讀取時推導）：同主機同問題的上一件案件以「已處理」結案、結案日距本件建立不超過 30 天（第 30 天算、第 31 天不算）；不處理類結案、已取消、沒有上一件都不算。成員表在狀態旁標「復發 N 次」與上一次的回覆（日期、狀態、說明）；「全部」篩選下同主機的舊案件標「第 N 次」。
回覆對象含復發主機時，表單頂端提示並排出三個建議：「還在處理（設預計完成日）」、「觀察 7 日」、「請管理員評估調整規則或靜音」（選「無法處理」並預填「重複發生，請評估調整規則或靜音」，已有說明不覆蓋）。選「已處理」不擋。同主機同問題 30 天內第 3 次復發，管理員在「交辦總覽」提醒區看到「反覆結案又復發」。
觀察中的成員附「觀察期間再發生 N 天」「沒有再發生」或「無資料」（觀察期間沒有任何分析紀錄；不等於沒有再發生）。交辦單頁頂端的「把到期且沒有再發生的 N 台結案」（觀察到期且確定沒有再發生的成員；無資料與有再發生的不含）先確認，再以「已處理」、說明「觀察期滿未再發生」送出；不自動結案。

## 草稿與 AI 整理
未送出的文字會在此瀏覽器儲存草稿，仍應確認畫面提示。
主動登出會清除自己的草稿；不要把草稿當成正式處理紀錄。
AI 可用時，說明欄提供「AI 整理」。
它整理你提供的內容，不會替你補上沒做過的處置。
整理後先核對內容，再送出；需要時用「復原」回到整理前文字。
AI 整理不等於儲存，也不會自行結案。
「常用語」、「帶入上一張的說明」可以節省輸入，帶入後仍須逐筆核對。

## 連續與批次處理
翻頁時可保留選取；改變篩選條件會清除選取並提示。
批次回覆前確認已選張數，包括其他頁面選取的單。
若只成功一部分，依提示確認失敗與未處理的單，再重送。
「送出並回覆下一張」會接續下一張可處理的單。
下一張若有多台主機，先選擇對象，不會直接替整張單結案。
部分主機以結案類結論搭配「送出並回覆下一張」時，表單不停下來問其餘，改提示「其餘 N 台尚未處理，這張單之後還會再出現」，且這張單不計入本次已處理（「下一張」之後仍會回到它）。
可在期限欄調整預計完成日（有期限時點日期旁的鉛筆鈕，沒有時點「設定期限」），這不會改變處理說明與狀態。375px 手機寬度只顯示勾選框、問題與「回覆」鈕，單號、成員數、逾期、未回覆、期限收成問題欄底下一行。

## 找不到工作時
「目前沒有待我處理的交辦單」表示預設的「待我處理」篩選是空的、但還有觀察期內或上報中的單（畫面寫出台數），改選「進行中」可看到。
「你可以看到的主機目前有 N 個未處理問題（影響 M 台）」表示沒有交辦單、但可見範圍內有未處理問題，附「查看未處理問題」連到問題查詢。
「目前沒有被指派的工作」表示目前清單沒有待辦。
「尚未被授權任何主機」表示需要管理員協助設定授權。
「你的角色沒有處理能力」表示自己的角色（Manager、Dev）不處理交辦單，頁面不會有內容，不要當成沒被指派。
找已完成的工作時，把狀態篩選改成「已結案」或「全部」。
通知連結失效、工作已改派或無權查看時，返回「我的交辦」確認。
處理人會收到的交辦通知（「交辦單通知」開啟時，依交辦摘要時刻彙整成一封）除了新交辦、新增成員、移交、取消、退回，還有「代為結案」（管理者替你結案，信裡寫結案狀態、原因與問題再出現時會不會重新派工）、「靜音暫停」（問題被靜音、單暫停，寫迄日與原因）、「靜音恢復」（靜音提前解除，請繼續處理）。改派或拆出併進你已有的同問題單時，信裡是「新增成員」。退回段附「只看被退回的單」連結（`?flag=returned`），打開「我的交辦」後清單直接套用該篩選並顯示可清除的橫幅；新交辦、新增成員不帶篩選，連結直接指向「我的交辦」（這類信常在隔天早上才寄，帶「今天新增」會是空清單）。信件有「連結」行是因為管理者設定了系統設定的「站台網址」，連結指向你的「我的交辦」；沒設就沒有連結，請從站台進入。
各種通知信的意義與要不要回覆（對照信件現行文字）：「取消」是管理者取消整張單，其中的主機已調回未處理，處理人不必回覆，問題若仍出現夜間派工可能重新派工；「移交」是部分主機改由其他處理人負責，移出的主機不必再處理、也不必回覆；「退回」是管理者把處理人標為「無法處理」的主機改回處理中，要重新處理並回覆；「新交辦」「新增成員」「靜音恢復」同樣需要處理。信裡只含不需動作的種類（代為結案、取消、移交、靜音暫停）時，結尾寫「這些單不需要你再回覆」。
處理人頁頭出現「目前暫停接單」表示帳號被設為暫停接單：夜間自動派工不會再派新單給他，既有交辦單不受影響；本人與管理者都看得到。這和「只看暫停的單」（問題被靜音的單）是兩件事。設定與取消在「使用者」頁，需要 `Maintain`；使用者說沒收到新派工時，先確認是否暫停接單。
遇到載入失敗應重試或聯絡管理員，不要把失敗畫面當成沒有問題。
