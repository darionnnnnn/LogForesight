# 這次更新後你會看到的變化（AI 參考指引）

本章回答「這一波更新後，數字與按鈕哪裡不一樣」。回答時先分清使用者問的是數字口徑、回覆表單、交辦預覽，還是上線當天的現象，再引用對應章節（「我的交辦」「處理狀態與交辦單」「總覽儀表板」「群組與授權」）。

## 數字口徑
- 交辦單的「台」＝不重複的主機數；「件」＝成員（主機×問題）數。同一台主機結案後再發生是新的一件，件數可能大於台數。畫面寫「進行中 N 台；歷來 M 台、K 件」（歷來同進行中時寫「歷來同」）。停用主機上的成員不計入。
- 「待我處理」＝進行中、非上報中、非觀察期內的主機（觀察到期算在這裡）；與「觀察期內」「上報中」三者互斥，相加＝進行中台數。我的交辦的狀態篩選預設「待我處理」，所以預設看不到觀察期內與上報中的單，要改選「進行中」。
- 我的交辦「今天需要你處理」五個數字：今天新增（台）、復發（台）、被退回（件）、觀察到期（台）、3 天內到期（件）；點有數字的卡套用對應篩選。存量（進行中單、待我處理、觀察期內、上報中、逾期台數、未回覆單）是次要一排。
- 儀表板「待派工問題」與交辦總覽「待派」頁籤：最近出現日已被處理人結案的主機整筆不再計入，立即派工也不會為它們建單；之後有未結案的新出現日才回到待派。卡片數字＝「可以派」＋「派不出去」兩段的問題數，副標分開寫；「不會派」（嚴重度未達、不再打擾等）不計。
- 儀表板「未處理問題」卡：影響台數與問題查詢下鑽的主機數同定義；風險日分成「未處理 X、處理中 Y」。
- 問題查詢處理概況另列「N 台預設不處理」，不與「已處理」合計。風險日詳情顯示範圍三選項：待處理／全部（含已完成）／只看已完成，計數＝列出筆數，沒有收合區。
- 報表「未結案」拆三段（在處理人手上、待派、不需處理），主機日相加等於未結案主機日。
- 問題名稱全站同一出口：事件編號 0 只寫來源（恰好一條規則命中時附規則名稱）；已存在交辦單上的名稱不回寫，顯示時重新產生。
- 交辦總覽未讀徽章只對具 Assign 者顯示。處理人頁數字不含靜音暫停的單，負載看板含，兩處都有口徑說明。

## 按鈕與畫面
- 回覆一律開回覆表單（清單列的「回覆」、交辦單頁的「回覆這張單」、問題查詢依問題視角的回覆）：對象預設全部進行中主機；「只回覆部分主機」可搜尋、貼上多個主機名自動勾選、跨頁勾選。
- 「這次的結論」不預選，未選時送出鈕停用；選處理中時送出鈕寫「更新說明（不結案）」；觀察中有 3／7／14 日快捷，預設 7 日。
- 部分主機回覆為結案類後，單上若還有進行中主機，表單問「其餘 N 台要一起設為…」；回覆非結案類（處理中、觀察中）時不續問。
- 回覆被拒（單剛改派、已結案、成員已不在進行中）時訊息常駐，說明留在草稿；畫面自動重新載入單頭、成員表、清單與 KPI。
- 管理者交辦預覽：主機表格有狀態欄；已結案與「先前判定不處理」的主機預設不勾、略過，逐台勾選才重新交辦（勾選不再打擾的主機等於恢復它）；預覽寫略過台數、「N 台不在對方的檢視範圍」；處理人名單標進行中台數與「沒有 email」；「預計完成日（選填）」依嚴重度預填（高 3 天、中 7 天），可清除。
- 我的交辦與交辦總覽多了「嚴重度」欄與標記（新、復發、退回、觀察到期）；我的交辦排序預設「處理優先序」；另有「期限最近」「嚴重度」。
- 頁面頂端「清單有更新」＋「重新載入」：側欄徽章的既有輪詢發現自己進行中的台數或單數變了才出現，不是新輪詢。
- 儀表板「未回報主機」卡：沒有 `Maintain` 的角色不可點，提示文字列出可見範圍內最多 5 台未回報主機名。
- 管理者提醒區新增「今天新上報」（只在畫面顯示、不寄信）與「反覆結案又復發」（同主機同問題 30 天內復發達 3 次，也進摘要信）。
- 授權矩陣每勾一格只儲存那一格（增減式寫入，兩位管理員同時改不會互相覆蓋）。

## 第二、三波的畫面與按鈕
- 儀表板頂端「需要你處理」列（Assign）：取數失敗、今天新上報、上報逾期、可派未派、派不出去、沒有收件人、處理人停用或暫停仍有單、反覆復發、未分組主機；全部為 0 收成一行。
- 待派頁三段；「立即派工」與「派這個問題」先預覽再確認；沒有新成員時訊息「沒有需要派的項目（可能剛由其他人派出）」；「沒有人看得到」的主機群組去重並可就地「授權給…」（Maintain）。
- 交辦總覽：勾選多張「改派給…」（預覽→「確定改派 N 張」，最多 100 張，逐張回報）、處理人篩選、負載看板「改派他名下的單…」；停用或暫停接單前先顯示名下張數，可「一併改派」。「不再自動派工」區預設收合、展開才載入；「靜音中」頁籤點到才載入。
- 問題查詢「更多」：「不再顯示這個問題…」（三問句）、「調整這條規則」；比較表「不再顯示這個問題：選哪一種」；單一風險層級篩選時其他層級顯示「—」。
- 交辦單頁：處置參考與訊息樣本、三個捷徑、代為結案範圍（全部進行中／只有上報中的／勾選的成員）、成員登錄類型。主機詳情「這台的交辦」可一次回覆多個問題。頁頂主機搜尋（名稱或 IP）。
- 風險日詳情：來源觀測白話與當地時間；處理人列出各交辦單；處理狀態徽章可換行。
- 規則「試算」、執行總表每日結論與「補跑這些主機」、報表「下載 CSV」、權限異動「展開原文」、稽核動作分組與搜尋、owners.csv 預覽的新帳號提醒。
- 使用者編輯視窗一次送出、即時摘要、衝突提示；「暫停接單」只對派工池成員顯示。主機群組清單「看得到的派工池群組」欄。
- 設定頁「派工」頁籤（自動派工開關搬來）、AI「測試連線」；系統健康「派工就緒」卡與 AI 連線原因；AI 窗口未設定的明確提示；AI 失敗後互動功能冷卻 60 秒。

## 上線當天會看到什麼
- 高嚴重度或重大的問題，處理人判定不處理滿 30 天（第 31 天起）仍在發生就重新派工，新單成員標「先前判定不處理」。上線前（生效日 2026-11-25 前）就結案的不自動恢復，清單標「上線前判定」。
- 新站台第一次打開系統健康，「派工就緒」可能列出多項未通過，整體狀態同時寫出原因，這是預期。
- 上線前就有的交辦單與成員沒有期限，不回填、不會變逾期；上線後夜間新派的單依嚴重度帶期限（高 3 天、中 7 天、低不帶）；續掛進既有單的成員沿用單的期限，單沒有期限才依嚴重度帶。
- 復發（同主機同問題的上一件以「已處理」結案、30 天內又出現）為讀取時推導：成員表標「復發 N 次」與上一次回覆，單頭寫「其中 N 台是復發」，我的交辦列標「復發 N」。不重開舊案件；不處理類結案不算復發。
- 觀察到期的成員表寫「觀察期間再發生 N 天」「沒有再發生」或「無資料」；單頭「把到期且沒有再發生的 N 台結案」只含確定沒有再發生的成員，不自動結案。
- 登入落點：只處理交辦的帳號進「我的交辦」；開發維運（有 DevMonitor、沒有 Handle 也沒有 Assign）進「排程作業」；其他進儀表板。開發維運在排程作業頁不再送需要維護權限的請求，PRTG 設定相關欄位顯示「需要維護權限才能檢視」。

## 常見問答
- **為什麼台數比以前小？** 台數改成不重複的主機數，同一台主機的多件只算一台；件數另外顯示。
- **為什麼我的交辦清單看不到觀察中的單？** 預設篩選是「待我處理」，觀察期內的單不在其中；改選「進行中」。
- **舊單為什麼沒有期限？** 既有案件不回填期限，避免上線當天出現大量逾期；要的話處理人在單上點「設定期限」。
