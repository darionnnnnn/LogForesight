# 問題事件（AI 參考指引）

## 頁面基本資訊與存取架構

- **頁面路徑**：`/records`（左側主選單標籤為「問題查詢」）。
- **存取權限**：所有已登入角色（`user`、`dev`、`manager`、`admin`）均可存取。查詢結果全面經 `IVisibilityService` 資料過濾，使用者僅能查出被授權或其所負責主機的事件紀錄。
- **後端端點**：
  - 明細視角查詢：`GET /api/records`，對應 `RecordsController.Search` 與 `RecordListQueryService.Search`。
  - 依主機彙總查詢：`GET /api/records/by-host`，對應 `RecordsController.ByHost` 與 `RecordListQueryService.SearchByHost`。
  - 依日期彙總查詢：`GET /api/records/by-date`，對應 `RecordsController.ByDate` 與 `RecordListQueryService.SearchByDate`。
  - 依問題彙總查詢：`GET /api/records/by-issue`，對應 `RecordsController.ByIssue` 與 `RecordListQueryService.SearchByIssue`。
  - AI 查詢歸納：`GET /api/ai/query-summary`，對應 `AiController.QuerySummary` 與 `AiInsightService.SummarizeQueryAsync`。
  - 單筆歷史比對：`GET /api/records/{hostId}/{date}/handling/issue-history?issueKey={key}`，取得指定簽章在該主機的過往處理歷史。

## 篩選條件與控制項語意

篩選表單（`#records-filter`）支援多維度精確過濾：
- **主機篩選（`hostIds`）**：支援伺服器端即時搜尋與 autocomplete（`GET /api/hosts?query={q}`，上限 20 筆），選取後以晶片（Chip）呈現，可複選與單獨移除。
- **主機群組（`groupIds`）**：可選取登入者有權檢視的主機群組。
- **日期區間（`from` / `to`）**：支援日期選取或期間快捷按鈕（「昨日」、「近 7 天」、「近 30 天」、「近 90 天」）。
  - **結束日期錨定原則**：所有快捷按鈕的結束日期一律設定為**昨天**（`DateTime.Today.AddDays(-1)`），避免夜間批次尚未分析的今日造成末日空資料。
- **Event ID（`eventId`）與來源（`source`）**：精確縮小至特定事件訊號（如來源 `disk`、Event ID `7`）。
- **嚴重度／風險等級**：
  - 在「明細」、「依主機」、「依日期」視角下，過濾的是**「日風險等級（`riskLevels`）」**。
  - 在「依問題」視角下，標籤自動切換為**「問題嚴重度（`severity`）」**，過濾的是問題本身的嚴重度（高／中／低），兩者定義不同。
- **問題類別（`categories`）**：多選下拉選單（儲存裝置、硬體、安全、服務、備份、設定、資源、其他）。
- **處理狀態（`statuses`）**：過濾未處理（`unhandled`）、處理中（`in_progress`）、已處理（`resolved`）或特定結案原因。
- **特定標記開關**：
  - `未指派（unassigned）`：僅列出尚未指派處理人的紀錄。
  - `逾期（overdue）`：僅列出已超過預計完成日期的未結案項目。

## 四種檢視視角（Tab Views）

### 1. 明細視角（Details）
- **聚合粒度**：以「主機 × 日期（`HostId + Date`）」為單一列。
- **呈現內容**：主機名稱（含 IP）、日期、日風險等級徽章（高/中/低）、重點問題摘要標題、頻率趨勢註記（首次出現/頻率上升等）、處理狀態與指派人員。
- **互動**：點擊任一列直接跳轉至該主機該日的「風險日詳情（`/records/{hostId}/{date}`）」頁面。

### 2. 依主機視角（By Host）
- **聚合粒度**：依主機分組，合併查詢期間內的所有日期。
- **呈現內容**：主機名稱、所屬群組、期間最高日風險等級、觸發問題總數、累計風險主機日數與最後回報時間。

### 3. 依日期視角（By Date）
- **聚合粒度**：依日期分組，合併該日所有受影響的主機。
- **呈現內容**：分析日期、受影響主機總數、當日高／中／低風險主機分佈比例與當日重點事件彙整。

### 4. 依問題視角（By Issue，跨主機跨日彙總）
- **聚合粒度**：將同一個問題簽章（Windows 依 `Source + EventId`，Linux 依 `Source/Program`）跨主機、跨日期聚合為單一列。
- **排序原則**：固定依**「問題嚴重度（High > Medium > Low） → 總次數」**降冪排序，**刻意不受儀表板的 `PriorityScore` 影響**，保持客觀統計分析視角。
- **白話說明列（Summary）**：
  - 命中規則庫時，直接呈現規則庫預設的中文白話說明；文字過長時自動截斷，滑鼠懸停顯示完整 Tooltip。
  - 若無說明，欄位會明確標註原因：顯示為「其他」類別代表未命中任何規則（可至規則維護頁新增規則）；其餘情況代表命中之規則尚未填寫白話說明。
- **問題檔案連動（Issue Profile）**：若該問題在「系統管理 > 問題檔案」設定了負責人或機房結論，問題名稱旁會附上負責人徽章與自動套用狀態。

### 依問題視角之欄位定義

| 欄位名稱 | 意義與計算口徑 | 介面呈現細節 |
|---|---|---|
| **問題** | 問題來源（Source）與 Event ID（Linux 僅顯示來源名稱，不顯示 `(0)`） | 附帶嚴重度徽章、類別標籤、白話說明與問題負責人 Badge |
| **主機數** | 查詢期間內曾出現該問題的**相異主機台數** | 數字呈現 |
| **總次數** | 查詢期間內所有受影響主機累計觸發的事件次數加總 | 數字呈現（與主機數為正交維度） |
| **出現密度** | `出現天數 ÷ 查詢總天數` | 顯示分數（如 `28/30 天`）與視覺化進度條。比例高代表日常背景雜訊，比例低代表突發或零星異常 |
| **vs 基準** | 機房 30 天每日影響台數中位數 vs 最近一次影響台數之偏離倍數 | 第一行顯示「基準 N 台/日 → M 台」<br>第二行顯示倍數徽章：<br>・≥ 2.0：紅色「擴散」<br>・1.0 ~ 2.0：灰色「正常」<br>・< 1.0：綠色「收斂」<br>・不足 3 天：灰色「新問題，無基準」 |
| **首見** | 該問題在全機房歷史第一次出現的日期（不受查詢區間截斷） | 若「本期首見日」與「機房首見日」不同，下方會額外標註「本期 mm-dd」及圖示 |
| **處理概況** | 受影響主機的處理狀態分佈統計 | 垂直分為未處理／處理中／已處理三行（數量為 0 者淡色顯示以保持列高度一致） |

### 主機數口徑與儀表板對齊
- 列表上方會顯示**「共 N 台主機（去重）」**。
- **澄清**：依問題列表中每一列的「主機數」是該問題獨立影響的主機數。各列主機數直接相加會大於儀表板風險類型卡片的主機數，因為同一台主機可能同時存在多個問題。頂端的去重數字才是與儀表板同口徑的真實台數。

## 附加分析與批次處理功能

### 1. 複製為 CSV（Copy as CSV）
- 點擊工具列「複製為 CSV」按鈕，前端自動將目前篩選條件下的查詢結果格式化為逗號分隔文字並寫入剪貼簿，可直接貼入 Excel 進行二階段處理。

### 2. AI 查詢歸納（Query Summary）
- 當全站 AI 服務可用時顯示「AI 歸納」按鈕。
- 後端將當前查詢結果中出現的簽章進行跨主機聚類（`ClusterSignatures`），呼叫 LLM 生成一段白話總結，概括這批結果中最重要的風險聚合點。AI 離線時按鈕自動隱藏。

### 3. 跨主機批次指派與統一標記
- 在「依問題」視角下，具備 `Capability.Assign` 權限的管理員可對特定問題發起跨主機操作：
  - **批次指派（`BulkAssignIssueCase`）**：將該問題在多台受影響主機上一次建立跨日案件並指派給指定處理人。
  - **統一標記（`BulkCloseIssue`）**：將尚未有人接手的主機一次標記為指定機房結論（如已知雜訊），避免逐台點擊。

## 與「風險日詳情」的職責邊界

- **問題查詢頁（`/records`）**：跨主機、跨日期的搜尋與聚合檢視入口，回答「符合特定條件或特徵的問題有哪些、分佈在哪些主機」。
- **風險日詳情頁（`/records/{hostId}/{date}`）**：單一主機、單一日期的深入下鑽入口，回答「這一天該主機到底發生了什麼、時序脈絡為何、AI 建議如何處置」。

## 常見問答與邊界狀況（Q&A）

- **Q: 為什麼在「依問題」視角勾選「高嚴重度」，查出來的某些主機日卻是「中風險日」？**
  - **A**: 「依問題」視角的篩選條件是「問題嚴重度（Issue Severity）」，而非「日風險等級（Day Risk Level）」。一個高嚴重度的問題若發生在某一天，但其本身並非帶重大旗標的規則（例如單次 4625 登入失敗未達 10 次門檻），當天的整體日風險等級可能判定為中風險日。
- **Q: 為什麼點擊「AI 歸納」後顯示「目前條件無可歸納之重點」？**
  - **A**: 若當前篩選條件下的所有問題均為低嚴重度且無頻率異常，聚類演算法在過濾後若無任何具備顯著風險的簽章，會直接回報無重點，以避免消耗不必要的 AI Token 資源。
- **Q: 查詢條件設定完成後，重新整理頁面或複製網址給同事，篩選條件會保留嗎？**
  - **A**: 會。問題查詢頁會將所有篩選參數（主機、日期、類別、嚴重度、狀態、視角等）即時同步至 URL Query String。將完整 URL 分享給其他具備相應權限的同仁，即可看到完全一致的查詢結果。
