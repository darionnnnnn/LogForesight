# NetIQ 維護

「系統管理 > NetIQ 維護」頁（`/admin/netiq`，需 Maintain 能力）集中管理多主機環境中的 NetIQ Sentinel 連線、查詢與節流參數、網段掃描匯入主機精靈，以及 NetIQ REST API 診斷工具。

頁面分為三個分頁：

## 1. 設定分頁

### Sentinel 清單與連線設定
- **清單資訊**：列出每台 Sentinel 的名稱、連線位址、作業系統（Windows / Linux）、探索帳密設定狀態、轄下已登錄主機數與啟用狀態。
- **名稱**：必填，用於在主機頁「所屬 Sentinel」下拉選單中識別。
- **連線位址**：例如 `https://sentinel.corp.local`。
- **探索帳號與密碼**：掃描匯入主機所需的憑證。密碼為 write-only（留空＝不變更）。
- **作業系統**：Windows 或 Linux，做為掃描匯入時預填整批主機 OS 的依據。
- **以 ESM 事件來源目錄探索**：核取方塊。啟用後改自 ESM 目錄取得已註冊但目前無事件回報的完整主機清單（需具備 ESM 唯讀權限；若無權限會自動退回一般事件掃描）。
- **測試連線**：點擊可即時驗證連線位址與帳密是否正確，並顯示回應毫秒數。
- **停用**：暫停該 Sentinel 的夜間輪巡分析，轄下主機保持原狀。
- **刪除**：刪除 Sentinel 設定。若轄下有使用中的主機，刪除後這些主機會被停用並標記為「孤兒主機」（歷史紀錄不受影響，後續可在主機管理頁重新綁定至其他 Sentinel）。

### 連線與節流參數
套用於全站所有 Sentinel 的共用查詢行為：
- **節流間隔（毫秒）**：每次 REST 呼叫之間的間隔時間（0 為不節流）。
- **單頁筆數**（1~5000）與**單一查詢最多筆數**（超額時截斷防爆量）。
- **逾時秒數**（1~3600 秒）與**失敗重試次數**（0~20 次）。
- **每次執行回望天數**：每次執行往回檢查缺漏或需補跑的天數（1~30 天，正式環境建議設 1，避免大量歷史查詢拖慢執行時間）。
- **同時處理幾台 Sentinel**（上限 3）與**單台內查詢平行度**（上限 4）：控制多主機批次拉取的平行度。
- **略過憑證驗證**：供 Sentinel 使用自簽憑證時的逃生開關。
- **使用離線示範資料**：僅在開發／展示等非正式環境可見，開啟後改用離線假資料進行展示。
- **詢問 AI 即時查詢現場事件**：AI 服務有設定時可開啟，當風險 log 暫存查無資料時，向 Sentinel 發送即時查詢補充現場事件（全站併發 1、快取 10 分鐘，僅限 NetIQ 主機）。

## 2. 匯入分頁（掃描匯入）

提供網段主動掃描精靈，批次將 Sentinel 管理的主機收錄至系統中：

1. **啟動掃描**：選擇一台啟用中且已設定帳密的 Sentinel，輸入要掃描的網段（例如前綴 `192.168.0` 或 CIDR `192.168.0.0/24`），點擊「掃描匯入」。
2. **精靈步驟一：主機勾選**：系統依網段分組列出在掃描窗口內有事件回報的主機（安靜主機若無 ESM 權限需至主機頁手動登錄）。點擊「全選新主機」會預設勾選「新主機」與「可復活主機」（原屬其他 Sentinel 因移除而停用者），既有使用中主機預設不勾選（勾選代表更新歸屬）。
3. **精靈步驟二：群組指派**：確認作業系統與主機分級（核心／一般／測試，僅影響本次新增的主機），並針對每個網段指定主機群組（可選「未分組」、既有主機群組，或「＋ 建立新群組…」輸入新群組名稱）。
4. **完成匯入**：送出後立即建立/更新主機並指派群組，匯入結果會記錄於下方的掃描匯入紀錄中。

## 3. 診斷分頁（API 診斷）

用於在不影響夜間排程的前提下，對選定的 Sentinel 執行一組小規模驗證查詢：
- 選擇 Sentinel，可選填一台已知 Windows IP 與 Linux IP 作為樣本。
- 點擊「執行診斷」，系統在背景發送診斷查詢，核對連線狀態、時區計算、欄位對應、批次拉取與 ESM 來源清單。
- 診斷結果以等寬字體呈現在輸出框中，提供「複製」按鈕方便複製內容進行討論與排錯。
