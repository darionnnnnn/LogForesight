# PRTG 維護

PRTG 維護頁只供維護人員使用，側欄位置是「系統管理 > PRTG 維護」。頁面有「連線」、「擷取參數」、「鏡像狀態」、「環境探測」、「指定主機補值」和「使用效果」六個頁籤。

「使用效果」會分別顯示 PRTG 問題訊號、僅含 PRTG 主要問題的主機日、案件、交辦、回覆、抑制、靜音設定與跨來源佐證。前者只表示該日的 TopIssue 全來自 PRTG，不表示沒有其他較低優先級日誌；靜音數只計所選日期與靜音區間重疊的 PRTG 問題檔案，不代表期間發生 finding。各數字不共用分母，不能視為轉換率或修復率。

只憑同一主機日同時有事件與 PRTG 訊號是弱佐證，不能證明來自同一資源或同一事故。較強的來源核對需要兩邊各自具備可比對的原生參照、精確主機／資源身分和重疊 UTC 時間；缺少任一項就顯示未知。內部欄位摘要不是 PRTG 原生參照。目前 24 小時診斷是站內彙總寫入量，尚不能證明逐 sensor 的原生參照或 coverage。

## 資源壓力判定

CPU、記憶體與磁碟壓力使用已核對語意、資源身分與可信取樣證據。目前壓力觀測檢查最近兩個已完成且連續的小時；每日正式判定則檢查該 NetIQ 主機日內所有合格的連續兩小時窗口，白天命中後恢復也保留該日風險，最新恢復狀態另行顯示。每小時至少要有 75% 的唯一可信取樣時槽涵蓋。判定採各小時有效樣本平均，不表示時槽間每分鐘都維持該狀態。CPU 使用率兩小時平均都達 90% 才命中，兩小時都低於 85% 才視為恢復。記憶體先確認感測器代表「已用」或「剩餘」百分比，再按已用百分比使用相同門檻。磁碟以可用空間判斷：連續兩小時平均都不高於 10% 才命中，兩小時都高於 15% 才視為恢復。

CPU 與記憶體預設只產生提示，不改變主機日風險，也不建立正式案件或寄送正式通知。要切換為正式模式，維護者須先以目前伺服器端的合格資料執行成功試算，再於 24 小時內用同一 sensor、來源設定與規則版本啟用；啟用操作需要 Maintain 權限，伺服器會再次核對試算與目前證據。設定或證據版本改變後須重新試算。磁碟趨勢正式判定須符合逐 sensor 連續 28 日就緒資料和當前頻道語意證據；兩小時低水位採自己的完成小時門檻；暫定七日趨勢規則使用 35 日觀察窗，至少 28 個有效日、穩健下降至少 0.5 百分點／日、下降日比例至少 70%，預估在七日內到達 20% 可用空間低水位才命中。規則程式的就緒條件不代表目前正式站台已完成資料或預警效果驗證。

模式切換後的歷史撤回／重評由背景工作續作。主機詳情以「等待撤回／重評」、「已完成」、「已逾期」或「已被較新設定取代」呈現；完整證據就緒後才開始 15 分鐘期限。維護者頁面載入時會重新讀取狀態，工作仍待處理時每 15 秒更新；重新載入只重新查狀態，不延長期限或重設工作。畫面沒有手動重試按鈕；逾期時先檢視狀態與原因，不要把它當成歷史撤回／重評已完成。

這些小時判定依 PRTG 資源證據中的來源時區、分析時區、感測器語意與世代識別，不使用「同一天」或群組列出的首次／最後時間代替 UTC 資源證據。磁碟歷史會先轉成 UTC，再依服務主機本機時區歸入 NetIQ 主機日；只有完整落在該主機日窗口內的小時可參與趨勢。量測或接收時間晚於該日截止的 slot 不授予可信資格，下一個主機日資料也不回填成前一天的風險證據。時區缺失或轉換有歧義時顯示未知。

資源觀測上的時間解讀會註明它是事件時間、小時平均或來源涵蓋區間；沒有原生時間區間時仍顯示未知。15 分鐘補充期限從合格 NetIQ 父紀錄與必要 PRTG 證據均已就緒時起算，不從作業錯誤時間推算。若來源時間語意、主要頻道或單位尚未在現場確認，狀態會保持未知，不能宣稱該環境已支援正式判定。目前近 24 小時快照診斷只代表站內彙總回報量，無逐 sensor 證據；正式 PRTG 的來源時區及主要頻道／單位仍待現場核對。設定頁的「資源守門」門檻另用於夜間取數暫停，與上述壓力告警門檻分開。

## 連線

在「連線」頁籤填入 PRTG 位址，選擇認證方式，再按「測試連線」確認。支援「API token（推薦，PRTG 21+）」、「帳號密碼（PRTG 傳統 API / passhash）」和「帳號＋passhash」。測試成功後按「儲存」。

## 擷取參數

「PRTG 擷取（數值取數對象）」決定是否啟用 PRTG 取數，以及取數範圍。可選「關閉（預設）」、「只抓觸發主機」、「全部已對應主機」或「觸發主機＋指定清單」。另可設定取數策略、請求逾時、併發請求數、歷史回填天數、資料保留天數與 sensor type 白名單。

「保守（預設）」以快照供應數值；「激進」會對觸發主機逐顆查詢歷史值。儲存後可按「估算規模」查看主機、device、sensor 與保留量級。

資源守門已移到「系統管理 > 設定 > 資源守門」，PRTG 維護頁的連結會帶你前往該頁籤。

## 鏡像狀態

本頁「快照最近 24 個完整小時」只讀站內持久回報寫入量，不會呼叫 PRTG。這是聚合數字，沒有逐 sensor identity 證據，不能據此證實每顆 sensor 成功或 100% coverage；也不代表 sensor 數值可用或已累積 28 天趨勢資料。目標數為 0 會顯示無目標，不代表健康或故障；`Unknown` 是診斷證據不足，不能當作沒有目標。系統健康摘要空白時會顯示 `unknown`「尚無完整小時診斷資料」。

按「同步結構與對應」更新 PRTG 裝置、sensor、主機對應與狀態。頁面會列出成功對應、衝突、未對應、排除 IP 與目前鏡像數量。衝突列可依「衝突型別」選取後指派主機；不確定是否應清除資料時，先看取數範圍與同步結果。

取樣尚未啟用時，只要已儲存來源網址及認證，也可以同步結構與對應；同步不會啟用取樣。首次設定先完成同步及作用範圍，再完成快照與 Profile 容量試測，通過共同容量檢查後儲存啟用。同步途中變更來源、範圍或啟用狀態會安全取消，請以新的設定重新開始。

同步完成後，監看裝置鏡像依完整裝置同步結果判定；sensor 鏡像依「數值取數對象」的取數範圍判定。只有在完整同步與主機對應都成功、監看裝置範圍非空且不是部分處理、裝置鏡像本趟確實更新，並且已有監看裝置數基準、這次數量減少沒有超過縮小保護門檻時，系統才會立即清除不再屬於目前取數範圍的數值與狀態變更。首次沒有基準，或監看裝置數驟減而觸發縮小保護時，不自動清除；請在本頁「監看範圍外資料」先看預覽，再按「確認清除」人工處理。範圍計算失敗、空範圍、部分處理或裝置鏡像未成功更新時也不清除。歷史值補抓請到「PRTG 維護」頁；「排程作業」只查看 PRTG 狀態與執行中的停止鈕。

## 環境探測

環境探測另有「磁碟值型資料準備度」與「單顆磁碟語意驗證」。逐 sensor 分頁每頁最多 100 顆；第 1 頁另以最多前 100 顆提供 readiness 摘要，超出部分不納入，也不代表全站就緒數。每顆 sensor 的 28×24 小時缺口以 bitmask 表示。資料取自已落地資料，不重跑全站環境探測；資料準備度和 PRTG 頻道／單位語意是兩項不同檢查。

選取一顆或最多 5 顆 sensor 後可對昨天有限資料執行語意驗證，批次依序逐顆執行；取消會停止目前項目並略過後續項目。`requestId` 去重只存在目前行程記憶體，最多 512 筆、15 分鐘，重啟後不保留。驗證對照 PRTG 主要頻道、單位與資料庫既有值。若單位未知或系統無法確定頻道含意，結果會要求人工核實；只有最近成功比對的候選才可人工確認，並需填寫理由。驗證只檢查有限資料，並不等於真實趨勢或預警效果已驗證，也不會自動啟用規則或派送交辦。

「指定主機補值」可先選取主機與日期，查看估計請求數再開始；補值只寫歷史數值，不回頭建立舊日 finding 或交辦。局部回填可安全取消自己啟動的 run；程式／替身測試已驗，正式站操作待驗。

磁碟可用空間趨勢規則目前預設停用。規則維護頁可編輯草稿並對 1–730 個已完成日執行唯讀試算；每批依約 10 萬個預期歷史點分批。結果按「完成日 × sensor」配對分頁，查看資料就緒、語意狀態、排除原因與門檻命中。`UnsuppressedHitRowCount` 只計本頁未抑制命中配對列；一列可能涉及多位負責人，並非派工量上界或交辦張數。另依目前抑制設定估計抑制數，不含問題靜音及實際派工。試算不寫入規則或案件。只有至少一顆磁碟 sensor 同時具備 28 日有效資料與仍有效的語意證據，後端才允許啟用。尚未以真實 PRTG 28 天資料或現場頻道語意驗證；試算命中不代表正式站台預警效果已驗證。

先前探測的匯出約只有 6 天可用資料，且當時 sensor 單位為 null；這是歷史結果，不代表目前來源現況。請以同版本環境探測核實主要頻道、單位與時基，再核對逐顆準備度與試算結果。合成情境可驗程式行為，不能代替原生來源語意或真實事故效果；補抓舊資料也不能把缺少可信世代與語意證據的歷史追認成新資格。

環境探測是唯讀工具，用來確認 API 回應、分頁、狀態變更查詢、數值查詢、取數範圍和資源守門目標。首次啟用或調整取數範圍前先執行，特別查看「9d-5 逐物件查詢驗證」與「站台對照」。探測遇到連線、認證或逾時會顯示原因，不把量不到當成零資料。

有界探測結果綁定 PRTG 版本、sensor 分類、作用範圍與傳輸成本；共同容量准入必須符合固定工作負載、配額與完成期限。缺少相符證據時顯示等待原因，不能因單次探測成功宣告整體容量通過。

## NetIQ 試點與判定資格

PRTG 只補充已成功完成 NetIQ 分析的主機日。該日零事件仍可接受補充；缺日、失敗、執行中、本機來源或無法辨識的舊來源會保留待補證據，不獨立建案。重跑失敗不沿用舊成功資格。

在頁面上方「正式判定試點」確認 PRTG Core System ID、來源時區與顯示語系，選取 NetIQ 主機和 sensor，核對後儲存。最多 3,000 台／15,000 顆，清單每頁最多 100 筆。連線測試、鏡像數量與裝置查詢成功不能取代這個確認，也不能證明每顆 sensor 的歷史完整。更換來源或資源身分會重新暖機，不追認過去資料。

每顆已選 sensor 會顯示可信涵蓋與語意暖機時間。缺口和未知狀態不代表恢復。已確認的持續 Down 不因有人在 PRTG 按「確認」或持續超過 14 日而降低故障風險；通知另行去重。磁碟趨勢必須有連續 28 日的同世代資料、可信通道與當次核對；來源原始時間基準與分析時區均須有明確可信設定，跨時區須可確定轉換；缺少時間基準或 DST 歧義時等待證據。

「狀態涵蓋進度」的初始收集週期預設 72 小時，Maintain 可設定 1–720 小時。到期後不再發出新請求；管理者須在來源與授權仍相符時明確續行，系統沿用已保存的公平游標、逐 sensor 水位與待續頁前導，不自動重設期限。週期完成代表目前選取的 sensor 均完成至少一次封閉查詢且資源身分仍相符；這與可用歷史長度、個別規則門檻及正式就緒分開判定。畫面的成本基準是固定請求速率模型估算，預算遙測未知時會顯示 unknown；估算不是容量保證或 15,000 顆 sensor 的服務承諾。

## 晚到、重試與歷史修訂

NetIQ 成功紀錄晚到後，背景工作會續作可信補追加、案件及交辦。可在上方「補追加與通知」查看等待 NetIQ、未交辦、寫入待重試與 SMTP 狀態。擁有全站主機維護範圍的人可重試；此操作同時解除收件人連續失敗暫停，但保留成功去重識別。先修正郵件路由或地址，再重試。

SMTP 接受不代表收件匣實收。每名收件人的「SMTP 已接受」、「寄送結果未知」與「本輪未送出」分開保存；信件內容送出後沒有收到 SMTP 確認，會顯示可能已送達，不當成確定未寄出。途中靜音或權限改變會停止後續寄送，已取得的 SMTP 接受紀錄仍保留。部分成功或結果未知時，重試可能讓已收到的人再收到同案通知。持續同一故障不每日重寄；恢復後的新事故或風險升級另判。過期補追加只進摘要，不補發過時緊急通知。

完整可信重評可撤回不再命中的舊狀態／磁碟判定，案件及人工結論仍保留，不自動結案。無法還原原 AI 或獨立風險下限時，列為待重評，請重新執行 NetIQ 分析。歷史同日訊號缺資源與時段證據時僅為弱佐證，不能當作雙重確認；待重評清單可由頁面上方進入。

## 現場驗收

在「使用效果」選擇期間下載驗收證據包。包內 `ScopeComplete=false` 時，依 `ScopeStatus` 核對超限、缺失、格式或歸戶問題；全體比較會停用，不能以部分資料當作完整驗收。事故查證表單先選取主機，再載入該主機的查證清單，填入獨立事故識別及各基準可行動時間。時間依瀏覽器時區輸入，未知留空，不代表系統沒發現。合併分析必須有當時已取得的證據；事後回填不能計為提前預警。相同主機與事故識別會更新同筆查證。

單看關聯數、Down 告警或測試通過，不能證明額外提前預警。必須另比較 NetIQ、原生 PRTG、簡單聯集與合併分析，並先訂出現場負載、誤報、提前時間及查證成本門檻。

匯入 PRTG 證據包只作診斷；不搬運來源信任、正式案件或通知。重新確認來源、對應與試點後重新暖機。

## 保留與復原

新分片診斷工作完成後保留 7 天，明確放棄後保留 1 天；每分鐘最多清理 16 個工作、每個工作 8 片。receiving／validating 自建立起固定保留 7 天，failed／abandoned 自終止起保留 1 天；讀取與續傳不延長期限。過期後拒絕新寫入／新 lease，未過期 lease 可安全完成；取消請求保留片段，「放棄」才會變更伺服器工作，「清除本機紀錄」只清除本瀏覽器續傳資訊。舊診斷 blob 及不再選取、且無未完成有效判定引用的感測器證據，依 PRTG 保留天數清理，每輪最多 100 份。有效待補追加保留，案件最小證據不隨原日誌清除。已取代的舊判定版本可清理；正在使用的來源身分與試點暖機保留。

快照待寫資料位於資料目錄 `pending/prtg-snapshot`，目前使用具校驗的 manifest 與分段 journal；有效舊 `checkpoint.json` 會在完整性及來源核對後原子遷移。來源、資源世代或資料庫身分無法核對時停止採集並保留資料；單一對應變更不讓其他未變更資源重新暖機。先停服務，備份整份資料庫、資料目錄與設定；確認可回到原來源時先在原來源重放。若要放棄舊來源批次，將整個快照待寫目錄搬至備份隔離位置，再啟動新來源，記錄被隔離的日期與涵蓋缺口。不能只改檔內識別或把舊資料重放至新 Core。

升級前保存資料庫與資料目錄的一致備份，先在副本啟動並驗 schema、NetIQ 分析、補追加、案件與通知。回退應先停服務及郵件副作用，復原匹配版本的資料庫／資料目錄／程式；只回退程式不能保證新欄位與新判定相容。上線後新增的案件與人工回覆須另外保留及核對，不能覆蓋掉再當作無損回退。

事故查證分「實際發生」「介入後避免影響」「尚未觀察到結果」。預防案例不填未發生時間，必須記錄介入時間、具體動作與同資源前後量測；預測影響時間另填，不算已觀察提前預警。既有查證可從清單載入後補填未知欄位。證據包分列每例、樣本數、中位數與最差提前／查證耗時差，負值保留，未知不當零。查證耗時差只採已查證、具有非空白證據且兩種耗時都有效的案例；待查證或缺證據不計入改善樣本。已查證的誤報與預防案例仍可比較實際查證成本，增加的耗時會保留為負值。

人工主機對應與 IP 排除是全站範圍修改，需全站主機可見的維護權限。儲存／刪除與批次帶載入版本，過期拒絕或停止後續批次，不覆蓋其他管理者。衝突時先重新整理核對，再送出保留的表單內容。

版本分段預設包含程式 build、解析語意、可見試點的現有資源世代、磁碟語意、明確採樣通道語意及 CPU／記憶體正式風險模式；資源重建、通道尺度變更或正式模式切換後分開比較。日常檢查時間、試算更新與作業進度不建立新段；已有事故的版本欄位保留原分組，查證時依當時證據核對。

容量樣本綁定目前程式建置，快照與 Profile 都不沿用舊版成本；升級後先在停用狀態重新完成同契約試測。只改品牌、AI 或郵件等無關設定時，系統在來源、範圍、政策、目前量測與速率全部仍相符後重綁設定版本，不重設核准時間、租約或配額。PRTG 來源、憑證、策略、範圍或政策變更仍須重新核對，不能借用舊核准。

## 來源變更與作用範圍核對

調整來源前先選「新來源／重新暖機」「同 Core 延續」或「無法確認」，按「預覽來源變更影響」核對主機、sensor、未結案件與暖機。延續需填身分核對證據並勾選確認，換 Core、時區或語系不能延續；未知會停止正式判定。憑證輪替本身不重設來源。來源變更第一次儲存會先顯示影響，核對後再儲存。

按「預覽已儲存試點的實際作用範圍」查看逐項規則、排除原因、待 NetIQ 或待資料。預覽唯讀，分頁及總數依可見範圍顯示；可評估不代表命中、派工或收到信。補追加與通知區可核對工作 ID、採用與期望版本、最後完成階段及安全停止狀態；「已結束」不等於成功。這份工作版本列表重啟會重置，持久結果仍看作業、補追加與通知紀錄。

新快照復原檔有 checksum；不符、舊 v1 缺完整性證明或另一程序正在寫入，都會停止快照並保留資料。升級前先用舊版正常提交待寫批次，再停服務做一致備份。遇舊 v1，先備份，選擇回匹配舊版本與來源核對提交，或把整個快照目錄隔離、記錄涵蓋缺口後重新採集；沒有自動補簽或轉換，不要手改 checksum，也不要刪鎖繞過仍存活的工作者。來源搬址即使選延續，若還有舊 binding 的待寫樣本，仍按原來源重放／隔離流程處理。

探測版本 1.0.53.2：更新後至 PRTG 維護 → 環境探測，執行「完整環境探測」，完成後下載安全探測 JSON；小範圍資料流驗證不會帶出此完整 metadata context，不能代替。完整 JSON 需有 `deployment_resources` 與 `storage_environment`，兩者描述執行服務的程式環境及實際儲存 provider；儲存 provider 不一致、缺欄或欄型錯誤會被拒絕。`total_available_memory_bytes` 是 .NET runtime/GC 的可用記憶體資訊，不是實體 RAM；SQLite 的 `owned-data-root` 是本機資料根磁碟，不代表遠端 SQL Server volume。探測未能讀取或權限不足時保留 unknown/partial，不得推作零或完整。每種取得樣本的類型另有 `identity_preserving_raw_history`，保存昨天第一小時 `avg=0` 原始 XML 的有限通道 ID、數值、原始時間與接收時間摘要；無資料、逾時或來源格式不符會明示狀態，摘要解析成功仍不代表主要通道、單位／縮放或原始時間基準已確認。未知時區／語系維持未確認。

另到 NetIQ 維護 → 診斷，選擇實際 Sentinel 並執行「安全欄位形狀探測」，複製其獨立、有界的安全報告；這不是 PRTG 完整探測 JSON 的一部分。下一輪交接需同時提供完整 PRTG JSON 與這份 NetIQ metadata 報告，不能用小範圍資料流輸出替代。這是受控探測材料，不代表要在現場部署或完成正式站台驗收；執行時仍須使用既有且有權存取來源的探測環境。

容量核准分開收集快照與 Profile 傳輸樣本。Profile 試測可在 PRTG 擷取停用時執行；它對目前政策排序後的前 5 顆 sensor（範圍較小時取全部）各依序送出前置 sensors、channels、native primarychannel property 與後置 sensors 四個 Table 配額請求，每份回應最多 512 KiB、整趟 30 秒。只有 5 筆相同來源憑證、範圍、策略、請求形式與程式版本的成功樣本才可參與 Profile 容量估算；失敗、逾時、格式變更或來源／設定／範圍／策略變更都會留下可見的等待原因或使舊樣本失效。它只保存不可逆雜湊、請求數與耗時，不會寫入信任 Profile，也不會改資源身分或頻道世代，因此不會讓來源資格通過。重新啟用或擴大有效採集範圍時，快照與 Profile 都必須各有 5 筆新鮮且相符的成功樣本；共享 Table API 每秒 2 次配額、快照期限及 Profile 23 小時刷新期限會保留餘裕後一起估算。範圍估算會另外顯示共同容量結果、每秒保留配額與各自完成期限；分項試測個別符合條件只代表樣本足以估算，不代表共享配額、最多 5 顆 sensor 共用的 30 秒探測期限或整體期限已通過。綠色狀態依共同容量結果判定，並區分已核准方案與尚待儲存／啟用重驗的候選估算。停用狀態可儲存設定。

既有採集方案失敗後另有有限復原：必須仍是同一已核准方案、來源／設定／範圍／策略，Profile 資格有效，取數範圍僅 1–50 顆，且有 1–4 筆 24 小時內同契約的真實快照批次結果。系統以設定的最壞請求逾時、目前共享配額及 25% 餘裕重新准入；每輪只允許一批快照，先不執行 sensor 補抓或狀態 Queue。這些結果不會被補造成成功樣本；完整作業仍須等到 5 筆新鮮且相符的成功快照。沒有批次證據、證據過期、範圍擴大或契約改變時，維持等待並顯示原因。

交接前可在有 PowerShell 7 的電腦執行 `pwsh -NoProfile -File scripts/Verify-PrtgProbeEvidence.ps1 -Path 安全探測.json`。預設要求 1.0.53.2 與完整 40 位 build revision；若要核對特定提交，另加 `-ExpectedRevision` 與完整40位 Git revision。工具僅讀取最多64 KiB，回報固定欄位、列數與狀態，不輸出原始字串、路徑或連線資訊。結束碼0表示版本、raw identity 與適用的部署／儲存 metadata 形狀完整；2表示 unknown、partial、timeout、截斷或權限不足等證據未齊；1表示 JSON、provider 配對、欄位形狀或版本不符。SQLite 的 SQL 主機資源標為不適用；SQL Server 的遠端主機實體資源無法由服務程序觀測，會維持 unknown 並回報未齊。即使結束碼0，也必須逐項確認來源語意、時基、風險與容量條件，不能由此啟用正式資格。

校準卡「PRTG 狀態規則門檻」僅重算 down／flapping／warning；silent、磁碟趨勢及資源期間規則明示未評估，不能解讀為零命中。匯出保留完整規則目錄，以 ThresholdKind 區分門檻種類，趨勢及期間規則的純量 Threshold 為 null。規則目錄開關不代表來源可信、試算合格或已授權正式風險。


## 診斷匯出的資料庫前提

診斷搬運的完整下載需要一致快照，才能在背景採集持續寫入時取得同一版本。若下載被拒絕，請管理者先核對部署所用資料庫：

- SQL Server：在實際服務資料庫執行唯讀查詢 `SELECT DB_NAME() AS database_name, snapshot_isolation_state_desc FROM sys.databases WHERE database_id = DB_ID()`，必須為 `ON`。若未啟用，由資料庫管理者在確認版本儲存空間後，針對查得的實際資料庫執行 `ALTER DATABASE [實際資料庫名稱] SET ALLOW_SNAPSHOT_ISOLATION ON`，再查一次確認。`READ_COMMITTED_SNAPSHOT` 只有逐敘述快照，不能替代本項整份資料的一致快照。
- SQLite：核對部署的 `Storage:SqliteWal` 為 `true`（預設值），並以唯讀 `PRAGMA journal_mode` 確認為 `wal`；修改部署設定須依服務重啟流程生效。不要在下載流程臨時改資料庫模式。

這些設定不會授予來源信任，也不代表容量通過。服務遇到不符合前提的資料庫會在下載開始前拒絕；校正後可重新執行匯出。

## Trusted profile 頻道綁定與資格核驗

在 PRTG 維護的 Trusted profile 進度頁逐列選取實際 sensor。唯讀 probe 回傳的頻道清單只供管理者明確選擇精確 Channel ID、caption 與來源單位；清單順序、來源 primary 標記、sensor 值相等或環境 native primary capability 都不會自動選頻道或授予資格。若清單截斷、身分／頻道世代不明或來源欄位不足，保持 unknown 並重新核對。

保存綁定時會帶入 `ExpectedSettingsRevision`、`ExpectedPolicyRevision`、`ExpectedIdentityEpoch`、`ExpectedChannelGeneration` 與 `ExpectedBindingRevision`，以及明確選定的 `ChannelObjectId`、`ExpectedCaption`、語意、單位、正 Scale、方向、原始間隔單位、原始與分析時區及不含密鑰的 `TimeBasisEvidenceReference`。首次保存或語意／來源契約變更後為 waiting，並列出 `qualification_required`；保存本身不是資格核准。完全相同且仍符合目前身分與來源契約的保存會保留既有 proof、binding revision 及頻道世代，回覆可維持 qualified。若回覆 409 `binding_fence_changed` 或 `catalogue_changed`，保留草稿，重新載入目前版本及來源候選，再由管理者核對後重送，不自動覆寫。

「核驗此綁定」會按已保存綁定版本執行單次有界來源核驗。只有取得真實、可解析的原生 PRTG 歷史 XML，且其 sensor、明確綁定頻道、raw value 與 `datetime_raw` 證據通過前後來源核對，才可能建立 physical-sample qualification proof；missing fact、逾時、格式錯誤、身分或頻道世代變更都保持 waiting/unknown。連續 metadata 更新不能冒充重新取得 historic proof。環境探測輸出的 native primary capability 摘要只屬診斷資料，不能授予正式 Profile ready；正式綁定核驗另以 primarychannel property 的前後 sensors／channels 核對及 raw 歷史證據建立資格。

Profile metadata freshness 為 24 小時；背景 refresh 工作的期限為 23 小時，兩者含義不同。共享 historic API quota 的初次核驗每顆 sensor 限一次有限的 `avg=0` GET，用於取得真實 raw proof；它不是冷卻時間，也不代表其他請求已通過容量驗收。正式擴至 15,000 顆前仍須以量測結果完成整體來源 probe、refresh、quota、timeout 及期限的共同准入；目前不能把範圍上限或分項試測描述為 15,000 顆已驗收。

管理者介面所用唯讀查詢形狀：`GET profiles?offset&limit` 回傳分頁與每列 binding/status/缺項摘要，不含原始頻道 payload；`GET bindings/{sensorObjid}` 回傳目前 binding（可為 null）及五個 expected CAS 值；`POST probe` 接受 `{sensorObjids:[...]}`，一次 1–5 顆並回傳逐 sensor 身分世代及頻道候選；`PUT bindings/{sensorObjid}` 保存一筆 explicit binding；`POST bindings/{sensorObjid}/qualify` 接受 `{expectedBindingRevision,expectedBindingFingerprint}`。保存候選最多 100 筆的批次使用 `POST bindings/batch`，每列仍需自己的五個 expected fence 並逐列回報。初次 physical-sample proof 綁定當時的 binding、source、resource、channel 與 time-basis 證據；之後 metadata refresh 不會改寫或重新取得該 historic proof。

MVC API 的 binding request 使用 `ChannelObjectId` 十進位字串；`Quantity` 是數字 enum：1=CpuLoadPercent、2=MemoryUsedPercent、3=MemoryAvailablePercent、4=DiskFreePercent、5=DiskUsedPercent（0=Unknown 不可保存）。管理者要先按每顆 sensor 讀取 probe，再從該 row 的 channels 精確挑選 channel ID、確認 caption/unit、填語意與時間證據，不能套用其他 sensor 的頻道。

如需多顆設定，可逐顆完成 probe 與表單後按「加入批次草稿」；草稿留在目前頁面記憶體中，最多 100 筆，跨 profile 分頁保留。按「提交批次綁定」才送出伺服器；每列仍使用加入草稿時的獨立版本 fence，回覆逐列接受或拒絕，首次／變更的接受列是 waiting，後續必須明確核驗；相同且仍有效的列維持既有 qualified。拒絕列與未提交草稿會保留，重新載入不會默默取代草稿。若 fence／目錄衝突，草稿會保留；逐列重新載入 sensor、probe、核對並重新加入可更新該列 fence。批次上限不是 100 顆自動挑選，也不代表全部 15,000 顆容量已驗收。

Qualify API 成功回應的外層 `status` 才是本次核驗狀態；內層 `binding` 是保存資料，`probe` 是來源回報。Profiles row 也分別提供 profile resolver `status` 與 `bindingStatus`，不可把已有 proof reference 的 `qualified` 字樣直接當成 profile `ready`。

來源 Profile 必須同時符合摘要、目前資源身分、保存的 binding 語意指紋與當前時間依據。Scale 可為有限正數，原始值只正規化一次；合法的非 1 Scale 證據可出現在主機明細。背景 metadata 刷新若完成核對並確認必要來源事實缺失／衝突，會原子撤銷該次捕捉的舊 Profile；較新 Profile、改動後的 binding、歷史資料及 journal 不受舊結果覆寫。網路失敗、逾時、取消或失去租約只記錄失敗／等待，不能冒充已觀測到語意變更。

切換 sensor 會保留未提交編輯器草稿，明確排入批次的版本與較新的編輯草稿各自保留。API 確認已寫入但目錄隨後變更時，顯示已提交並要求 reload；此回執不帶來源／binding 內容，核驗按鈕保持停用，直到 reload 與 probe 核對。網路、逾時或伺服器錯誤只表示結果未確認，草稿保留，先 reload 核對已保存版本再决定重送，不自動重試。


# PRTG 原始採樣資格作業

管理員先儲存每個 sensor 的明確通道 binding，再執行最多 5 個 sensor 的資格容量探測。探測走目前 PRTG 設定與有界 native endpoints，核對實際 channel ID、raw 值、原生時間、primary-channel property 與穩定的前後 sensor metadata。探測回應是本次部署的證據；文件描述或合成測試不能替代它。

探測成功只表示容量契約與 raw proof 可用，不會建立正式 profile。完整政策範圍最多 15,000 個 sensor；作業按 100 筆 SQL 分頁逐顆執行，單次最多 30 秒來源探測、每個 sensor 本輪最多 1 至 3 次嘗試、固定退避、十分鐘切片。達到本輪上限後保留 waiting/failed 水位；只有管理員明確續跑並重新核准成本才會開始新一輪。重新啟動會沿用原期限，只有管理員明確續跑才會建立新期限。期限為 1 至 720 小時，畫面中的 72 小時是可調預設值。

作業執行時，資料庫共享 HistoricData 配額每分鐘最多保留 1 次給資格作業、4 次留給同一 LogForesight 資料庫的其他來源呼叫；停止或到期後取消分配。每次完整嘗試計 4 個 Table/property GET 加 1 個 Historic XML GET。容量試算依管理員選擇的 1 至 3 次上限、來源實測請求形狀、既有 Table admission rate、25% headroom，以及最多 120 秒的既有 request reservation 回收等待估算。15,000 sensors、單次探測、720 小時可依有效 pilot 試算；同範圍 72 小時或三次探測會因超出成本拒絕。容量證據缺漏、來源/應用版本、範圍不符或成本超出期限時，作業維持 waiting-capacity。

資格作業只把 raw proof 與工作分頁在同一 SQL 交易內寫入。後續既有 profile refresh 再核對目前 native primary channel、binding revision、時間與來源 fences，成功時才發布正式 profile 給 resolver 與 consumer。缺 binding、native ID/值/時間不符、owner/lease/page revision 競爭或來源設定改變，都不會成為 trusted sample。

按下取消後 worker 會在短間隔檢查作業 fencing 並停止後續工作；已送出的 HTTP 請求可能仍在來源端執行，已送出的 Historic token 會在共享 60 秒窗口內保留。

事故查證每台主機最多 1,000 筆；跨主機清單及證據包最多輸出 1,000 筆，日期篩選先於輸出上限。缺少查證文件代表未知，已保存的空清單才代表已知零筆。時間線僅匯出有界摘要；缺失、超限、格式錯誤或現有資源歸戶不符會保留未知，不補成已完成。異常的既有查證文件會拒絕覆寫並保留原檔，先核對及修復後再保存。

驗收證據包格式第 2 版以 `TimelineRepresentation=bounded-summary-v1` 標示時間線摘要，不再輸出完整狀態／涵蓋陣列；舊包仍保留原格式，不混當同版完整資料。未選取任何可見試點時，包內範圍不完整。

驗收期間依服務主機的本地日期，與 NetIQ 父紀錄主機日一致。表單保存的 UTC 事故／介入／查證時間先換成本地日再篩選；PRTG 採樣分析時區不改變此日曆邊界。
