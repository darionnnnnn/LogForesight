# PRTG 維護

PRTG 是另一套監看網路與主機數值的軟體，例如磁碟剩多少空間、CPU 多忙。
本系統讀取 PRTG 的資料，和日誌分析一起判斷風險。
入口是「系統管理 > PRTG 維護」，只有維護人員看得到。

頁面有六個頁籤：連線、擷取參數、鏡像狀態、環境探測、歷史回填、使用效果。

## 常用操作：第一次啟用

頁首的「啟用準備」會逐項提醒下一步：

1. 「已儲存的連線位址與認證」：在「連線」頁籤填位址與認證，測試連線成功後儲存。
2. 「上次環境探測」：在「環境探測」頁籤執行「完整環境探測」，確認 PRTG 資料取得到。
3. 「PRTG 擷取」：在「擷取參數」頁籤勾「啟用 PRTG 擷取」並儲存。
4. 「上次結構與主機對應同步」：在「鏡像狀態」頁籤點選「同步結構與對應」。
5. 「PRTG 規則」：到「規則維護」的「PRTG規則」分頁，啟用要用的規則。
6. 「每日排程」：確認「排程作業」的每日排程已啟用。

六項都完成後，下方會出現「最近一次排程驗收」，用隔晚實際跑的結果再確認一次：

- 最近一趟排程取數的 PRTG 結果是否成功。
- 取數結束後 AI 判讀有沒有跟上（AI 沒設定時顯示「不適用」）。
- 快照最近 24 個完整小時有沒有達標。

手動「立即執行」不算在驗收內。結果有變時，點選「重新確認」。

**注意：**PRTG 帳號的時區請設成和本系統主機相同，否則部分數值可能落在錯的小時。

## 什麼時候會看到結果

- PRTG 告警類的問題（例如裝置離線、警告），隔晚第一次排程後就會出現。
- 數值慢慢變差的問題（例如磁碟逐漸變滿），要累積 28 天有效資料才可能出現。累積期間，主機詳情會顯示「資料累積中 X／28 日」。

## 連線

| 認證方式 | 要填 |
|---|---|
| API token（推薦，PRTG 21+） | PRTG 產生的存取碼 |
| 帳號密碼（PRTG 傳統 API / passhash） | 帳號與密碼；密碼會加密保存，之後每次取數都會用到 |
| 帳號＋passhash | 帳號與 passhash（由密碼換來的登入碼）；不保存密碼 |

密碼欄留空代表沿用已儲存的值；要移除請用該欄的清除選項。

## 擷取參數

| 設定 | 說明 |
|---|---|
| 啟用 PRTG 擷取 | 總開關。關閉後夜間取數、歷史回填與排程同步都不執行；仍可手動「同步結構與對應」 |
| 取數策略 | 「保守（預設）」每 15 分鐘取一次數值；「激進」每 5 分鐘，夜間另外逐項查詢。大型站台用保守 |
| sensor type 白名單 | 要取數值的監看項目類型。出廠已包含 Ping、CPU、記憶體、磁碟可用空間與網卡 |
| sensor type 分類補充對照 | 新類型要告訴系統它量的是什麼，否則會被當成「單位未知」而略過 |
| 監看範圍（可選縮圈） | 在頁籤最下方，預設收合；不選就是全部已對應的主機，平常不用動 |

## 鏡像狀態

「鏡像」是本系統保存的一份 PRTG 資料副本。點選「同步結構與對應」會更新這份副本，並把 PRTG 裝置對到本系統的主機。
這個頁籤只列主機清單裡的主機。PRTG 裡有、主機清單沒有的裝置不會出現。

- 對應主要靠 IP。同一個 IP 在 PRTG 有好幾個裝置時，全部算同一台主機。
- 主機的 IP 完全對不到時，才改用裝置名稱比對主機名稱。
- 「衝突」代表同一個 IP 給了好幾台主機，或裝置名稱對到好幾台主機。請在衝突清單指定正確的主機，或排除該 IP。
- 「未對應主機」列出主機清單裡、還沒對到 PRTG 裝置的主機，並寫出原因。
- 在未對應主機那一列點選「指派 PRTG 裝置」，輸入名稱或 IP 搜尋，選好後送出。
- 同一個 IP 只想認其中一個裝置時，對那個裝置做人工指派，其他的會自動略過。
- 「名稱不一致」表示 IP 對上了，但 PRTG 上的名稱和主機清單不同。主機名稱可能改過，請確認。
- 「快照最近 24 個完整小時」顯示每小時取到多少數值。
- 表中「品質達標列／目標」與驗收段用同一個數。
- 不再需要的舊資料會自動清除。
- 第一次同步或範圍大幅縮小時不會自動清，請先在「監看範圍外資料」預覽再確認。

## 環境探測

- 「完整環境探測」：只讀取、不寫入，檢查 PRTG 版本、資料能不能取得、主機 IP 覆蓋率。第一次啟用或調整範圍前先跑一次。
- 「驗證小範圍資料流」：挑一個項目，實際抓一天的資料並讀回確認。
- 「數值資料就緒度」：列出 CPU、記憶體、磁碟、Ping 各有多少項目可用。不能用的會寫原因，例如有效日不足。規則頁把 Ping 這一類叫「連通性」，指的是同一類項目。
- 「校準數值匯出」與「診斷資料搬運」：給維護人員調整門檻或排查問題時使用。

## 數值趨勢規則

規則維護的「PRTG規則」有四條趨勢規則，全部預設停用：
磁碟可用空間、記憶體使用、CPU 負載、Ping 延遲。

1. 在規則編輯視窗點選「試算草稿」，看哪些項目會命中、目前值多少。試算不會寫入任何資料。
2. 至少有一個項目資料就緒，才能啟用規則。
3. 啟用後，資料不足的項目會顯示原因，不會產生問題，也不會拉高風險。

趨勢規則只抓慢慢變差的狀況。一夜之間突然出事，由 PRTG 自己的告警處理。

## 歷史回填

- 「全量歷史回填」：先點選「預估全量工作量」看要查多少，確認後才開始。
- 保守策略下，回填會補全部已對應主機。激進策略下，依「夜間數值取數對象」決定。
- 中斷後再預估一次，已完成的日子會預設略過。要全部重抓請勾「全部重做」。
- 排程作業頁「立即執行」回望多天時，可以勾「一併補齊 PRTG 逐小時數值」。
- 勾選框旁會寫出主機數、查詢次數與大約時間。查詢很多時預設不勾，請自己決定。
- 某天之前還沒有主機對應時，會沿用之後最早的一份對應，執行紀錄會註明。
- 「指定主機歷史數值補值」：最多 5 台主機、7 天，點選「預覽工作量」後開始。
- 兩者都可以點選「停止回填」；排程作業頁的 PRTG 卡也看得到進度。

**注意：**夜間取數遇到回填還在跑時，最多等 30 分鐘。建議回填避開排程時段。

## 看懂執行結果

- 執行詳情的「PRTG 逐日」表，「說明」欄會寫出部分失敗的原因。
- 「整趟擷取階段失敗」代表那一段資料可能少了一些，不代表找到的問題是錯的。
- 說明寫「某類趨勢證據未完整」：那一類趨勢沒算完，這趟標成部分完成。其他類別與 PRTG 告警照常判斷。
- 最新一天的主機對應整天沒對上時，會先沿用前一天的對應。數值就緒度不會因此突然變成 0。
- 完整的失敗訊息在同一個視窗下方的「重要紀錄」。
- 保守策略不在夜間逐項查詢，所以觸發主機與 sensor 欄位顯示「—」。
- 同一台主機在 PRTG 有好幾個裝置時，每個裝置的問題會各列一筆。
- 新啟用一條規則時，過去的日子不會自動重算。請用「立即執行」回望要重算的天數。

## 問題的處理與誤報

- PRTG 的問題會出現在當天的風險日；那天沒有日誌資料時，會建立只有 PRTG 的風險日。
- PRTG 問題不寄即時告警信，改在每日與每週摘要裡呈現。
- 把 PRTG 問題標為「誤報」後，同一台主機同一個問題 30 天內再出現會視同已處理。
- 「使用效果」頁籤列出每條規則被標誤報與已處理的次數，可作為調整門檻的依據。
- 「使用效果」最下方是「通知處理狀態」。

## 注意事項

- 升級系統前先備份資料庫。
- 「診斷資料搬運」的完整下載需要資料庫管理員先開啟一致讀取的設定；沒開時下載會在開始前被拒絕。
- 資源守門的設定在「系統管理 > 設定」，見「資源守門」。
