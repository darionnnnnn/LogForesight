# PRTG 維護

PRTG 維護頁只供維護人員使用，側欄位置是「系統管理 > PRTG 維護」。頁面有「連線」、「擷取參數」、「鏡像狀態」、「環境探測」、「歷史回填」和「使用效果」六個頁籤；頁首的「啟用準備」逐項指出下一步。

## 四步啟用

1. **連線**：在「連線」頁籤填入 PRTG 位址、選擇認證方式，按「測試連線」成功後儲存。
2. **同步結構與對應**：在「鏡像狀態」頁籤按「同步結構與對應」（背景執行）。衝突與未對應的裝置可事後在清單處理，不必等全部處理完。
3. **啟用規則**：到「規則維護」的 PRTG 規則確認要用的規則已啟用。
4. **等每日排程**：夜間取數會自動做結構同步、主機對應、規則評估與數值取數。

時程：狀態型問題（Down、Warning、反覆故障）在啟用後的第一次每日排程就會出現；趨勢型問題最早要累積 28 個有效日後才可能出現。累積期間，就緒度卡與主機詳情會顯示「資料累積中 X／28 日」。

**PRTG 帳號的時區請設成與服務主機相同。** 數值以 PRTG 回傳的 UTC 時間為準；時區不同時執行輸出會出現警告與計數，少數缺時間欄位的列可能落在錯的小時。

## 連線

支援「API token（推薦）」、「帳號密碼」和「帳號＋passhash」。帳號密碼模式由系統換取 passhash，密碼只在換取那一次送出；帳號＋passhash 模式系統不保存密碼。留空的密碼欄沿用已存值；清除要用頁面的清除操作。

## 擷取參數

- 「啟用 PRTG 擷取」是總開關；關閉時夜間取數、快照與回填都不連線。
- **取數策略**：「保守（預設）」每 15 分鐘以快照取數值；「激進」每 5 分鐘快照，夜間另對觸發主機逐顆查詢整點平均。大型站台用保守。
- **sensor type 白名單**：要取數值的 type。出廠值含 Ping、CPU、記憶體、磁碟可用空間與網卡等分析型 type，不含 Traffic（取值不可靠、目前規則用不到）。已升級的站台會保留原本儲存的清單，需要 Ping 數值時請自行加入。白名單只影響數值取數，不影響狀態規則。
- **sensor type 分類補充對照**：一行一筆 `type=分類`，也可加量測語意：`type=分類:語意`，例如 `SNMP Linux Meminfo=memory:memory-percent-free`。語意可用 `cpu-percent-used`、`memory-percent-free`、`disk-percent-free`、`ping-ms`。沒有語意的 type 在數值規則裡會被當成「單位未知」而略過。改動會影響資源守門的自動偵測。
- 資源守門在「系統管理 > 設定 > 資源守門」，本頁只有指路連結。

## 鏡像狀態

按「同步結構與對應」更新裝置、sensor、狀態變更與主機對應。頁面列出成功對應、衝突、未對應、IP 排除與鏡像數量。

- 對應先比 IP；IP 查無主機或裝置沒填 IP 時，改用裝置名稱括號內的字串與主機名稱比對。名稱比對到多台主機、或該主機已有其他對應時列為衝突，標「hostname 多主機」或「hostname 主機已被對應」。
- 衝突列依型別指派主機；確定某個 IP 不該查 PRTG 時可直接排除該 IP。
- 「快照最近 24 個完整小時」只讀站內寫入量，不呼叫 PRTG，也不代表每顆 sensor 都成功。
- 同步成功且通過縮小保護時，系統會清除不再屬於取數範圍的數值與狀態變更；首次同步或範圍驟減時不自動清，請在「監看範圍外資料」先看預覽再按「確認清除」。

## 環境探測

- **完整環境探測**（唯讀）：檢查 PRTG 版本、type 分布、IP 覆蓋、分頁語意、數值單位與逐物件查詢；成功後接著印「站台對照」（取數範圍試算、範圍內實測、資源守門目標）。首次啟用或調整範圍前先跑一次。
- **驗證小範圍資料流**：挑一台已對應主機的一顆 sensor，沿正式路徑抓昨天一天的值並讀回。
- **數值資料就緒度**：取數範圍內 CPU、記憶體、磁碟、Ping 四類 sensor 依原因分組計數——就緒、有效日不足、品質不足、值不合理、固定值、單位未知、對應無效。數字與夜間執行輸出的就緒度行一致。
- **校準數值匯出**與**資料搬運**也在這個頁籤。

## 數值趨勢規則

規則維護頁的 PRTG 規則有四條趨勢規則：磁碟可用空間、記憶體使用、CPU 負載、Ping 延遲。全部預設停用，門檻是暫定值。

- **趨勢規則只抓慢性惡化**。一夜之間的突發（例如磁碟一晚塞滿、CPU 突然滿載）由 PRTG 自己的告警經狀態規則（Warning／Down）處理。
- 數值可信要同時符合三件事：該日對應有效、該小時資料品質可用、單位可判。不符合的 sensor 會顯示原因，不會產生問題，也不會拉高風險。
- 啟用前可在規則編輯視窗「試算」草稿，看哪些 sensor 會命中、目前值多少、為何被排除；試算不寫任何資料。後端只在至少一顆 sensor 就緒且語意相符時才允許啟用，否則請回「環境探測」的數值資料就緒度查看原因。
- 趨勢問題的說明固定列出：裝置／sensor、近 N 日有效 M 日、目前值與每日斜率、預估何時到達門檻、資料截至哪天。值回到安全側且不再惡化後就不會再命中。

## 主機詳情的 PRTG 區

主機詳情列出對應的 PRTG 裝置與 sensor。CPU、記憶體、磁碟、Ping 類 sensor 另有「數值資料」欄：就緒（綠）、「資料累積中 X／28 日」（灰）、其他原因（警示色）。資料不足不會顯示成綠燈。維護人員另有連結可直接到就緒度卡。

## 問題的處理與誤報

- PRTG 問題會進入當日主機日；當天沒有日誌分析紀錄時會建立只有 PRTG 的主機日，之後日誌分析寫入同一天時會合併。只有 PRTG 的主機日不算「已分析」，不影響缺日補跑。
- PRTG 問題不寄即時告警信，改在每日／每週摘要的 PRTG 段呈現。
- 某天把 PRTG 問題標為「誤報」後，同主機同問題 30 天內再出現會視同已處理：不進摘要，問題排行顯示「已標誤報」。資料照樣保留；把那天改回其他狀態即取消，30 天後再出現視為新問題。
- 「使用效果」頁籤按規則代碼列出「標記誤報／已處理」筆數，哪條規則誤報多就是下次調門檻的依據。

## 歷史回填

在「歷史回填」頁籤先按「預估」查看逐日主機、sensor 數與請求次數，核對後確認才開始；預估五分鐘內有效。回填只補數值與狀態變更，不重跑結構同步、不重建歷史對應。「指定主機補值」可選主機與日期，只補數值、不回頭建立舊日問題或交辦。進度與停止鈕在「排程作業」的 PRTG 卡。

## 資源守門

設定在「系統管理 > 設定 > 資源守門」。守門讀 PRTG 主機與 Sentinel 主機的 CPU、記憶體 sensor，資源緊張時暫停夜間取數。

- 受監看清單留空時，夜間取數開始前會自動偵測並填入，清單上方顯示「自動偵測 日期」。偵測不到或逾時（15 秒）時這趟不守門，取數照常。
- 手動填寫的清單不會被自動偵測覆寫；想重抓時按「自動偵測並填入」再儲存。
- 記憶體門檻是「可用」百分比（低於多少算緊張），方向與 CPU 相反。

## 升級注意

- **升級前先備份資料庫。** 升級會刪除已停用機制留下的設定資料（無法還原）。
- 舊版的三條資源壓力規則已移除；需要時改用記憶體／CPU 趨勢規則。
- 規則維護頁出現內建規則更新橫幅時，套用後才會拿到新的趨勢規則（預設停用）。

## 診斷匯出的資料庫前提

診斷搬運的完整下載需要一致快照：SQL Server 須啟用 snapshot isolation（`ALLOW_SNAPSHOT_ISOLATION ON`），SQLite 須為 WAL（`Storage:SqliteWal=true`）。不符合時下載會在開始前被拒絕；請資料庫管理者調整後重試，不要在下載流程臨時改資料庫模式。
