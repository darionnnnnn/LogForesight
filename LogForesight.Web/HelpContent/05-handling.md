# 處理狀態與案件

風險日與其中的個別問題都可以標記處理狀態、指派處理人，讓團隊追蹤「誰在處理、處理到哪」。

## 處理狀態

對外一律呈現三態：**未處理**／**處理中**／**已處理**。「已處理」底下實際細分四種結案原因：已解決、不予處理、誤報、已知雜訊——結案時選擇最貼近實際情況的原因，方便日後追溯「當初為什麼判定不用處理」。

「處理中」底下還有一個**無法處理**：處理人評估後發現自己解決不了（例如需要外部廠商、超出自己的權限），標記時必須填寫原因。這**不是結案**——案件維持進行中，畫面上仍歸「處理中」，但會即時寄信通知全部 admin 群組成員（郵件通知已啟用時），請他們決定是要直接結案還是重新指派給別人處理。與「不予處理」的差別在於：不予處理是「評估後認為不值得處理」，無法處理是「這件事還是要處理，但我做不到，需要上報」。

## 指派與負責人

- 標記處理狀態需要 `Handle` 能力；指派／改派處理人需要 `Assign` 能力（僅 admin）——刻意分開，只有 admin 能決定「誰來處理」。
- 主機負責人（於「主機與群組」頁設定）即使沒有加入任何群組，登入後也能看到並處理自己負責的主機。
- 問題負責人（於「問題檔案」頁設定，以來源＋Event ID 跨主機生效）優先於主機負責人：該日問題命中規則且負責人恰好一人時，自動帶入為預設處理人；多人時不自動猜，落回主機負責人規則。詳見「名詞解釋」的「問題負責人 vs 主機負責人」。

## 跨日問題案件（IssueCase）

同一台主機的同一個問題，第一次被指派處理人時會自動建立一個「案件」（以主機＋問題簽章為鍵）：

- 建案時自動回溯歷史裡同一個問題所有未結案的日子，一併掛進這個案件。
- 之後每天新分析到同一個問題，批次執行會自動把新的一天掛進進行中的案件，不需要每天手動重新標記。（狀態自動帶入的優先序為：人工標記 > 案件 > 機房結論）
- 在案件涵蓋的任一天標記狀態，會同步展開到案件涵蓋的其他天。標成結案類狀態時案件本身結案，問題如果之後重新出現，會視為一個新案件（不會延續舊的處理紀錄）。
- **同一個問題跨日只歸一人處理**：已有進行中案件時再次指派會保留原處理人，不會被搶走，系統會回報「已由 ○○○ 的案件涵蓋，未變更」。要換人處理請用「案件改派」，不要重新指派。

風險日詳情頁的問題列上會看到案件徽章（處理人／起始日），點擊處理人姓名可連到對方的處理人工作頁。

## 案件授與：把問題交辦給主機授權範圍外的人

被指派為某個案件的處理人時，即使你原本看不到那台主機，也會取得**針對那個問題**的檢視權——不然把問題交辦給不在授權範圍內的人等於白指派。這個授與非常窄：只看得到被交辦的那個問題，看不到同一天其他問題、也看不到整日的 AI 總覽敘事；頁面會明確標示「您以案件處理人身分檢視」。授與以「現在或曾經是處理人」為準，結案後仍看得到自己處理過的紀錄。

## 我的交辦（處理人工作頁）

側欄「我的交辦」連到自己的工作頁：可見主機、處理中／已處理案件數、逾期提醒一次看齊。管理者也可以在「使用者」管理頁點進任一使用者的詳細頁，用同樣的視角查看對方的工作負載。
