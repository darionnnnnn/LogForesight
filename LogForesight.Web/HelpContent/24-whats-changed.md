# 這次更新後你會看到的變化

這一頁整理交辦與處理流程中，你會馬上注意到的數字與按鈕變化。
所有登入的人都看得到。處理人與管理者受影響最多。

## 數字怎麼算

| 看到的地方 | 現在的算法 |
|---|---|
| 交辦單的「台」 | 不重複的主機數。「件」是一台主機的一個問題，同一台主機結案後又出現會多一件 |
| 「進行中 N 台；歷來 M 台、K 件」 | 進行中的主機數；歷來的主機數；歷來的件數 |
| 「待我處理」 | 進行中的主機，扣掉觀察期內與上報中的。觀察到期的算在這裡 |
| 「今天需要你處理」 | 今天新增、復發、被退回、觀察到期、3 天內到期，共五個數字 |
| 儀表板「待派工問題」 | 已被處理人結案的主機不再算進去。數字是「可以派」加「派不出去」，嚴重度未達與不再打擾的不算 |
| 儀表板「未處理問題」 | 影響台數與點進問題查詢的台數一致。風險日分成「未處理」與「處理中」兩個數字 |
| 問題查詢「處理概況」 | 沒人標記、只因嚴重度低不用處理的，另寫「預設不處理」，不再算進「已處理」 |
| 風險日詳情「顯示範圍」 | 三個選項：「待處理」、「全部（含已完成）」、「只看已完成」。選單旁的數字等於列出的筆數 |
| 報表「未結案」 | 分三段：在處理人手上、待派、不需處理。三段相加等於未結案風險日 |
| 問題名稱 | 全站同一種寫法。事件編號是 0 的問題只寫來源，不再顯示「0」 |
| 管理者看到的未讀徽章 | 只有能指派的人才有。主管與開發人員沒有，因為他們不會標已讀 |
| 處理人頁與負載看板 | 處理人頁不含靜音暫停的單，負載看板含。兩頁都寫明了 |

- 「待我處理」、「觀察期內」、「上報中」三個數字相加，等於進行中的台數。
- 「我的交辦」的狀態篩選預設是「待我處理」。
- 要看觀察期內或上報中的單，請改選「進行中」。

## 按鈕與畫面

- 每一列的「回覆」與交辦單頁的「回覆這張單」，都會打開回覆表單。
- 回覆對象預設是全部進行中主機。只處理幾台時，點「只回覆部分主機」。
- 「這次的結論」不會預選。沒選就不能送出。
- 選「觀察中」可以點「3 日」、「7 日」、「14 日」。預設 7 日。
- 部分主機回覆為已處理後，表單會問「其餘 N 台要一起設為…」。
- 回覆被拒絕時，訊息會留在畫面上，你寫的說明還在草稿裡。
- 管理者交辦時，已結案與「先前判定不處理」的主機預設不勾選。
- 要重新交辦這些主機，請在預覽清單逐台勾選。
- 交辦視窗的「預計完成日（選填）」會依嚴重度先填好。
- 「我的交辦」與交辦總覽多了「嚴重度」欄。
- 「我的交辦」的排序預設是「處理優先序」。
- 頁面頂端出現「清單有更新」時，點「重新載入」。
- 儀表板的「未回報主機」卡，沒有管理主機權限的人不能點，改看卡片上的主機名。
- 有指派權限的人，儀表板最上方多一列「需要你處理」。全部是 0 時收成一行文字。
- 待派頁分成「可以派」、「派不出去」、「不會派」三段。「不會派」預設收合。
- 「立即派工」與每個問題的「派這個問題」，都會先預覽再確認。
- 交辦總覽可勾選多張單，點「改派給…」一次改派，最多 100 張。
- 負載看板的「改派他名下的單…」，一次改派某位處理人的全部進行中單。
- 停用帳號或暫停接單前，若他名下還有進行中的單，會先問要不要一併改派。
- 「不再自動派工」區預設收合，展開才載入，開頁面更快。
- 問題那一列的「更多」多了「不再顯示這個問題…」與「調整這條規則」。
- 交辦單頁可展開「處置參考」與「訊息樣本」，並有「這個問題的其他交辦單」等捷徑。
- 代為結案可選範圍：全部進行中、只有上報中的、勾選的成員。
- 每個頁面頂端有主機搜尋框，輸入名稱或 IP。主機詳情新增「這台的交辦」。
- 風險日詳情的「來源觀測」改用白話與當地時間，原始欄位收在「技術細節」。
- 報表三張圖有「下載 CSV」。規則編輯有「試算」。
- 執行總表每天有一句結論，失敗的列有「補跑這些主機」。
- 權限異動「無法解析細節」的列可點「展開原文」。稽核的動作選單有分組與搜尋。
- 設定頁多了「派工」頁籤，AI 服務頁籤多了「測試連線」。
- 系統健康多了「派工就緒」卡。AI 連不上時，也會列為原因。

## 上線當天會看到什麼

- 上線前就有的交辦單沒有期限，不會因此變成逾期。
- 上線後新派的單依嚴重度帶期限：高 3 天、中 7 天。
- 同一台主機的同一個問題，結案後 30 天內又出現，會標「復發」。
- 復發不會重開舊單。它是新的一件。
- 同一個問題 30 天內第 3 次復發，管理員會在交辦總覽的提醒區看到。
- 觀察到期的主機會被標出來。觀察期間沒有再發生的，可以一鍵結案。
- 授權矩陣每勾一格，只儲存那一格。兩位管理員同時改，不會互相蓋掉。
- 嚴重度高或重大的問題，被處理人判定「不處理」後，滿 30 天仍在發生會重新派工。
- 重新派工的新單，成員旁標「先前判定不處理」。處理人再回不處理，就重新計 30 天。
- 中、低嚴重度與管理者勾選「不再自動派工」的，仍是永久。
- 上線前就結案的高嚴重度問題不會自動恢復，在「不再自動派工」區標「上線前判定」。
- 新站台一開始，系統健康的「派工就緒」卡會列出還沒設好的項目，整體狀態也會跟著寫出原因。
- 兩位管理員同時編輯同一條規則或同一位使用者，後存的人會看到衝突提示，內容仍留在畫面上。
- 設定頁的自動派工開關搬到「派工」頁籤，設定值不變。

## 常見狀況

- 台數比預期小：台數是不重複的主機數，同一台主機的多件只算一台。
- 清單看不到觀察中的單：預設篩選是「待我處理」，改選「進行中」就會出現。
- 高嚴重度的問題隔了一個月又派給我：這是 30 天後重新派工，單上有「先前判定不處理」的標記。
- 儲存時看到「這筆資料剛被其他人修改」：別人先存了。點「重新載入」看最新內容，再決定要不要重填。
- 舊單沒有期限：上線前建立的單不會補期限，要的話在單上點「設定期限」。
