# 系統健康

這頁讓維護人員快速確認系統是否正常運作。
位置在「系統管理 > 設定」的「系統健康」頁籤。

## 頂端的整體狀態

頁面最上方先寫整體狀態，有三種：

- 「系統狀態正常」。
- 「系統需要注意（N 項）」，下面一項一行列出原因。
- AI 已設定卻連不上時，也會列為原因。
- 「系統目前無法正常運作」，例如資料庫連不上。

每一頁頂端的黃色告示也列出同樣的原因，系統管理員與開發人員才看得到。
原因超過兩項時，告示會先收起來，點「看 N 項原因」展開。
開發人員看得到告示，但進不了系統健康頁。告示末行寫「請聯絡系統管理員」，請找系統管理員處理。
告示上的「查看系統健康」連到這一頁。排程資料過期時，連結改寫「確認並靜音」。
原因都處理掉，告示就消失。

## 看懂八張卡片

| 卡片 | 看什麼 |
|---|---|
| PRTG 快照 | PRTG 最近的快照取得順不順；快照停止或超過 6 小時沒有成功時會顯示警示。點卡內連結前往「PRTG 維護」檢查 |
| 排程資料新鮮度 | 排程有沒有啟用、最近一次成功更新資料是什麼時候；狀態為「正常」、「過期」，或確認靜音後的「已確認，靜音至（日期）」 |
| 記憶體 | 站台目前用了多少記憶體，單位是 MB。快用完時上方會出現黃色「警示」，處理方式見「系統設定」章的「系統健康：記憶體」 |
| 慢查詢 | 最近最慢的資料庫操作 |
| 背景工作 | AI、回填、同步等背景工作的狀態、「主機日恢復」，以及「密碼欄位加密」的金鑰來源 |
| 登入暫停 | 因多次登入失敗被暫時擋下的帳號與 IP，可手動解除；站台重新啟動後會清空 |
| 初始設定 | 首次啟動精靈與必要設定是否完成 |
| 派工就緒 | 派工真的會動嗎。逐項寫通過或未通過，旁邊有修正連結 |

「派工就緒」逐項檢查：

- 主機都有群組。
- 主機群組都有派工池看得到。
- 有可接單的派工池。
- 自動派工已開啟。
- AI 執行窗口已設定。
- 排程已啟用。
- 管理員有可用的 email。
- 派工池成員都有可用的 email。

最後兩項只在郵件通知開啟時才檢查。
還沒設定 AI 時，AI 執行窗口這一項不檢查。
「自動派工已開啟」「排程已啟用」沒通過時只在這張卡上提醒，不列入頂端的整體狀態。
這兩項可能是刻意關掉的，所以不會一直跳告示。
其他項目沒通過，頂端的整體狀態就會列出原因。
新站台一開始會列出還沒設好的項目，逐項處理即可。

## 常用操作：資料顯示「過期」時

1. 先看告示上寫的原因。寫「有憑證無法解密」時，到告示上的連結重新輸入密碼。
2. 到「系統 > 排程作業」看最近一次執行有沒有成功。
3. 確認站台服務還在執行（請管理員檢查 IIS 應用程式集區）。
4. 問題修好後，用「立即執行」跑一次完整範圍。成功後告示就會消失，不必等到夜間排程。
5. 原因已處理或暫時可接受時，點選「確認並靜音」，設定「靜音到」日期。

## 注意事項

- 只補本機或指定主機的手動執行不算資料更新，告示不會消失。
- 重新輸入全部密碼後，健康頁的「部分憑證無法解密」會馬上解除。
- 顯示「金鑰與資料庫不相符」時，還要重新啟動站台才會解除。已停用的 Sentinel 也要重新輸入密碼，用不到的可以刪除。
- 「密碼欄位加密」寫「金鑰檔與部署目錄在一起」時，代表重新部署會清掉金鑰檔。這時所有已存的密碼都會失效。
- 請管理員把金鑰檔改放到部署資料夾之外。或重新部署時，保留存放金鑰的資料夾。
- 已經這樣做的，可以忽略這句。
- 這句提示不會讓系統狀態變成異常，只是提醒。
- 「金鑰與資料庫不相符」或「部分憑證無法解密」比這句優先顯示，先處理那兩項。
- 寫「金鑰檔無法建立，目前以內嵌金鑰運作」時，請管理員檢查資料夾的寫入權限。
- 看到「開了忽略憑證錯誤且沒有填信任的憑證指紋」時，請填入伺服器的憑證指紋。PRTG 要到 PRTG 維護的「擷取參數」填。Sentinel 要到 NetIQ 維護的「連線與節流參數」填。填好後提示會消失。
- 看到「交辦通知佇列已滿」時，代表有待寄通知被丟棄。請先檢查郵件設定與 SMTP 是否正常。處理後最多七天，提示會自動消失。
- 看到「郵件設定的摘要時刻格式不合法」時，請到郵件設定把時刻改成 09:30 這樣的格式。在那之前，該摘要不會寄出。
- 看到「站台金鑰檔無法使用」時，請管理員確認站台帳號對資料目錄的 keys 資料夾有讀寫權限。在那之前，密碼類設定存不進去。
- 「確認並靜音」只是暫時不再提醒，不會修復資料；這個動作會留下稽核紀錄。
- 排程剛跑完時，新鮮度最多晚 30 秒才更新。
- 郵件「寄送中」或「結果不確定」的項目不會自動釋放，避免重複寄信。
- 「主機日恢復」寫「排隊處理中」是正常的，資料較大的日子會在之後幾輪逐筆處理完。
- 寫「需要檢查」代表有資料讀不出來，請管理員查看站台記錄檔。
- 這頁不會把外部系統查詢失敗當成正常。要確認 PRTG 的連線與資料，請到「PRTG 維護」的「環境探測」。
