# 系統設定

這頁集中管理全站可調整的參數，存檔後立即生效，不必重新啟動站台。
入口是「系統管理 > 設定」，需要系統維護權限。

## 九個頁籤

| 頁籤 | 用來設定 |
|---|---|
| 層級與顯示 | 哪些嚴重度與風險等級要顯示、預設常用語 |
| AI 服務 | AI 的連線方式與進階參數、token 用量 |
| AD 驗證 | 用公司網域帳號登入 |
| 分析參數 | 主機角色描述、要掃描的日誌、CSV 匯入上限 |
| 資料保留 | 各類資料要留幾天 |
| 系統健康 | 見「系統健康」 |
| 資源守門 | 見「資源守門」 |
| 郵件通知 | 寄信設定、交辦單通知、自動派工 |
| 外觀 | 側欄與登入頁的標題和圖示 |

## 層級與顯示

- 「問題嚴重度」：勾選哪些等級算進「未處理」。
- 沒勾的等級可選「預設隱藏，仍可手動開啟」或全站隱藏。
- 「日風險等級」：統計畫面要不要顯示某個等級的日子。「高風險日」一定顯示。
- 「預設常用語」：處理人寫說明時可以快速帶入的句子。

**注意：**顯示設定只影響看得到什麼，不會改變任何一天已判定的風險等級。

## AI 服務

1. 選「服務提供者」。
2. 依提供者填欄位（見下表）。
3. 儲存。

| 服務提供者 | 要填 |
|---|---|
| 本機 OpenAI 相容端點 | 「API 位址」；金鑰選填；模型名稱預設 local-model |
| OpenAI 官方 | 「API 金鑰」與「模型名稱」；位址選填 |
| Azure OpenAI | 「API 位址」、「部署名稱（Deployment Name）」、「API 版本」、「API 金鑰」 |

- 必填欄位沒填，就是不用 AI。系統改用統計模式，規則判斷照常，速度更快。
- **注意：**選雲端服務時，每次分析最多會送出 500 則原始日誌（可能含帳號與 IP）到外部。從本機切換到雲端時，儲存前會再確認一次。
- 正式站台使用雲端服務時，請管理員設定加密金鑰，否則 API 金鑰的保護較弱。
- AI 寫的內容在畫面上一律放在獨立區塊，和程式判斷的結果分開。

## AI 服務：進階設定

點開「進階設定」才看得到。平常用預設值即可；「還原預設值」只會填回預設值，仍要按「儲存」。

| 欄位 | 預設 | 什麼時候調 |
|---|---|---|
| 單次呼叫逾時（秒） | 1200 | 大模型常在快完成時被中斷 |
| 網路層重試次數 | 3 | 網路不穩或 AI 伺服器偶發過載 |
| 首次重試等待（秒） | 10 | AI 伺服器排隊很長；之後每次加倍 |
| JSON 檢查未過重問次數 | 2 | 模型常回傳格式錯誤的內容 |
| 一般呼叫 token 上限 | 2048 | 摘要被截斷；調大不會提高成功率 |
| 深入分析 token 上限 | 8192 | 深入分析被截斷 |
| 頻率懲罰／存在懲罰 | 0.8 | 模型一直重複同一句話 |
| 額外請求欄位（JSON） | 空白 | AI 伺服器需要特殊參數時 |

## AI 服務：token 用量

- 顯示今日消耗、累計消耗與累計呼叫次數。重試也算一次呼叫，用到快取的不算。
- 有些 AI 伺服器不回報 token，畫面會提示有幾次呼叫沒有回報。
- 填入 input 與 output 的「每百萬 token 金額」，可以試算費用。
- 金額填 0 代表不估費。
- 「近 30 天明細」可看每天的用量。
- **注意：**「清空重新計算」會把用量歸零，無法復原。

## AD 驗證

1. 勾「啟用 AD 驗證」。
2. 填「AD 伺服器」；需要時填「查詢基準 DN（選填）」與「查詢過濾器」。
3. 用「測試帳號」與「測試密碼」測試連線，不必先儲存。
4. 儲存。

- 救援帳號不受 AD 設定影響，AD 設錯時仍可登入修正。
- 使用者名稱顯示「規則（選填）」：一行一條，用來去掉 AD 顯示名稱的公司名等前後綴。只改顯示，不改資料。

## 分析參數

| 欄位 | 說明 |
|---|---|
| 伺服器角色描述 | 讓 AI 更了解主機用途 |
| 體檢間隔天數 | 預設 7 天 |
| 額外監控權限異動的資料夾 | 一行一個路徑 |
| 要掃描的 Event Log 頻道 | 留空使用預設的六個頻道 |
| CSV 匯入檔案大小上限（KB）／資料列上限 | 預設 2048 KB、5000 列 |

權限異動的四個「自訂欄位」平常留空。只有權限異動檢核頁抓不到「對象」或「帳號」時才需要填，而且只對之後收到的事件生效。

## 資料保留

超過天數的資料會在每次分析開始時自動清除。每項最少 90 天、最多 3650 天。

| 項目 | 預設 |
|---|---|
| 歷史資料保留天數 | 180 |
| 原始事件內容保留天數 | 120（不可超過歷史資料） |
| 執行歷程保留天數 | 120 |
| 稽核與追責紀錄保留天數 | 730 |
| 報告保留天數 | 180（不可超過歷史資料） |
| 首次執行回補天數 | 120 |

資料很多時會分好幾次清完，執行畫面會顯示還剩多少。

**注意：**天數設短，超過的資料就會被刪除，無法復原。

## 郵件通知

1. 勾「啟用郵件通知」，填郵件伺服器、帳號密碼、寄件人與收件人（一行一位）。
2. 用「測試寄信」確認連得上，不必先儲存。
3. 勾選要寄的信：

| 開關 | 什麼時候寄 |
|---|---|
| 排程／手動執行結束後寄執行摘要 | 每次分析結束 |
| 每日摘要／每週摘要 | 設定的時刻 |
| 高風險日即時通知 | 出現高風險日時；同一台同一天只寄一次 |
| 交辦單通知 | 依「交辦摘要時刻」（預設 08:00、12:00）寄給處理人 |

- 「摘要納入門檻」決定多嚴重才寫進摘要。
- 勾「同時通知負責人」會另寄給問題負責人；沒有問題負責人才寄給主機負責人。
- 「期間內無達門檻風險日時不寄摘要信」預設不勾：沒事的信也代表系統還在運作。
- 有人回覆「無法處理」時，會立即寄信給 admin 群組。
- 信件以問題為單位，分「逾期」、「新出現」、「擴散中」、「其他高風險」四區。

**注意：**每位收件人只看得到自己權限內的主機名稱。對應不到帳號的地址只會收到統計數字。

- 開啟通知前已產生的結果不會補寄。
- 某個地址連續三次寄送失敗會被暫停，列在「被暫停的郵件收件人」；改正地址並儲存後會重新嘗試。

## 郵件通知：自動派工

在郵件通知頁籤最下方。勾「夜間分析後自動派工」後，沒人接手的新問題會自動派出。
系統會選「派工池」群組裡、看得到該主機、手上工作最少的人。

- 派工池在「群組與授權」的使用者群組勾選。沒有任何派工池時，這裡會顯示警告。
- 派不出去的問題會列在「交辦總覽」的「待派」頁籤。
- 不派工的情況見「處理狀態與交辦單」。

## 外觀

可改側欄與登入頁的「主標題」、「副標題」與「圖示」（PNG 或 JPG，64KB 以內）。存檔後重新整理頁面即可看到。
