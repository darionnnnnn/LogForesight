# 規則維護

「系統管理 > 規則維護」頁（`/admin/rules`，需 Maintain 能力）是日常維護偵測規則的正式途徑，分「Windows 規則｜Linux 規則｜告警抑制」三個分頁。規則調整**不需要重新編譯部署**，存檔立即生效。

## 比對順序的語意

**規則的比對順序＝清單上的順序，第一個命中的規則生效**。新增規則預設加到清單最後（依建立先後決定順序）；本頁不支援手動拖曳調整順序。

儲存時系統會自動偵測「遮蔽」——如果一條規則被排在前面、範圍更廣的規則擋住，導致它永遠不會被命中，存檔時會直接警告並提示要調整範圍或順序。**Windows 與 Linux 規則各自獨立排序，不會互相遮蔽**。Linux 規則要特別留意 program 名稱的包含關係（例如 `"sudo"` 包含 `"su"`），具體的規則要排在泛用的規則前面。

## 新增規則

- `Id` 強制以 `custom-` 開頭（區分你自訂的規則與程式內建的 `builtin-` 規則）。
- 填類別、嚴重度、比對條件（**依所在分頁自動決定平台**：Windows 分頁填來源比對＋Event ID；Linux 分頁填 Program 比對＋訊息子字串或正規化事件名），以及「命中即列為高風險日（重大）」旗標。
- 四個知識庫欄位：白話說明、影響、常見原因、處置步驟——這些內容會直接出現在風險日詳情頁與風險報告裡。

## 為什麼不要直接改內建規則

想微調某條 `builtin` 規則的內容（改門檻、改處置文字）**不要直接改那一條**——程式改版後，如果在規則頁勾選「覆蓋已修改的內建規則」套用升級，你的修改可能會被蓋回去。正確做法：**把該條停用，複製一條改成 `custom-` 開頭的新規則再修改**。規則頁的「回復預設」可以把改壞的 builtin 規則還原成原廠內容，並提供前後對照確認。

停用規則不會讓對應事件從趨勢層／關聯層的偵測中消失，只是不再有規則命中的分類與知識庫說明——這是刻意設計，避免停用規則之後同一個訊號變成完全沒被記錄。

## 內建規則改版

程式改版後若內建規則有新增或修訂，頁面頂端會出現橫幅提示「內建規則有更新（vX → vY）」：

1. 按「預覽差異」，對話框列出將新增／更新／略過／衝突的規則清單。不勾選「覆蓋已修改的內建規則」時只會新增缺少的規則。
2. 需要連同你沒改過、但程式內容已更新的既有 builtin 規則一併套用時，勾選「覆蓋已修改的內建規則」，預覽即時重新整理，確認清單無誤後按「套用」。

你自訂的 `custom` 規則永遠不會被這個流程碰到；勾選覆蓋時也會保留你對該條 `Enabled` 的設定（不會被悄悄打開）。

## 清單頁的輔助資訊

清單可依類別／嚴重度／來源（內建／自訂）／啟用狀態／有無抑制快速篩選；「已修改」徽章標示哪些內建規則被你改過內容；有抑制設定的規則會顯示抑制筆數與預覽，不必切到「告警抑制」分頁另外查。
