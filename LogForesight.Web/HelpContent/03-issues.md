# 問題事件

「問題查詢」頁（`/records`）是跨主機、跨日期查找問題的主視角，不必先點進某一台主機才看得到問題。

## 篩選條件

- **主機**：輸入名稱搜尋，可複選（以 chip 呈現，逐一移除或清除條件）
- **日期區間**：起訖日期，或用「期間快捷」（近 7 天／近 30 天等）直接套用常用範圍
- **Event ID**、**來源**（選填，如 `disk`）：縮小到特定訊號
- 清單支援依風險等級、問題類別等維度進一步篩選（見表格上方的篩選列）

## 查詢結果

結果以表格呈現，欄位包含主機、日期、問題摘要、趨勢註記、處理狀態等。點列可下鑽到該主機該日的「風險日詳情」頁查看完整內容。

- **複製為 CSV**：把目前篩選結果匯出成 CSV 文字，貼到 Excel 等工具進一步整理。
- **AI 歸納**（AI 已設定時才顯示）：把目前篩選結果裡重複出現的問題簽章跨主機聚類，AI 用一段白話講清楚「這批結果裡最值得注意的是什麼」。這是加值功能，AI 未設定或失敗時按鈕不出現，不影響查詢本身。

## 依問題視角與問題負責人

頁籤可切換「明細」／「依主機」／「依日期」／「依問題」四種視角。「依問題」把同一個問題（來源＋Event ID）跨主機、跨日期彙總成一列。

問題名稱下方會有一行**白話說明**（命中規則庫時才有），用一句話講清楚這是什麼問題；文字過長時會截斷，滑鼠移上去看得到完整內容。若這個問題在「問題檔案」頁（系統管理 > 問題檔案）有指派規則，問題名稱旁會附上負責人 badge，一眼看出「這個問題歸誰」；若機房已對這個問題下過結論（如「已知雜訊」）並開啟自動套用，之後新出現的主機日會自動沿用同一個結論，不必逐台重新標記。

### 各欄怎麼讀

非常規欄位的表頭都有 `?` 圖示，滑鼠移上去會顯示同樣的說明。

| 欄位 | 意思 |
| --- | --- |
| **主機數** | 查詢期間內曾出現這個問題的相異主機台數 |
| **總次數** | 查詢期間內所有受影響主機累計觸發的事件次數。與主機數是兩個維度——「1 台主機爆 500 次」和「500 台各 1 次」總次數相同，但要處理的方式完全不同 |
| **出現密度** | 有發生的天數 ÷ 查詢天數，數字下方是同一個比例的長條。比例高（如 30/30）代表天天都有的背景雜訊；比例低（如 2/30）代表零星或近期才冒出來的突發狀況 |
| **vs 基準** | 第一行是「基準 N 台/日 → M 台」，第二行是倍數徽章。倍數＝最近一次出現的受影響主機數 ÷ 過去 30 天的每日中位數。**≥2 顯示紅色「擴散」**（影響範圍異常放大）、**1～2 顯示灰色「正常」**（一般波動）、**<1 顯示綠色「收斂」**（影響台數已低於平常水準，例如 ×0.9 表示比平常少一成）。過去 30 天出現不足 3 天的問題沒有基準可比，顯示「新問題，無基準」 |
| **首見** | 預設顯示**機房首見**——這個問題第一次在整個機房出現的日期，不受查詢期間截斷。若本次查詢期間內的首次出現日與機房首見不同，下方會多一行標示「本期 mm-dd」並附圖示。兩者相同時只顯示一行 |
| **處理概況** | 受影響主機的處理狀態分佈，未處理／處理中／已處理各佔一行（數量為 0 的仍然顯示，只是淡色，讓各列高度一致好對照） |

### 為什麼列表的主機數加起來會比儀表板的卡片多

儀表板「風險類型」卡的「M 台主機」是**該類別跨問題去重**後的台數（同一台主機同時中三個問題只算一台），而依問題列表每一列的「主機數 / 主機日」是**該問題自己的**台數與主機日數。同一台主機出現在多列，加總自然比卡片大。

列表上方會顯示「共 N 台主機（去重）」——那個數字才是與卡片同一個口徑，用它對照就對得上。

## 與「風險日詳情」的差別

問題查詢頁是**跨主機、跨日期**的搜尋入口，答案是「符合條件的問題有哪些」；風險日詳情頁（見下一節）是**單一主機單一天**的完整檢視，答案是「這一天到底發生了什麼、AI 怎麼解讀、要不要處理」。兩者互補：先在問題查詢頁找到關注的問題，再下鑽到風險日詳情頁看完整脈絡與處理。
