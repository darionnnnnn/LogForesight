# 問題檔案

「系統管理 > 問題檔案」頁（`/admin/issue-owners`，需 Maintain 能力）以「問題（來源 Source ＋ Event ID）」為單位，指派跨主機的長期問題負責人，並可設定全機房適用的「機房結論」。

## 問題負責人的效力

與針對特定主機指派的「主機負責人」不同，問題負責人是**以問題簽章為對象的跨主機負責人**。設定後享有以下效力：

- **自動建案與交辦**：當該問題在夜間批次分析中再次出現時，系統會自動建立案件並指派給第一位問題負責人，直接進入該負責人的「我的交辦」工作清單。
- **郵件通知優先**：系統發送警報郵件時，若該日問題命中問題負責人規則，郵件會優先寄送給問題負責人，不再通知主機負責人。
- **跨主機授權穿透**：問題負責人會自動取得在資料保留期間內曾出現該問題之所有主機的檢視權與處理權限，即使該主機原本不在其所屬群組的授權矩陣內。
- **問題查詢頁標示**：在「問題查詢」頁切換至「依問題」視角時，問題名稱旁會顯示問題負責人徽章。

## 機房結論（自動套用）

在編輯問題檔案時，可為該問題設定全機房通用的結論：

- **四種結案狀態**：已處理（`resolved`）、不處理（`wont_fix`）、誤報（`false_positive`）、已知雜訊（`known_noise`）。
- **原因必填**：設定結論時代全體下結論，必須填寫具體原因說明，該原因會留存在紀錄與稽核日誌中。
- **之後自動套用**：勾選「之後新出現的主機日也自動套用這個結論」後，未來夜間分析新產生的事件若包含此問題，系統會自動套用該結論結案，維運人員無需逐日逐台手動標記。
- **解除結論**：若情況改變需重新追蹤，可點擊「解除結論」按鈕。解除後系統會停止自動套用；但過去已經寫入歷史紀錄的結案狀態會誠實保留、不會回滾。

## 操作說明

### 新增問題檔案

1. 點擊頁面右上角的「新增規則」按鈕開啟視窗。
2. **選取問題**：可由「下拉挑選」（預設由「近 30 天」曾出現過的問題清單中依影響主機數排序挑選），或點擊「找不到？改為手動輸入」以「手動輸入」尚未出現或歷史較久的問題，填寫「來源（Source）」（如 `disk`、`DCOM`）與「Event ID」（Windows 請填事件識別碼；Linux 請填 `0`）。
3. **指派負責人**：由使用者清單中勾選一位或多位負責人（支援關鍵字過濾）。
4. **填寫備註**：選填備註說明。
5. 點擊「儲存」完成新增。

### 編輯問題檔案與設定結論

1. 在列表點擊該問題右側的「編輯」（筆形圖示）。
2. 在編輯視窗中可修改負責人勾選與備註。（注意：問題的 Source 與 Event ID 在編輯時已鎖定不可改，若要更換問題請刪除後重新新增）。
3. 編輯視窗下方會出現「機房結論」區塊，可由下拉選單選取結論狀態（維持空白表示本次儲存不變更結論）、填寫原因並決定是否勾選「之後新出現的主機日也自動套用這個結論」；若已有結論，可點擊「解除結論」按鈕予以清除。
4. 點擊「儲存」送出。

### 刪除問題檔案

點擊問題右側的「刪除」（垃圾桶圖示），確認後即可移除。刪除後該問題的新增告警將落回主機負責人規則（若有設定），原有的機房結論也會一併移除。
