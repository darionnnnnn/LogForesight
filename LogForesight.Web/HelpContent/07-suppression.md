# 告警抑制

某個訊號已確認是已知雜訊、不想再收到通知，但又不想整條規則永久停用（停用會讓其他主機也跟著沒有分類）時，用「告警抑制」。維護入口是「系統管理 > 規則維護」頁的「告警抑制」分頁。抑制與規則的「停用」是完全不同層級的兩個動作，差異對照見〈規則維護〉章節的「停用、遮蔽、抑制」表格。

## 抑制關掉的是「要不要吵」，不是「要不要記」

**抑制只關掉通知與風險升級，事件仍會照常聚合、命中規則、寫入歷史**。這樣才能在體檢報告與風險日詳情頁看到「這個被抑制的訊號本期實際發生了幾次」，暫時關掉的東西不會變成沒人記得的永久盲區。風險日詳情頁的「已抑制的告警」區塊收合呈現這些內容，隨時可以展開查看。

## 四種抑制目標

抑制設定針對不同性質的訊號，選對目標才會真的擋住你要擋的東西：

1. **規則**：整條規則的命中結果都不再通知（等同該規則對指定範圍靜音，但事件仍照常聚合）。
2. **問題簽章**：針對特定的「來源＋Event ID＋類型」組合，比整條規則更精準——同一條規則底下其他簽章不受影響。
3. **關聯模式**：針對特定的跨 log 關聯訊號（攻擊鏈／故障鏈組合），可直接在風險日詳情頁的關聯訊號旁按「抑制此關聯模式」建立。
4. **音量（趨勢量）**：針對錯誤或稽核事件總量突增的趨勢告警，用於某台主機本來就是高流量、量的波動屬於正常範圍的情況。

## 三種抑制範圍

- **主機**：只影響單一主機，原有的細粒度。
- **主機群組**：同類主機批次抑制一次，避免大規模環境下同一個雜訊要在每台同類主機上各設一次——逐台設定的維護成本最終只會讓人乾脆停用整條規則。
- **全站**：不限主機或群組，整個環境都不再收到這個訊號的通知。

## 與「已知雜訊」的差別

告警抑制是**你主動設定**、看得到清單、可隨時查詢與解除的規則性設定；如果系統裡另外看到「已知雜訊」相關的標記（如處理狀態的「已知雜訊」結案原因），那是針對**單一問題個案**的處理結果，兩者是不同層級的概念，不要混用。

## 到期與解除

抑制可以設定到期天數（省略即永久生效直到手動解除）。到期後**不會自動清理設定紀錄**，只是恢復告警——執行分析時會在輸出中提示「這條抑制已到期」，避免你以為抑制還在生效。

## 抑制何時生效

新增或調整抑制設定，只影響**設定之後**執行的分析——已經寫入歷史的紀錄（風險等級、是否列為高風險日）不會被回溯改寫。今天新設一條抑制，回頭看昨天以前的紀錄不會有變化，要等下一次分析執行才看得到「原本會拉高風險的訊號，現在被抑制不再升級」的效果。
